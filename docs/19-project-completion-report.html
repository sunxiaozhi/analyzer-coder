01

项目概述

Analyzer Coder 是面向开发者与项目维护人员的代码与知识检索平台。项目将源码、项目说明和人工维护的知识组织为有来源、可定位、可区分版本的检索资产，让用户从业务问题出发找到相关实现与约束，并通过原始材料核对答案。

当前主流程为：接入项目 → 选择并准备分支快照 → 维护关联知识 → 联合检索 → 查看源码和知识来源。项目问答、代码图谱及 MCP 在这条主流程上提供辅助能力。

项目定位已经从较宽的工程分析平台收敛为代码与知识联合检索工具。跨仓工程项目、变更审查、PR/MR Webhook、审查 CI、任务结果回报等能力已退出当前产品范围，不作为本次结项的现行交付成果。

02

建设背景与解决的问题

2.1 建设背景

在项目研发和维护过程中，代码实现、架构说明、业务约束与开发经验通常分散在仓库文件、Markdown 和个人经验中。传统文件搜索偏向路径和关键词，开发者即使找到代码，也可能缺少理解该实现所需的业务背景。引入 AI 后，如果答案没有可靠来源或混用了不同版本的材料，又会增加核对成本。

随着项目采用多分支开发，同一文件或知识在不同分支上的含义与有效性可能不同。因此，系统需要同时解决信息查找、来源核对、版本隔离和知识维护的问题。

03

主要建设成果

3.1 项目接入与多分支管理

支持本地 Git、远程 Git及 ZIP 接入。一个 Git 项目对应一个仓库逻辑身份，可管理多个分支；分支同步和索引产物以受管快照组织，不依靠 checkout 用户源工作区来切换阅读版本。ZIP 保留单版本模式。

全站项目与分支选择统一到阅读上下文。代码、检索、知识、图谱及问答使用固定版本，切换时使旧请求失效，未就绪分支不借用默认分支结果。分支支持跟踪、逻辑归档和恢复，并对仍被上下文、任务或知识等引用的产物保留清理保护。

3.2 代码与知识联合检索

源码组织为携带路径、符号、行号和快照身份的片段。代码与已发布的可见知识通过统一检索服务召回、排序和展示，用户可从结果查看原文与关联范围。

关键词检索构成最小可用路径；字符相似度、外部向量模型和 CodeGraph 属于增强能力。增强能力未配置或不可用时，不应把降级结果包装为完整语义理解，也不应借用其他版本的产物。

3.3 知识管理与维护

支持知识卡创建、编辑、审核、发布、撤回、修订历史及来源关联。项目共享知识与分支专属知识独立维护，不按相同标题或正文自动合并、覆盖。

Markdown 来源按项目、分支、快照和路径组织，避免同路径跨分支覆盖。分支知识验证已迁至知识详情，保留验证结论、说明、管理权限及修订/快照绑定，知识列表支持当前分支验证状态展示与筛选。

3.4 问答、图谱与 AI 工具接入

项目问答基于检索材料提供回答与引用，并保存会话来源信息。代码图谱辅助查看结构关系和源码位置，其结论受图谱产物、语言支持和算法覆盖范围限制。

MCP 提供只读 search_project 工具，复用同一后端检索服务和权限边界，使网页与 AI 客户端使用一致的查询基础。平台不通过这些能力自动修改代码、执行审批或判定发布是否通过。

3.5 权限、任务与基础工程能力

具备账号、会话、项目成员权限、模型配置及系统审计等基础管理能力。仓库读取在服务端校验 READ 权限，维护与管理操作继续按相应权限控制。

后台任务采用数据库持久化状态，支持准备、索引及图谱等操作的状态诊断。任务中心区分普通索引任务、向量任务与分支准备任务；分支任务支持项目/分支筛选、分页历史和错误详情。

技术底座采用 Java 17 / Spring Boot、Vue 3 / TypeScript、PostgreSQL / pgvector 与 Flyway，并提供启动、诊断、部署及测试脚本。

3.6 产品收敛与界面优化

已清理不再服务主流程的遗留组件、API 包装和跨仓工程功能。跨仓退出使用带数据检查的前向迁移，存在跨仓业务数据的部署需先迁移或导出，不静默扩大知识适用范围。

分支面板保留选择、同步、一键准备、打开代码与状态摘要，高级操作折叠；知识验证与任务历史分别由知识详情和任务中心承接。主菜单统一为项目总览、联合检索、代码图谱、项目问答、知识管理、项目管理、任务中心等清楚且长度接近的名称。

08

结项结论

本项目已形成以版本化源码和独立知识资产为基础的联合检索工具，具备项目接入、多分支阅读、知识维护、来源核对和辅助问答的主要能力。其突出价值是把实现与知识放到同一查找路径，并让结果的来源和适用版本更容易核对。

依据现有研发交付与验证记录，可作为阶段性研发结项成果移交。整体业务验收与生产可用性仍需在真实项目、独立验收环境及生产运行条件下确认。后续重点应放在检索质量、知识维护闭环、端到端验证和运维可靠性上。
