# 真实性与实用价值优化需求

版本：v1.0  
日期：2026-08-25  
状态：已完成

## 1. 目标

将系统从“具备代码知识功能”收敛为“结论边界清楚、证据可追溯、失败不会伪装成成功”的代码证据工作台。

本轮只接受可验证的产品行为：

1. 原始事实必须绑定仓库、快照、提交、路径、行号和内容摘要。
2. 派生结论必须说明算法来源、覆盖范围和未知项。
3. 模型输出不得仅因引用格式正确就标记为事实已被支持。
4. 降级、缺失、过期和未验证状态必须进入接口模型，不能只写日志。
5. 每项需求必须有自动化测试或可重复的验收脚本。

## 3. 详细需求

### TRUTH-001 服务端强制当前快照隔离

问题：仓库发布新快照后、索引完成前，部分查询只按仓库过滤，可能返回旧快照 chunk。

要求：

1. 代码关键词、代码向量、结构关系、chunk 列表、chunk 计数和图谱目标查询必须匹配 `repositories.current_snapshot_id`。
2. 当前快照尚无索引时返回空结果或明确的未准备状态，不得回退到旧快照。
3. 知识卡片代码引用的有效性判断只能使用当前快照 chunk。
4. 历史问答继续保存原引用快照，不受当前快照过滤影响。

验收：构造“仓库当前快照 B、数据库仍保留快照 A chunk”的状态，所有实时查询均不得返回 A；历史记录仍可恢复 A 的引用快照。

### TRUTH-002 重定义问答证据状态

问题：当前 `SUPPORTED` 只证明答案中存在合法 `[S编号]`，不证明事实受到证据支持。

要求：

1. 将格式校验与事实支持拆成不同状态。
2. 每个事实段至少包含合法引用；无引用段落不能进入“有引用”状态。
3. 未做语义蕴含验证时不得使用“已证实”等强语义标签。
4. 接口返回引用覆盖率、非法引用和未引用事实段数量。

验收：仅末尾带一个引用的多段事实回答不能进入最高证据状态。

### TRUTH-003 变更分析版本一致性

要求：

1. 每个候选、测试建议和依赖样例携带自己的 `snapshotId` 与 `contentHash`。
2. 任一代码证据与分析顶部快照不一致时直接排除并记录未知项。
3. HIGH 置信度改名为“证据覆盖等级”，避免解释为统计概率。

### RETR-001 结构检索真实性

问题：问答内部 `CODE_GRAPH` 通道来自字符串 `symbol(` 匹配，不是 CodeGraph CLI。

要求：

1. 该通道改名为 `HEURISTIC_CALL_REFERENCE`，或直接接入已发布 CodeGraph 产物。
2. 启发式关系在索引阶段构建，禁止每次查询全量删除重建。
3. 接口必须返回关系来源、快照和算法限制。

### RETR-002 本地哈希检索边界

要求：所有接口与页面将 `LOCAL_HASH` 展示为“字符相似度”，不得称为模型语义理解；外部 embedding 才显示“语义检索”。

### EVAL-001 质量评测

建立至少三类代表仓库和以下金标准：

- 50 个源码定位问题；
- 30 个带人工证据的问答；
- 20 个已知真实修改范围的变更任务。

发布门槛至少包括 Recall@10、引用覆盖率、陈述支持率、变更文件召回率和 P95 延迟；不得用界面演示代替质量验收。

### GRAPH-001 CodeGraph 后台化

构建接口只入队并立即返回；Worker 执行复制、构建和发布；任务支持心跳、超时、取消和失败原因；旧产物在新产物成功前继续可用。

### KNOW-001 知识状态语义

拆分为来源版本状态、人工评审状态和发布状态。保存卡片不能自动等价于人工核验，自动生成的 Markdown 卡片保持草稿和未评审。

### INDEX-001 增量索引完整性

使用可识别增加、修改、删除、重命名的 Git 差异；基线缺失、差异失败、脏工作区或变更比例过高时自动全量回退，并在任务详情记录实际执行模式。

### OBS-001 可观察性

问答和检索响应返回实际启用通道、不可用通道、模型、快照、召回数量、耗时和降级原因；禁止吞掉异常后仍显示完整能力。

### TEST-001 测试体系

默认 CI 启动 PostgreSQL/pgvector 集成测试；增加真实 MyBatis SQL、快照切换、CodeGraph CLI 契约、前端关键路由和至少一条仓库导入到问答的端到端测试。

### CLEAN-001 清理与文档

删除未路由的静态 mock 页面和废弃空适配器；需求文档以当前路由、接口和数据库行为为准，代码变更必须同步能力状态。

## 4. 完成定义

单项需求只有同时满足以下条件才可标记完成：

1. 产品行为、接口字段和错误语义已实现。
2. 自动化测试覆盖正常、降级和版本切换路径。
3. 相关页面没有扩大后端结论含义。
4. 文档状态与实际代码一致。
5. 后端测试、前端类型检查和生产构建通过。
