# UI 交互与展示优化方案及分步清单

- 编写日期：2026-09-29
- 状态：2026-09-30 已完成步骤 01–11 的前端实现与验证；步骤 12 的前端模拟验收通过，真实服务联调保留待办。
- 目标：保持当前业务功能，通过界面调整，让用户更快找到知识、更顺畅地维护知识，并清楚知道当前项目、分支和操作结果。
- 依据：当前前端实现、上一轮功能验证及知识共享编辑窗口的浏览器实测。建议中的布局尺寸是实施起点，需以实际页面验证结果调整。

## 1. 优化范围

本方案调整信息层级、页面布局、操作入口、文案、交互反馈和界面状态保留。

保留现有知识创建、编辑、评审与发布、三种共享范围、分支验证、历史恢复、附件、代码引用、Markdown 来源、检索、问答、图谱以及管理功能。权限、检索规则、数据模型、接口契约和已有工作流程沿用当前实现。

“折叠”“收进更多”“移动到侧栏”均表示调整展示位置，原有字段和操作仍可访问。保存仍生成草稿，发布仍由现有发布动作完成。多分支共享沿用同一卡片、同一正文、分支分别验证的规则。

文档只安排 UI 工作；新增知识模板、批量操作、收藏、通知、自动发布、新检索能力等产品能力不纳入本轮。

## 3. 第一阶段：知识维护

### 步骤 01：重排知识列表

**现状与目标**：当前卡片同时展示类型、评审、来源等元信息，缺少直观的正文摘要。优先帮助用户判断“这是不是我要的知识”。

**优化点**

- [x] 采用紧凑的纵向列表，每条知识保持稳定的阅读顺序。
- [x] 第一行突出标题和主要状态，标题允许适度换行。
- [x] 第二行展示正文前两行的纯文本摘要，去除 Markdown 标记、代码围栏和附件占位语法。
- [x] 第三行展示共享范围、少量标签和更新时间；剩余标签以“+N”展开。
- [x] 查看、编辑保留直接入口；需要发布时突出“确认并发布”，历史等低频操作进入“更多”。
- [x] 保留现有正文/标签搜索、知识类型和分支验证筛选，统一放在列表上方。
- [x] 长标题、长分支名和无标签卡片使用一致的换行与空值样式。

**验收标准**：无需打开详情即可看到主题、内容摘要和共享范围；现有操作均能找到；编辑返回后搜索条件、滚动位置和修改项仍然可见。

**主要组件**：[KnowledgeView](../../frontend/src/views/KnowledgeView.vue)、[KnowledgeCardListItem](../../frontend/src/features/knowledge/KnowledgeCardListItem.vue)。

### 步骤 02：调整知识编辑窗口

**现状与目标**：现有共享范围、正文、代码关联、约束设置纵向排列，窗口内滚动较长。让正文成为主要编辑区域。

**优化点**

- [x] 桌面采用约 70% 主编辑区、30% 设置区；具体宽度按正文可读性调整。
- [x] 主编辑区集中展示标题、正文、编辑/预览切换，正文获得更大的可视面积。
- [x] 设置区展示共享范围、知识类型、标签；代码关联、附件和约束设置分组收纳。
- [x] 已有附件、关联代码和非默认约束显示数量或简短摘要，用户不用展开也知道已有配置。
- [x] 继续使用固定底部操作栏，明确区分“创建草稿”“保存新修订”；发布保持现有独立入口。
- [x] 必填项错误显示在字段附近，提交失败后保留已输入内容。
- [x] 小窗口切为单列，共享范围靠前，正文紧随其后；保存按钮始终可到达。
- [x] 避免左右区域各自出现难以判断的多层滚动条。

**布局建议**

| 主编辑区 | 设置区 |
| --- | --- |
| 标题 | 共享范围 |
| 正文编辑 / 预览 | 知识类型、标签 |
| 大面积正文输入区域 | 关联代码、附件、约束设置 |
| 底部统一操作栏：取消 / 创建草稿或保存新修订 | 同左侧共用操作栏 |

**验收标准**：填写标题与正文、检查范围和保存不需要来回寻找按钮；编辑/预览切换保留输入；原有隐藏兼容字段随保存保留；附件、代码绑定、约束仍能正常编辑。

**主要组件**：[KnowledgeCardEditorDialog](../../frontend/src/features/knowledge/KnowledgeCardEditorDialog.vue)、[KnowledgeCardContentSection](../../frontend/src/features/knowledge/KnowledgeCardContentSection.vue)、[KnowledgeCodeAssociationSection](../../frontend/src/features/knowledge/KnowledgeCodeAssociationSection.vue)、[KnowledgeCardPolicySection](../../frontend/src/features/knowledge/KnowledgeCardPolicySection.vue)、[useKnowledgeCardEditor](../../frontend/src/features/knowledge/useKnowledgeCardEditor.ts)。

### 步骤 03：明确共享范围与当前分支状态

**现状与目标**：共享范围已恢复；发布、评审、来源和分支验证状态同时存在。让用户直接看懂范围和适用性，保留各状态原有含义。

**优化点**

- [x] 范围摘要统一为“仅 main 可见”“项目全部分支共享”“main、legacy 共 2 个分支共享”。
- [x] 项目共享注明包括后续新增分支；指定分支支持查看完整名单。
- [x] 表单常驻一条当前选择的说明，详细规则放入可展开的帮助。
- [x] 列表和详情采用同一套状态显示规则，主要状态使用文字配合颜色。
- [x] 主位置显示“草稿”“已发布 · 当前分支已验证”“已发布 · 当前分支待验证”或“已发布 · 当前分支不适用”等实际组合。
- [x] 通用参考知识发布后可检索的现有规则继续有效，不因“尚无人工分支验证”就统一显示为不可用。
- [x] 只有能根据现有上下文和规则确认时才显示“可用于当前分支检索”；信息不足时展示发布和验证事实。
- [x] 代码引用显示来源分支、文件及行号；与当前分支不同时，跳转前便可识别。

**展示示例**

| 情形 | 建议主文案 | 次级信息 |
| --- | --- | --- |
| 尚未发布 | 草稿 | 尚未用于检索和问答 |
| 已发布且当前分支验证通过 | 已发布 · 当前分支已验证 | 当前分支名及验证说明 |
| 已发布，关联代码/约束类知识在当前分支尚未验证 | 已发布 · 当前分支待验证 | 进入现有分支验证入口 |
| 当前分支已判定不适用 | 已发布 · 当前分支不适用 | 展示该分支的复核说明 |
| 项目共享的通用参考知识，满足现有检索规则 | 已发布 · 可用于当前分支检索 | 项目全部分支共享 |

**验收标准**：能区分“发布到共享范围”和“已验证适用于当前分支”；切换 main/legacy 后状态随分支更新；一个分支不适用时，其他分支的有效状态正确展示。

**主要组件**：[KnowledgeBranchScopeSection](../../frontend/src/features/knowledge/KnowledgeBranchScopeSection.vue)、[knowledgeBranchScope](../../frontend/src/features/knowledge/knowledgeBranchScope.ts)、[KnowledgeBranchValidationPanel](../../frontend/src/features/knowledge/KnowledgeBranchValidationPanel.vue)、知识列表和详情组件。

### 步骤 04：改善知识详情与返回路径

**现状与目标**：当前详情使用弹窗，维护信息已经折叠。继续提升正文阅读和多条知识连续查看的效率。

**优化点**

- [x] 宽屏采用右侧阅读抽屉，保留列表和选中项；小屏采用占满可用宽度的详情层。
- [x] 详情顶部固定标题、关闭入口和必要操作；正文、标签、附件及代码引用按阅读顺序排列。
- [x] 将修订号、完整时间等次级信息降为普通文本，减少彩色标签堆叠。
- [x] 保留现有“维护信息与复核”折叠区；从待验证状态进入时直接展开对应验证区域。
- [x] 负责人优先展示现有数据中可获得的姓名或账号；只有 ID 时提供可复制标识，不捏造姓名。
- [x] 关闭详情恢复列表滚动位置与焦点；历史恢复后定位新草稿并显示明确结果。
- [x] 从知识跳转源码后，返回时恢复原知识、查询词和列表位置。

**验收标准**：筛选后连续查看三条知识不丢失筛选和位置；附件下载、历史恢复、查看源码和图谱入口全部可用。

**主要组件**：[KnowledgeCardDetailDialog](../../frontend/src/features/knowledge/KnowledgeCardDetailDialog.vue)、[KnowledgeAttachmentList](../../frontend/src/features/knowledge/KnowledgeAttachmentList.vue)、[KnowledgeDriftPanel](../../frontend/src/features/knowledge/KnowledgeDriftPanel.vue)、KnowledgeView。

## 4. 第二阶段：检索与源码阅读

### 步骤 05：重排联合检索结果

**优化点**

- [x] 保留当前搜索入口，搜索结果统一按“标题 → 命中摘要 → 来源位置”展示。
- [x] 高亮关键词，优先截取命中附近的内容，降低用户阅读无关正文的成本。
- [x] 代码结果突出文件/符号、路径、行号；知识结果突出知识标题、共享范围与代码引用数量。
- [x] 当前选中结果与源码定位保持明显对应，选中态不只依赖颜色。
- [x] 检索通道、匹配方式、内容版本等诊断信息默认折叠；影响结果完整性的降级保留一句说明。
- [x] 区分“尚未搜索”“正在搜索”“没有结果”“读取失败”，每种状态给出对应的现有操作入口。
- [x] 返回结果列表时恢复查询词、选中项和滚动位置。

**验收标准**：同一查询得到的结果、排序和分支范围与优化前一致；高亮不破坏代码或 Markdown 展示；从结果打开源码仍定位原行号。

**主要组件**：[ChunksM0View](../../frontend/src/views/ChunksM0View.vue)、[RepositoryFilePreview](../../frontend/src/components/RepositoryFilePreview.vue)。

### 步骤 06：改善源码与证据对照

**优化点**

- [x] 宽屏将现有较宽的证据抽屉调整为与源码并排的区域，保留有效源码阅读宽度。
- [x] 支持调整源码/证据区域宽度，并记住当前会话的布局选择。
- [x] 分别明确“目录”“搜索结果”“文件与证据”的打开、收起和选中状态。
- [x] 文件路径可换行或中间省略，保留文件名及完整路径查看方式。
- [x] 跳转后突出目标行；来源为其他分支时同步展示真实分支上下文。
- [x] 小窗口复用现有目录/代码/结果切换能力，保证证据入口也能到达。
- [x] 切换面板保留代码位置；跨项目或分支时按实际上下文重新定位，避免保留错误行号。

**验收标准**：1366 像素宽窗口可对照源码和证据；窄窗口能够完成目录、代码、结果、证据之间的切换；跨分支引用不套用当前分支的代码位置。

**主要组件**：ChunksM0View、[RepositoryFileTree](../../frontend/src/components/RepositoryFileTree.vue)、RepositoryFilePreview、[CodeEvidencePanel](../../frontend/src/features/code/CodeEvidencePanel.vue)。

## 5. 第三阶段：问答与全局交互

### 步骤 07：理清问答中的回答与依据

**优化点**

- [x] 回答正文优先展示；引用入口跟随对应回答，运行和模型说明使用次级样式。
- [x] 引用可以就地展开现有摘要，保留打开完整知识、源码和图谱的入口。
- [x] 引用展示类型、来源标题/文件、分支及行号，和联合检索采用一致的表达。
- [x] 本地证据模式与模型回答明确区分，同时减少重复说明占据首屏。
- [x] 输入区保持稳定位置，发送中展示实际请求状态，失败后保留问题并使用现有重试入口。
- [x] 历史会话的选中、展开和返回状态保持一致；窄屏可收起历史区域。
- [x] 模型切换保留在现有位置附近，不抢占回答阅读区。

**验收标准**：可完成提问、阅读、展开引用、查看源码、返回会话；引用始终属于对应回答；本地证据不会被包装成模型生成结论。

**主要组件**：[AskView](../../frontend/src/views/AskView.vue)、[AskConversationPanel](../../frontend/src/features/ask/AskConversationPanel.vue)、[AnswerEvidencePanel](../../frontend/src/features/ask/AnswerEvidencePanel.vue)、[AskHistorySidebar](../../frontend/src/features/ask/AskHistorySidebar.vue)。

### 步骤 08：统一项目/分支上下文、反馈和状态保留

**优化点**

- [x] 顶部项目和分支构成稳定的上下文区域；各页面重复显示的版本信息适度收敛。
- [x] 提交号和内容版本默认简写，完整值通过详情或复制查看。
- [x] 切换分支时就地显示加载状态，页面旧数据同步退出，避免新分支标题配旧内容。
- [x] 区分“刷新页面数据”和“读取最新分支版本”的按钮名称、提示与作用。
- [x] 同一页面的搜索、筛选、滚动和选中项按项目与分支保留，恢复时核对上下文。
- [x] 保存、发布、切换等成功反馈说明实际结果；错误就近展示并保留用户输入。
- [x] 统一按钮主次：主要动作突出，常用次要动作使用普通按钮，低频动作进入“更多”。
- [x] 用户切换项目、分支或退出登录时，界面状态按原有数据权限正确更新。

**建议反馈文案**

| 操作 | 建议文案 |
| --- | --- |
| 新建成功 | 已保存为草稿，可确认并发布 |
| 编辑成功 | 已保存为新修订，请确认后发布 |
| 指定分支发布成功 | 已发布，共享范围：main、legacy |
| 范围覆盖但仍需分支验证 | 已发布；其他使用分支需分别确认适用性 |
| 无检索结果 | 未找到匹配内容，可调整关键词或筛选条件 |
| 保存发生修订冲突 | 知识已被修改，请刷新后重新核对；当前输入保留 |

**验收标准**：切换后标题、列表和请求上下文一致；两个刷新动作可区分；同一分支来回导航保留操作位置；不同项目的数据不会混入。

**主要组件**：[WorkspaceShell](../../frontend/src/components/WorkspaceShell.vue)、[WorkspaceTabs](../../frontend/src/components/WorkspaceTabs.vue)、[branchContextStore](../../frontend/src/stores/branchContextStore.ts)、[useBranchReadScope](../../frontend/src/features/branches/useBranchReadScope.ts) 及相关页面状态。

## 6. 第四阶段：总览与全站统一

### 步骤 09：调整项目总览的信息顺序

**优化点**

- [x] 首屏依次展示项目身份、当前分支、现有能力是否可用及相关操作入口。
- [x] “进入检索”“准备分支”等已有动作按当前状态突出最相关的一项。
- [x] 图谱节点数、向量覆盖等技术统计放在能力结论之后，保留详细查看方式。
- [x] “当前问题”突出问题、影响和对应操作，避免在多个区域重复长说明。
