# 问答证据去重与原文阅读

本次开发不修改知识或向量数据，不要求重建已有索引，也不调整发布版本。

## 检索规则

- 保留现有相关度门槛和多路融合。重复记录在同一召回通道只计分一次。
- 已通过发布、审核与版本有效性筛选，且没有 Markdown 派生来源记录的知识，可以获得小幅加分。加分为 `系数 × 相关度`，默认系数 0.04，限制在 0–0.08。配置项为 `app.retrieval.curated-knowledge-boost`，环境变量为 `APP_RETRIEVAL_CURATED_KNOWLEDGE_BOOST`；设为 0 可关闭。
- Markdown 代码片段与知识必须匹配仓库、来源分支、内容版本、文件路径，且去除多余空白后的片段全文被知识包含，才用知识替代片段。至少 80 字符，避免短公共语句误合并。
- 同源、同修订、同适用范围且正文完全一致的派生知识合并；不同版本、分支、范围或不同正文保留。
- 同文件代码仅合并行范围和正文均被另一片段包含的冗余片段；互补的重叠片段保留，不对冲突文本做模糊去重。
- 合并使用最高单条得分，不累加重复副本的得分；先处理全部候选再截取结果数量，以便补足有效证据。合并来源随结果保存；调用链扩展不重新加入已合并的代码块。

## 模型输入与历史快照

按当前问题选取原文的相关段落及邻近上下文，完整段落/代码围栏能放入预算时保留完整；过长段落选择命中行附近的连续窗口。片段不经模型改写。预算按最终证据数量预分配，确保每个编号都对应实际发送的正文。代码关联、修订号、范围、内容版本与摘录行号进入模型上下文。

引用保存完整原文、实际使用片段、行号、知识修订和合并来源。历史阅读使用该快照；“查看知识”仍用于进入当前知识详情。检索到但回答未引用的证据单独存储在问答快照中，不计入回答引用覆盖率。旧快照没有片段字段时明确显示“历史原文快照”。编号和覆盖率校验仍不代表已经验证语义蕴含关系。

## 阅读交互

- `AnswerContent`：将正文中的有效引用转为标题按钮，保留代码中的字面编号，发出定位事件。
- `AnswerEvidencePanel`：每条知识原文默认展开，代码默认折叠；展示适用范围和来源记录，并提供现有详情入口。
- `CitationExcerpt`：显示保存的片段，按需展开同一修订的完整原文；复用 Markdown、代码高亮、Mermaid 及其放大能力。
- `AskConversationPanel`：组织每轮回答和证据；点击标题后定位并聚焦该轮对应原文；未引用证据放在“更多相关证据”中。

第一版采用可解释的固定规则，不做语义模糊去重或模型重排。无法确认同源、含有额外信息、缺少来源凭据的内容继续保留，避免丢失有效证据。
