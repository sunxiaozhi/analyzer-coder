# 项目总览的数据口径

本次调整将总览定位为准备状态、知识治理与历史审查的事实面板。页面不对工程质量、测试通过率、安全性或知识内容正确性作综合评分。

| 展示项 | 数据口径 | 未知或失败时的行为 |
| --- | --- | --- |
| 快照、提交、分支 | 与准备状态接口一起返回的已采集版本 | 不使用全局仓库列表中的旧版本代替 |
| 准备与治理状态 | 索引阶段、知识卡状态及最近 5 条审查中的失败记录 | 接口未返回时显示未知；准备中或准备失败时禁用发起审查 |
| 图谱节点、关系 | 当前快照已发布产物的统计；节点包含多种符号，关系包含调用、引用、包含等 | 产物数据库文件缺失、不可读或节点数为零时视为未就绪；准备操作可以重新构建 |
| 向量覆盖率 | 当前配置下有效向量数 / 已索引片段数 | 无分母显示“—”；有缺口时不显示 100%；展示字符相似度或语义检索能力 |
| 已审核的当前知识 | 未归档知识中，同时满足已发布、审核通过、来源版本 CURRENT 的条数 | 接口缺失显示“—”；该状态不构成知识内容正确性的证明 |
| 文件分类 | 支持识别的源码语言，按路径和命名规则归入一个职责类别 | 展示所有非空分类，条形长度为其占识别源码总数的比例 |
| 最近审查 | 本仓库最近 5 条记录，可包含旧快照 | 失败或运行中的统计字段为 null；展示失败原因、快照及详情链接 |

准备状态与健康接口在各自只读事务中使用一致数据库视图。前端比较两者的快照和提交，不一致时提示重新读取；代码分类来自其他版本时不混入本次总览。后台准备中的页面每 5 秒刷新，离开页面时停止轮询。刷新总览只读统计；同步或重扫代码通过准备操作进行。

工作区顶部为功能导航，不再用“已发布快照”的勾选标记暗示所有证据准备完毕。审查详情支持 `reviewId` 链接，也不会用当前提交填补历史审查缺失的待审提交。

仍需理解的边界：

- 图谱文件存在且可读并不证明图谱关系完整，也不替代实际查询时的校验。
- 向量齐备不代表召回准确；字符相似度不会因覆盖率达到 100% 而具备语义理解能力。
- 来源变更检查完成可能没有待检知识，或产生待复核记录，不能解释为知识内容全部正确。
- 文件职责分类是命名规则推断，不是语义分类或测试覆盖率。
- 历史失败记录保留原始错误；改进总览展示不会自动重跑历史审查。

接口变更：`RepositoryPreparation` 增加快照、提交、分支、dirty 和读取时间字段；审查摘要的七项统计允许为 null；健康问题新增 `REVIEW` 操作目标。前后端需一起更新，无数据库迁移。
