## 本轮补齐

- 账号表格保留“编辑”“查看审计”，访问令牌、解锁、重置密码和启停进入“更多”；当前账号不可停用的限制保留。
- 审计页通过缓存路由再次进入时，目标账号筛选立即更新。
- 问答模型及向量模型保存失败后，保留表单和本次输入的密钥供重试；成功后清空密钥，重新打开表单清除旧错误。
- 手机问答范围独占一行，项目名称与分支不再竖排；小屏历史默认收起。
- 证据面板按照自身宽度折叠标题、筛选和操作，1366 像素并排源码时仍可阅读；相关辅助文字提升到至少 12px。
- 回归覆盖草稿、发布、历史恢复、附件、Markdown 生成、分支独立验证、只读入口、跨分支源码往返及键盘焦点恢复。

此前已落地的知识列表摘要、双栏编辑器、阅读抽屉、检索高亮、问答引用展开和状态隔离继续保留。本轮没有修改发布条件、搜索排序、授权判断或后端契约。

## 尚需真实环境联调

本轮没有连接真实后端；检查时本地 8080、18080 端口均未监听。模拟页面的数据只保存在内存，刷新后重置；它验证界面操作和请求参数，不证明服务端业务已执行。

- 使用测试项目完成实际 Git/ZIP 接入、分支准备、任务重试与取消。
- 验证真实附件存储、扫描及下载权限，Markdown 内容变化后的同步、来源复核和发布检索结果。
- 验证真实账号授权、登录验证码、首次改密、外部模型连通性和 MCP 客户端接入。
- 在目标设备验证实际 WebGL 3D 渲染；本轮浏览器验证 2D 节点、关联和源码，3D 降级行为由现有组件测试覆盖。

分支任务接口未提供时间字段，页面未虚构任务时间；任务编号、版本、阶段和错误仍可在详情中查看。

## 复现

在 `frontend` 目录启动 `npm run dev`，按 `frontend/qa/README.md` 配置已有 Playwright，再运行 `node qa/verify-ui.cjs` 和 `node qa/verify-layout.cjs`。无需真实服务账号；不要将模拟验收结果作为生产联调结果。
