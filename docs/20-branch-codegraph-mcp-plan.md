# 分支 CodeGraph 统一 MCP 服务方案

> 状态：实施前方案存档。当前已提供分支发现与只读 CodeGraph 工具；实际工具名、参数和接入步骤以 [MCP 接入说明](../mcp-server/README.md) 为准。下文“当前基础与差距”和分阶段表保留当时的设计背景。

## 目标与范围

对外继续使用平台现有的 `/api/mcp` 地址。使用者通过 MCP 发现自己可读取的项目和分支，选择其中一个后，客户端固定该分支快照，并在同一会话中使用 CodeGraph 的符号搜索、源码与调用路径、调用方/被调用方、影响分析等只读能力。使用者无需从网页复制 UUID，也无需为每个分支配置或启动独立的 MCP 服务。

保留现有 `search_project` 和 `resolve_project_context` 的参数与行为；网页图谱、项目管理、任务系统和原 HTTP 接口保持可用。本方案不让 MCP 令牌触发图谱构建、同步代码、切换全局阅读分支或修改仓库。

## 当前基础与差距

- `RepositoryBranchService.resolve` 已能按账户、项目、分支创建一小时有效的 `contextId`，并把它固定到 `snapshotId`、提交和知识修订；过期或分支不匹配时会报错。
- 分支 CodeGraph 产物按项目和快照构建，在受管副本中发布；现有 HTTP 接口支持按快照读取图谱概览和影响分析。
- MCP 当前仅有 `search_project`、`resolve_project_context`。它尚不能列出可选项目/分支，也没有 CodeGraph 查询工具。
- 网页使用的图谱概览是有限节点/边投影，不能代替 CodeGraph 原生 `explore` 返回的带行号源码、调用路径和动态调用线索。
- 本机 CodeGraph CLI 为 1.5.0，而平台的 SQLite 图谱读取器标注面向 1.6 及以后。实施前必须确认目标环境和实际产物格式；工具不能在不兼容时伪造空结果。

## 使用流程

1. MCP 客户端调用 `list_codegraph_scopes`，按当前令牌的 READ 权限分页获取项目及其分支。返回项目名、分支名、提交摘要、快照、内容/图谱状态及不可用原因。未就绪分支仍展示，但不能调用图谱查询。
2. 使用者用名称选择一个项目与分支。若同名或目标不明确，助手列出候选项请其选择；不会自动使用默认分支。
3. 助手将选项中的 `repositoryId + branchId` 传给现有 `resolve_project_context`，取得账户绑定、快照固定的 `contextId`。
4. 后续 CodeGraph 工具调用携带 `repositoryId + contextId`，返回统一版本信封：项目、分支、提交、`snapshotId`、图谱产物 ID/CLI 版本，以及工具结果。用户只看到可读名称，不必手工处理 UUID。
5. `contextId` 过期后，在继续查询前重新解析并说明版本是否发生变化；若已更新，明确询问是否切换到新快照。新对话重新选择，不沿用上次项目。
6. 选中分支没有已发布图谱时，返回准备状态和“到项目管理一键准备或构建图谱”的提示，不回退到其他分支，也不在 MCP 读取请求中自动构建。

MCP 服务器提供工具及结果，具体的候选展示和选择交互由接入的 AI 客户端完成。若客户端不能弹出选择器，助手在对话中列出候选项。

## 工具设计

| 工具 | 作用 | 主要输入 | 实施优先级 |
| --- | --- | --- | --- |
| `list_codegraph_scopes` | 分页发现可读取项目、分支及图谱状态 | `query?`、`page?`、`pageSize?` | 第一阶段 |
| `resolve_project_context` | 复用现有能力，固定所选分支快照 | `repositoryId`、`branchId` 或 `contextId` | 已有 |
| `codegraph_explore` | 对自然语言问题或符号集合返回相关源码、调用路径和影响提示 | `repositoryId`、`contextId`、`query`、`maxFiles?` | 第一阶段 |
| `codegraph_node` | 读取单个符号或文件范围，含行号与依赖线索 | 上下文、`symbol?` 或 `file?`、`offset?`、`limit?` | 第一阶段 |
| `codegraph_search` | 搜索/消歧符号，可按种类过滤 | 上下文、`query`、`kind?`、`limit?` | 第一阶段 |
| `codegraph_callers` / `codegraph_callees` | 沿真实调用边查看上下游 | 上下文、`symbol`、`limit?` | 第二阶段 |
| `codegraph_impact` | 对指定符号计算受影响路径和覆盖范围 | 上下文、`symbol`、`depth?` | 第二阶段 |
| `codegraph_files` / `codegraph_status` | 文件树、当前快照图谱状态 | 上下文、范围/分页参数 | 第三阶段 |
| `codegraph_affected_tests` | 由变更文件推断相关测试；只有目标 CodeGraph 版本可靠支持时开放 | 上下文、`files`、`depth?` | 第三阶段、能力门控 |

工具名尽量与 CodeGraph 原生 MCP 对齐，但不直接透传原生 `projectPath`。CLI 能力和服务端已发布 SQLite 能力要逐项对照：凡原生输出包含源码或动态调用路径，而平台现有图谱投影没有的，应从对应快照的受管 CodeGraph 副本读取，不用简化投影冒充原生结果。默认可向客户端重点展示 `explore`、`node`、`search`；其余工具仍可调用，避免长工具列表干扰普通使用。

本方案第一阶段针对 Git 分支。ZIP 单版本项目没有 `branchId`，现有 `resolve_project_context` 不能直接为它创建分支上下文；其既有 MCP 检索行为保持不变。若后续要在统一发现列表中纳入 ZIP，需要另设计单版本快照定位方式，不能伪造 Git 分支。

## 服务端边界

- 每次调用使用令牌对应的实时 READ 权限过滤列表并校验目标。客户端不能传文件系统路径、任意图谱产物 ID 或任意快照 ID；受管路径只由服务端通过项目和上下文解析。
- 只查询状态为 `PUBLISHED` 且与 `context.snapshotId` 完全一致的产物。禁止跨分支、跨项目、跨账户复用上下文；过期、已清理、未构建、不兼容都返回明确错误码。
- 原生 CLI 查询只能执行固定命令和服务端生成的受管项目路径；参数以独立进程参数传递，限制超时、输出字节数、文件数、行数、深度与并发。不会执行客户端提供的命令。
- 源码结果仍属于项目数据，只对具有 READ 权限的账户返回。错误响应不暴露服务器绝对路径、数据库信息或凭据。保留必要的调用审计，不记录完整源码输出。
- 读取工具不修改发布快照或图谱；构建仍由项目管理中的现有任务和 MAINTAIN 权限负责。
- 远程 `/api/mcp` 与本地 stdio 适配器使用同一语义和错误码；旧工具及旧客户端继续可用。

## 交付顺序与验收

**第一阶段：发现与核心查询。** 实现项目/分支发现、选择和上下文固定，再开放 `explore`、`node`、`search`。验证项目名称歧义、普通用户只见授权项目、未就绪分支可见但不可查询、双分支相同符号不串数据、上下文过期与新旧快照并存、CLI/产物版本兼容。

**第二阶段：关系与影响。** 开放 callers、callees、impact；对照同一快照的 CodeGraph CLI 输出与网页影响分析，核对调用方向、动态调用线索、深度截断和空结果语义。

**第三阶段：补齐原生辅助能力。** 增加 files、status 和经验证可用的 affected tests；更新远程 MCP、stdio 适配器、帮助说明及工具目录。执行权限、路径、并发、超时和大仓库输出测试。

验收标准：使用者在全新对话里只凭项目/分支名称完成选择，并能连续提问、读取源码和分析影响；每条结果可追溯到正确快照；未就绪或版本变化不静默回退；现有网页与 MCP 检索行为不回归。
