# Analyzer Coder 使用手册

核对日期：2026-09-17
当前定位：最小版本的“代码 + 知识”联合检索工具。

## 1. 系统解决什么问题

开发者接入一个项目后，可以在同一个入口中搜索源码片段和项目知识，并从结果回到文件、行号或知识原文核对。系统优先提供可追溯的检索证据，不把模型生成内容当作代码事实。

最小主流程只有四步：

1. 在“项目管理”接入仓库。
2. Git 项目在“项目管理”准备目标分支快照，或在“项目总览”使用一键准备；ZIP 项目沿用单版本准备。
3. 在“知识库”查看或补充 Markdown 与知识卡片。
4. 在“代码与知识”输入问题，联合检索两类结果。

“问项目”、代码图谱和 MCP 是可选入口：问答基于检索证据生成自然语言回答；图谱展示结构关系；MCP 让编码工具只读查询代码、知识和已发布的分支图谱。

## 2. 第一次使用

### 2.1 接入项目

进入“项目管理”，选择本地 Git、远程 Git 或 ZIP。系统把可读取的项目内容发布为受管快照，不在原仓库中编辑或提交代码。

本地路径是后端服务所在机器能读取的路径，不是浏览器所在电脑的任意路径。远程仓库是否能导入取决于网络、凭据和分支配置。

### 2.2 准备索引

Git 项目先在“项目管理”选择并准备目标分支；也可在“项目总览”使用一键准备。ZIP 项目沿用单版本准备。最小检索依赖已发布快照和代码片段；向量模型、代码图谱和知识失效检查属于增强能力，缺失时仍可使用关键词检索。图谱查询需要目标分支另有已发布的 CodeGraph 产物。

准备完成后应至少确认：

- 当前项目、分支和 Commit 正确；
- 已发布 Snapshot；
- 代码片段数大于零；
- 页面没有阻断检索的错误。

### 2.3 准备知识

进入“知识库”查看项目中的 Markdown 来源和知识卡片。具有维护权限的用户可以补充项目约束、架构说明和开发约定；只读用户仍可查看可见知识。

知识结果会携带状态和来源。过期、未发布或不满足检索条件的知识不会被伪装成正式规则。

### 2.4 联合检索

进入“代码与知识”，输入路径、类名、函数名、业务概念或自然语言问题。每次查询都限定在当前选择的项目内。

结果分为两类：

| 类型 | 主要来源 | 核对方式 |
| --- | --- | --- |
| 代码 | 当前 Snapshot 的文件与 `code_chunks` | 查看路径、符号、行号和原文 |
| 知识 | 可检索的知识卡片与 Markdown 来源 | 查看标题、状态、来源和正文 |

排序分数只表示相关性，不等于事实正确率。回答问题时应优先核对原始代码和知识来源。

## 3. 可选能力

### 3.1 问项目

“问项目”先检索当前项目的代码和知识，再生成带引用的回答。没有外部模型时可以使用本地证据模式；外部模型文本是辅助总结，引用才是核对依据。

### 3.2 MCP 接入

在页面右上角打开“MCP 接入”，创建自己的账户访问令牌，并将远程 `/api/mcp` 地址与 `Authorization: Bearer <令牌>` 配到支持 Streamable HTTP 和自定义请求头的客户端。所有账户共用同一服务地址；每次工具调用按令牌账户的实时仓库 READ 权限校验。仅支持 stdio 的客户端可使用仓库提供的 Node.js 适配器，详见 [MCP 接入说明](../mcp-server/README.md)。

查找代码和知识时，调用 `search_project` 并提供 `repositoryId`、`query`；不指定分支时读取项目默认快照。指定 `branchId` 后可固定已准备分支的代码和适用知识，返回的 `context.contextId` 可供后续查询复用。

查分支图谱时按以下顺序操作：

1. 调用 `list_codegraph_scopes`，按项目名与分支名选择 `codegraphReady` 为 `true` 的条目。该列表只包含当前账户可读取的 Git 项目。
2. 使用所选 `repositoryId + branchId` 调用 `resolve_project_context`，取得账户绑定、有效期一小时的 `contextId`；也可在首次图谱查询时直接传这两个 ID。
3. 后续图谱查询传 `repositoryId + contextId`。`codegraph_explore`、`codegraph_node`、`codegraph_search` 用于探索源码和符号；`codegraph_callers`、`codegraph_callees`、`codegraph_impact` 用于调用关系和影响分析；`codegraph_files`、`codegraph_status`、`codegraph_affected` 用于文件、图谱状态和受影响测试线索。

`contextId` 固定到创建时的分支快照，不随分支更新自动切换。过期后需重新选择或解析，并核对新旧提交。分支未准备或图谱未发布时会明确报错，不会回退到其他分支。ZIP 单版本项目仍可使用原有 `search_project` 默认快照检索，不出现在分支图谱发现列表中。MCP 工具不会同步、构建、执行测试或修改仓库。

### 3.3 代码图谱

通过导航“代码图谱”进入独立的结构地图页面（`/atlas`），不改变项目首页。页面要求当前快照已经发布 CodeGraph 产物；没有产物时可前往项目总览准备，再刷新图谱。

- 无关键词时展示模块聚合图；模块由文件路径规则分组，不等于人工确认的业务架构。
- 默认进入 3D 空间模式，按模块分区排列，保留立体区域、文件图标和空间连线。默认关闭自动环绕，需要演示时可开启；支持拖动旋转、滚轮缩放和右键平移。点击节点后聚焦当前节点与一层关联节点，淡化无关节点；关闭详情恢复选中前的 3D 视角。双击模块或使用右侧“展开”按钮进入符号视图。
- 可切换到平面阅读模式；平面模式支持拖拽平移、滚轮缩放，节点支持回车展开模块。大图默认保持可读比例，“全景”按钮用于缩略查看全部节点。

- 三维坐标仅用于模块分组展示，不代表业务层级、运行顺序或依赖强度。图标和环形装饰不增加虚构节点或关系。
- 模块使用文件夹图标；符号按所属源文件路径显示 Java、TS、JS、Vue、Python、Markdown、配置等类型图标，未知类型使用通用文件图标。3D 图标始终朝向镜头，标签边框保留模块分色。图例只列当前视图出现的类型；类型图标不会额外导入未被 CodeGraph 解析的文件。
- 全景默认显示模块间聚合连线；符号视图默认选中后才显示相关连线，也可开启“全部连线”。入向关系为青色，出向关系为蓝色。仅在选中时为最多 80 条连线显示流动粒子，按静态关系的源到目标方向移动，不代表实时调用。
- 3D 标签按屏幕空间避让，每帧最多显示 32 个标签；可旋转、缩放或搜索定位其他节点。设备不支持 WebGL 时自动启用基于 CSS/SVG 投影的兼容 3D，继续提供空间旋转、缩放、节点聚焦和方向连线；只有两种 3D 渲染都失败时才回退平面模式。减少动态效果设置会关闭自动环绕和粒子运动。
- 操作说明、文件类型图例与渲染诊断统一收在“图例与设置”中，可重新检测 WebGL 或手动使用兼容 3D。当前引擎要求 WebGL 2，具有 GPU 并不等同于浏览器已启用 WebGL 2；可在 Chrome 的 chrome://gpu 或 Edge 的 edge://gpu 查看状态。本次页面使用过程中自动降级后，切换模块沿用兼容模式，避免反复创建失败的上下文。
- 图标按屏幕尺寸限制大小，标签在上下左右四个方向尝试避让图标与其他标签。三维透视仍可能使节点投影重叠，可旋转视角、搜索或选中节点聚焦查看。
- 点击符号查看源码摘录；右侧面板撑满图谱页面高度，桌面宽屏与画布并排，窄屏使用全高侧栏。代码长行自动换行，只需纵向滚动，换行后的续行不重复行号。有源码时默认收起关系列表，把高度留给代码。入向/出向筛选按原始关系方向高亮，关系类型保留 CodeGraph 原值。
- 右侧仅列出当前视图内的一层关系；模块外、搜索未命中或因数量限制未展示的节点不包含在该列表。静态关系不代表真实运行调用。
- 全景最多返回 120 个模块，符号视图最多 240 个节点和 1200 条关系；截断时明确提示缩小范围。源码快照不一致时拒绝显示，并提示刷新。

首版没有路径查询、源码执行、图谱编辑或自动代码修改。大图后端读取仍复用现有 SQLite 图读取器，需要在大仓库上进一步评估查询耗时和内存。

### 3.4 分支工作区

项目管理页已采用左侧项目列表、右侧分支列表：选择左侧项目后，右侧显示该项目的受管分支。选择分支可准备快照、构建代码向量和验证适用知识。“项目管理操作”保留资料、凭据、权限和原默认版本操作。ZIP 等非 Git 来源使用单版本入口。

当前“接入项目”仍沿用导入并准备来源的兼容流程；先建立项目元数据再按需拉取分支，以及全站统一分支切换，按文档 18 后续阶段实施，尚未完成。

选择项目后，可从顶部页签区打开“分支工作区”。该窗口锁定自己的分支、Snapshot 和 Commit，不会切换服务端工作目录，也不会改变其他页面正在使用的默认快照。

- 本地 Git：输入服务端仓库中已存在的分支名，添加后按需准备或更新快照。
- 远程 Git/GitLab：维护者可点击“发现分支”，通过仓库已绑定凭据读取远程分支；选择“添加”只建立跟踪记录，仍需明确点击“准备分支”才会生成快照。
- 发现远程分支不会自动索引所有分支。准备过程把远程提交拉到临时内部引用，不执行 checkout/reset；失败时保留该分支上一次成功发布的快照。
- 分支准备完成后，可在窗口内检索该分支代码和适用知识，并复制 `repositoryId`、`branchId` 供 MCP 使用。
- 准备和代码向量构建均在后台排队执行；窗口显示阶段与失败信息，关闭窗口不取消任务。重复提交相同活动任务不会重复排队，失败后可重试。准备期间仍可阅读旧快照，完成后需显式打开或刷新阅读版本。
- 在已打开的分支快照中点击“构建代码向量”，任务固定到这个快照，不改默认分支。同仓库中内容摘要、模型、维度与检索能力一致的代码向量可复用；无语义模型时按现有配置使用字符相似度，并明确区分两者。
- 展开“知识分支验证”，选择适用知识并核对正文。管理者可填写结论和说明；只读用户可查看。验证绑定知识修订、分支和快照，知识或快照更新后不会继承旧结论。保存验证不等于发布或审核知识。

### 3.5 管理功能

管理员可以查看索引任务、配置模型、管理账号权限和读取审计日志。这些能力用于保障检索系统运行，不属于开发者的最小使用路径。

## 4. 数据与权限边界

| 边界 | 说明 |
| --- | --- |
| 仓库隔离 | 每个请求都按当前账号和 `repositoryId` 校验权限 |
| 版本一致性 | 代码、片段、向量和知识引用应与当前 `snapshotId` 对齐 |
| 只读代码 | 平台浏览和检索受管快照，不充当在线 IDE |
| 模型边界 | 模型输出是建议，不覆盖原始文件和知识来源 |
| 降级能力 | 向量或图谱不可用时，系统可以继续使用关键词和文件检索 |

权限从低到高为 READ、MAINTAIN、MANAGE 和 OWNER。前端隐藏按钮只用于减少误操作，最终权限以服务端校验为准。

## 5. 当前明确不做

当前版本不包含变更审查、需求影响预估、PR/MR Webhook、审查型 CI、自动执行测试、测试或审批判定、任务结果回报，也不会自动修改或提交代码。`codegraph_affected` 只提供受影响测试文件线索，不运行测试，也不作通过/失败判定。

## 6. 常见问题

### 搜不到代码

确认已选择正确项目，项目总览存在当前 Snapshot 和代码片段。然后先用真实路径、类名或函数名做一次关键词查询。

### 只看到代码，没有知识

检查知识库是否存在可检索内容及其发布、来源状态。Markdown 文件存在不代表已经转化为正式知识卡片，但仍可作为知识来源展示。

### 向量或图谱不可用

这不会阻断最小检索。用户仍可通过关键词、路径和原文完成核对；MCP 图谱工具需要已发布产物，出现 `CODEGRAPH_ARTIFACT_NOT_AVAILABLE` 时，应准备所选分支并构建图谱。

### 切换项目后结果变化

网页结果随当前选择的项目变化是预期行为。MCP 调用由显式传入的 `repositoryId` 和可选分支上下文确定范围，不跟随网页的项目选择自动切换。
