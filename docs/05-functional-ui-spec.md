# 代码知识平台功能与 UI 设计说明

版本：v0.9  
日期：2026-07-19  
依据：`01-requirements.md` v0.2

## 1. 产品信息架构

平台按用户任务组织为七个界面，而不是按后端技术模块组织。

| 页面 | 核心任务 | 对应需求 |
| --- | --- | --- |
| 仓库管理 | 接入代码仓库并判断是否可索引 | 仓库管理、CodeGraph 检测 |
| 索引任务 | 观察代码同步、CodeGraph 分析和知识索引过程，定位失败并重新执行 | CodeGraph、RAG 索引、可观测性 |
| 代码检索 | 用关键词、语义和符号关系定位代码 | 混合检索、代码引用 |
| 代码问答 | 基于检索证据理解业务与实现 | 代码问答、引用预览 |
| 调用图与影响分析 | 理解上下游依赖和改动风险 | 调用图、影响分析 |
| 知识卡片 | 将人工确认的结论沉淀为长期知识 | 知识沉淀 |
| 系统设置 | 管理模型、索引、安全和路径范围 | 安全性、可扩展性 |
| 账号管理 | 管理账号、角色和访问状态 | 登录与基础权限扩展 |

登录页仅作为未来鉴权入口。M0 单用户模式不应把登录页当作真实安全边界。

## 2. 功能详细说明

### 2.1 仓库管理

作用：接入本地或上传的代码源，形成可同步、可版本化、可索引的仓库记录，是所有检索、问答和图分析的前置入口。

1. 添加仓库弹窗先选择来源：本地 Git、远程 Git、GitLab、ZIP 上传；切换来源后只展示该来源需要的字段。
2. 本地 Git：填写名称、本地路径和默认分支；校验目录白名单、Git 状态和重复路径。
3. 远程 Git：填写名称、仓库地址、认证方式和默认分支；密码、Token 和私钥只允许写入，不在编辑页回显明文。
4. GitLab：填写项目地址或项目 ID、访问令牌和默认分支；提供“测试连接”并展示可访问分支。
5. ZIP 上传：填写仓库名称并选择压缩包；展示文件名、大小、上传进度和安全校验结果。
6. 仓库列表展示来源、代码版本、同步状态、CodeGraph 状态、索引状态、最后同步和最后索引时间。
7. Git 仓库的版本展示 branch/commit；ZIP 仓库展示上传版本与摘要，相关位置不显示无意义的 branch/commit。
8. 快捷动作按来源变化：本地 Git 为“重新扫描”，远程 Git/GitLab 为“立即同步”，ZIP 为“重新上传”；公共动作包括全量索引、查看任务和删除。
9. ZIP 重新上传使用确认弹窗，明确“完整覆盖而非合并”“仓库 ID 和历史保留”“新索引成功前仍使用旧索引”。
10. 删除本地 Git 只删除平台数据；删除远程 Git、GitLab 或 ZIP 仓库时同步删除平台受管代码副本。

关键状态：首次空状态、上传中、同步中、等待认证、认证失败、路径不可访问、非 Git 目录、ZIP 校验失败、代码可用但索引过期、缺少 CodeGraph、索引失败。

添加仓库弹窗字段：

| 来源 | 必填字段 | 可选字段 | 版本标识 |
| --- | --- | --- | --- |
| 本地 Git | 名称、本地路径 | 默认分支 | branch + commit + 工作区状态 |
| 远程 Git | 名称、Git URL、默认分支 | HTTPS Token 或 SSH 凭据 | branch + commit |
| GitLab | 名称、项目地址/ID、Access Token、默认分支 | GitLab 服务地址 | branch + commit |
| ZIP | 名称、ZIP 文件 | 解压根目录（无法自动识别时） | 上传版本 + SHA-256 |

### 2.2 CodeGraph 集成

作用：提供符号定义、引用、caller、callee 和文件关系等确定性代码事实。

1. 操作入口位于仓库管理页。根据状态展示“开始分析”“重新分析”“查看任务”或“查看错误”，不设计独立 CodeGraph 菜单。
2. 仓库页显示 CodeGraph 状态、对应代码版本、CLI/schema 版本和最后成功时间。
3. 状态包括未生成、排队中、分析中、可用、已过期、失败和版本不兼容；“已过期”与“分析失败”不得合并显示。
4. 开始分析前展示代码版本和预计影响；重新分析时说明失败不会覆盖上一版可用产物。
5. 分析任务进入索引任务页面统一观察，任务类型明确标记为“CodeGraph 分析”。
6. 任务详情展示环境预检、扫描源码、识别语言、解析符号、建立引用、建立调用关系、写入产物和结果校验阶段。
7. 检索结果标记“结构事实”“语义匹配”或“关键词匹配”；符号详情可查看定义、调用方、被调用项和源码。
8. CodeGraph 不可用时禁用调用图和结构化关系查询并给出修复入口，关键词和语义检索仍可继续。
9. 添加仓库弹窗提供“导入后自动分析并建立索引”复选项，默认不选中。

不设计独立技术管理页，避免把 SQLite schema 等实现细节暴露给普通用户。

### 2.3 RAG 索引

作用：将代码、文档按可追溯结构切分为 chunk，并生成语义检索所需的 embedding。

1. 全量索引依赖同一代码版本的可用 CodeGraph，依次读取结构事实、切分内容、生成向量并发布索引版本。
2. 增量索引：M2 基于 Git diff 和 hash 更新变化文件；M0/M1 不伪装支持。
3. 任务观察：任务列表支持按“代码同步、CodeGraph 分析、知识索引”类型筛选，展示阶段、进度、耗时和失败摘要。
4. 产物浏览：按语言、类型和路径过滤 chunk，并核对源码和行号。
5. 版本保护：新 CodeGraph 和新索引均在成功校验后切换，失败时各自的上一版产物保持可用。

### 2.4 混合检索

作用：合并语义向量、关键词/符号和 CodeGraph 图关系，兼顾模糊功能定位与精确结构查询。

1. 支持自然语言、符号名、文件路径和错误信息。
2. 自动识别问题类型，也允许选择综合、符号、语义、调用关系模式。
3. 展示命中原因、综合分、文件位置和相关符号。
4. 右侧源码预览与结果同步，定位行号并复制引用。
5. 提供排序解释，帮助判断结果可信度。

### 2.5 代码问答

作用：把多处代码证据组织成实现说明，减少手工拼接业务流程的时间。

1. 选择一个仓库后提问，避免默认跨仓混用证据。
2. 回答按结论、流程、限制组织，并在事实句后附引用编号。
3. 右侧“证据轨道”展示文件、符号、行号和证据类型。
4. 点击引用打开源码；证据不足时明确停止推断。
5. 用户可评价回答，M2 可将确认后的回答保存为知识卡片。

### 2.6 调用图与影响分析

作用：评估修改函数、类或文件后，可能受影响的入口、服务和测试。

1. 选择中心符号，控制 caller/callee 方向和深度。
2. 节点按入口、业务、基础设施和测试标记，不只依赖颜色。
3. 选择节点后显示源码位置、关系类型和最短路径。
4. 影响摘要包含直接影响、间接影响、测试建议和风险。
5. 节点超限时按模块聚合，防止图谱不可读。

### 2.7 知识卡片

作用：保存人工确认的模块说明、架构决策和 FAQ，补充纯代码无法表达的团队语境。

1. 支持模块说明、FAQ、架构决策和排障记录。
2. 卡片绑定仓库、适用 commit/分支、引用、作者和时间。
3. 区分草稿与已发布，只有已发布卡片进入检索。
4. 引用代码变化后标记“需要复核”。

### 2.8 系统设置

作用：集中管理检索质量、安全边界和运行成本。

1. 路径范围：允许导入的根目录和符号链接策略。
2. 模型配置：本地/外部 embedding 与 LLM provider、连接测试。
3. 数据安全：排除规则、外部发送开关和审计元数据。
4. 索引参数：单文件大小、并发数、排除目录和任务超时。

### 2.9 登录与账号管理

登录页作用：提供统一身份入口。界面只包含用户名、密码、验证码和登录动作，不提供注册与忘记密码入口。

账号管理作用：由管理员维护本地账号及基础角色，为后续仓库权限和审计能力提供主体数据。

1. 支持新增账号、修改角色、停用和重新启用账号。
2. 基础角色为管理员、成员和只读；仓库级权限不在当前页面展开。
3. 展示账号状态、最近登录时间和最近 IP，帮助管理员发现闲置或异常账号。
4. 系统创建者不可被普通管理员删除，停用当前登录账号需要额外确认。
5. M0 单用户模式下该页面只作为设计预留，接入真实鉴权后再开放菜单。

## 3. 统一交互规则

1. 全局仓库选择器只影响检索、问答、图谱和知识卡片；仓库管理页不显示。
2. 蓝色只表示操作或当前选择；绿色、橙色、红色只表示状态。
3. 所有代码事实通过“证据轨道”显示来源类型、文件、符号、行号和 commit。
4. 未实现、不可用和无权限是不同状态，文案与按钮行为不得混用。
5. 长任务进入任务中心观察；短表单使用 Element Plus Dialog。

## 4. 视觉规范落地

本轮设计严格基于项目根目录 `DESIGN.md`：

1. 画布使用 Paper White `#ffffff` 与 Parchment `#f5f5f7`，侧边导航使用纯黑 `#000000`。
2. Action Blue `#0066cc` 是唯一交互强调色，用于主要按钮、当前选择、进度和引用定位。
3. 页面标题采用 SF Pro Display/system-ui 600，正文采用 SF Pro Text/system-ui 400；不使用 500 字重。
4. 操作、搜索和模式选择使用胶囊形；表单字段保持 8px 圆角；工具卡片使用 18px 圆角。
5. 卡片、按钮和文字不使用阴影，层级只通过画布变化、细边框和留白表达。
6. 统计信息收敛为连续信息带，减少后台模板常见的独立指标卡堆叠。
7. “证据轨道”使用连续蓝色引用线，是代码知识平台的识别性组件。

### 4.1 Header 信息架构

Header 使用 `surface-black #000000`，高度 44px，对应 `global-nav` 规范。内容按作用域分组：

1. Header 左侧固定显示全局仓库切换器，不展示“默认工作区”。
2. 面包屑位于主内容区，不放入 Header。
3. 代码检索、代码问答、调用图和知识卡片在内容上下文栏显示当前仓库的版本标识与索引新鲜度；Git 显示 branch/commit，ZIP 显示上传版本/摘要。
4. Header 右侧固定放全局搜索、帮助、通知和账户入口。
5. 页面主操作使用 `primary #0066cc`；索引新鲜度和当前选择使用同一主色。
6. 服务健康详情不长期占用 Header，异常时通过通知入口和页面内状态提示呈现。

### 4.2 石墨冰青主题

在保留 `DESIGN.md` 的排版、留白、圆角和无阴影规则基础上，项目主题由 Action Blue 调整为更贴近开发者工具的石墨冰青色：

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| Graphite Header | `#111315` | 顶部全局导航 |
| Graphite Navigation | `#171A1D` | 左侧功能导航 |
| Graphite Selected | `#262B30` | 深色区域选中项与搜索入口 |
| Ice Teal Primary | `#007F82` | 主按钮、浅色页面链接、进度和选中边框 |
| Ice Teal Highlight | `#55D6D2` | 深色区域高亮、索引新鲜度和键盘焦点 |
| Code Surface | `#1C2127` | 源码查看器和任务日志 |
| Work Canvas | `#F4F6F8` | 页面背景 |
| Hairline | `#DDE2E7` | 面板和输入框边界 |

`#007F82` 采用比装饰性青色更深的明度，以保证主要按钮上的白色文字具有足够对比度。高亮青 `#55D6D2` 不用于白底按钮。

该主题作为备选探索稿保留，不作为当前实施基线。当前确认采用 4.1 节的蓝色主题：页面主操作色 `#0066CC`，深色 Header 高亮 `#2997FF`。

### 4.3 蓝色导航框架

为降低纯黑 Header 与侧栏同时出现时的压迫感，实施主题进一步调整框架配色：

1. Header 使用 92% 白色磨砂表面，文字采用深蓝灰 `#102A43`，与内容区保持连续。
2. 侧栏采用深蓝黑 `#0D1B2A`，品牌区采用更深的 `#0A1624`。
3. 当前菜单采用 `#17324F` 背景和 `#2997FF` 左侧导轨，图标使用 `#63B3FF`。
4. 仓库、branch 和 commit 标签使用 `#F1F7FD` 浅蓝表面及 `#C7D9EA` 边框。
5. Header 全局搜索使用 `#EEF3F8`，帮助、通知和账户保持低对比，避免与页面操作竞争。
6. 主内容仍使用白色与 `#F5F5F7`，主操作继续使用 `#0066CC`。

### 4.4 浅色侧边栏

侧边栏由深蓝黑调整为浅色导航面板，与白色 Header 形成连续的轻量框架：

1. 品牌区使用白色 `#FFFFFF`，导航区使用浅蓝灰 `#F7FAFD`。
2. 菜单文字使用 `#334E68`，默认图标使用 `#627D98`。
3. 当前菜单使用 `#E8F2FC` 浅蓝背景、`#0066CC` 图标和左侧导轨。
4. 侧栏右侧和品牌区底部使用 `#DCE5EF` 细分隔线，不添加阴影。
5. 底部环境信息使用低对比 `#829AB1`，避免与菜单竞争。

### 4.5 纯白侧边栏

实施版侧边栏进一步统一为纯白背景 `#FFFFFF`。品牌区、菜单区和底部环境区不再使用浅蓝灰底，仅通过 `#DCE5EF` 右侧分隔线与主画布区分。选中菜单继续使用 `#E8F2FC` 浅蓝背景和 `#0066CC` 导轨。

### 4.6 紧凑主内容区

主内容区桌面内边距由 `32px 40px` 调整为 `24px 28px`，页面标题区域高度由 `72px` 调整为 `64px`。组件自身内边距和栏间距保持不变，以增加表格、代码和调用图的可用空间，同时避免内容拥挤。
