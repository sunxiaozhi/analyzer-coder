# 最小界面规范

## 信息架构

主导航保留：项目总览、代码与知识、问项目、知识库、项目管理、MCP 接入。默认主操作是“开始联合检索”。

## 代码与知识

- 顶部只有一个查询框和搜索按钮；
- 结果在一个列表中按相关度混排；
- 每条结果必须标记 `CODE` 或 `KNOWLEDGE`；
- 代码结果显示路径、行号、符号和片段；
- 知识结果显示标题、摘要、状态和代码关联数量；
- 点击代码打开源码定位，点击知识打开知识详情；
- 空状态提示用户尝试类名、错误信息或业务术语；
- 不出现风险评分、审查结论、测试要求或审批要求。

## 项目总览

只回答两个问题：仓库是否已准备好，以及用户下一步能否开始检索。准备完成后主按钮跳转“代码与知识”。

## 知识库

支持知识卡维护、发布状态和代码范围关联。界面应把知识描述为检索上下文，不把它包装成自动执行的审查规则。

## MCP 接入

只展示 `search_project` 的配置、参数示例、权限说明和排错信息。

## 视觉原则

整体保持工程工具的克制风格。代码使用冷色标识，知识使用赭黄色标识；颜色只用于区分证据类型，不表达未经计算的风险或结论。
