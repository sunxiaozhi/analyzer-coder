# 代码知识平台功能与 UI 设计说明

版本：v4.0
日期：2026-08-31
依据：`01-requirements.md` v3.1、当前 Vue 路由与样式
状态：当前运行 UI 基线

> 本文只描述当前用户能够看到和操作的页面。快速开始、开发者入门、备份恢复、多仓检索和流式问答没有当前入口，不纳入现状信息架构。

## 1. 产品信息架构

### 1.1 主导航

普通开发者固定显示：

1. 项目总览
2. 代码与证据
3. 问项目
4. 变更审查

当前仓库具备 MAINTAIN 以上权限时显示“项目维护”：

1. 知识治理
2. 项目管理

超级管理员显示可折叠的“系统管理”：

1. 索引任务
2. 模型配置
3. 账号权限
4. 审计日志

登录成功和根路由默认进入 `/overview`。菜单由平台角色控制；仓库内操作由服务端 capabilities 控制。

### 1.2 页面与路由

| 页面 | 路由 | 页面单一任务 |
| --- | --- | --- |
| 登录 | `/login` | 建立会话或完成首次改密 |
| 项目总览 | `/overview` | 核对当前版本、工程健康、可信知识和审查条件 |
| 代码与证据 | `/search` | 浏览源码并核对混合检索、关系、知识和审查引用 |
| 变更审查 | `/change-impact` | 对真实 Git 变化生成绑定 Snapshot 的确定性审查 |
| 问项目 | `/ask` | 对当前仓库提问、恢复历史并核对代码/知识证据 |
| 知识治理 | `/knowledge` | MAINTAIN 以上维护人工知识、附件、修订和代码引用 |
| 旧图谱链接 | `/graph` | 兼容重定向到代码与证据，不渲染独立页面 |
| 项目管理 | `/repositories` | 维护者接入、维护和治理仓库 |
| 索引任务 | `/indexing` | 管理员观察任务和当前向量索引 |
| 账号权限 | `/accounts` | 管理员管理账号和仓库授权 |
| 审计日志 | `/audit` | 管理员独立核对系统操作记录 |
| 模型配置 | `/settings` | 管理员备案、检测问答/向量模型 |

## 2. 全局壳层

### 2.1 侧边栏

- 桌面宽度 204px，白色背景，右侧细边框。
- 品牌区高度 58px。
- 菜单图标和文字同排，激活项使用浅蓝背景与蓝色文字。
- 日常研发、项目维护和系统管理分组展示；系统管理可折叠。
- 项目维护入口由当前可见仓库 capabilities 决定；系统管理只在 `auth.isAdmin` 为真时生成。
- 小于等于 760px 时侧栏转为顶部横向导航，隐藏文字以保留空间。

### 2.2 顶部栏

- 桌面高度 58px。
- 左侧为“当前仓库”选择器，数据来自当前账号可见仓库。
- 切换仓库调用服务端账号偏好接口；失败保留当前状态并提示错误。
- 右侧显示账号名称、管理员/普通用户和退出按钮。
- 管理页仍显示全局仓库，但管理列表不以它作为筛选条件。

### 2.3 工作区页签

- 位于顶部栏下方，固定高度 44px，与路由内容间距 12px。
- 只记录访问过的业务路由，同一路由名称只保留一个页签。
- 激活页签使用蓝底白字，非激活页签为透明/浅灰 hover。
- 支持单个关闭、中键关闭、关闭其他和关闭全部。
- 页签轨道可横向滚动。
- localStorage 只保存 `name/title/fullPath`，不保存业务正文。
- 关闭全部后回到项目总览。
- 路由内容使用 KeepAlive，最多缓存 12 个页面实例。

## 3. 页面设计

### 3.1 登录

页面采用左右分栏：左侧插画，右侧品牌和表单；移动端隐藏插画。

当前交互：

1. 用户名、密码为必填。
2. 服务端返回 `CAPTCHA_REQUIRED` 后显示算术验证码。
3. 登录失败统一显示服务端安全说明。
4. `mustChangePassword=true` 时在登录页切换到改密表单，只允许改密或退出。
5. 不提供注册、忘记密码和自助救援入口。
6. 登录成功进入 `/overview` 或原 redirect。

### 3.2 问项目

页面顶部显示当前仓库、准备状态和问答模型；主体为左侧历史会话、右侧当前多轮对话。每轮回答下方内联展示引用证据与检索诊断。

对话区：

- 当前会话按轮次展示问题和回答，选中某轮回答时右侧同步展示该轮证据。
- 历史记录按当前账号和仓库持久化，在左侧列表支持恢复、重命名和删除。
- 输入框支持 Ctrl/Cmd+Enter 或按钮发送，busy 时禁止重复发送。
- “新问题”只重置当前页面，不提前创建空记录。
- 当前请求为一次性 JSON，不显示 Token 流式动画和停止按钮。

回答内证据轨道：

- 显示证据总数和“知识与代码联合检索”。
- 证据区分“当前代码”和“团队知识”。
- 代码证据显示文件、行号、正文摘录、通道和分数。
- 支持“查看源码”“调用图谱”；知识证据支持“查看知识”。
- 知识引用可继续展示其关联代码。
- 可展开检索诊断，查看实际快照、向量模型、启用/不可用通道、召回数量、耗时和降级原因。

回答状态：

- `CITATION_COMPLETE`：所有已识别事实段都有合法引用，只表示引用覆盖完整。
- `CITATION_INCOMPLETE`：至少一个事实段缺少合法引用。
- `SUPPORTED`：仅用于兼容历史记录，页面显示为“历史引用格式已校验”。
- `DEGRADED`：使用 deterministic-local。
- `MODEL_OUTPUT_REJECTED`：模型回答被拦截并安全降级。
- `INSUFFICIENT`：证据不足，不调用模型。

当前支持多轮上下文；尚无证据篮、问题模式、建议追问、复制带引用 Markdown 和保存知识草稿。

### 3.3 知识治理

主区为白色容器、顶部标题搜索和“新建卡片”，下方卡片网格。

卡片列表：

- 展示标题、类型、发布状态、人工评审状态、来源版本状态、标签、修订和摘要。
- 支持查看、编辑和历史。
- 当前类型为业务规则、技术决策、接口约定、模块说明。

编辑对话框：

- 宽度 920px，桌面最大高度内滚动。
- 字段为标题、类型、Markdown、附件、关联代码和标签；保存始终产生草稿且未评审的新修订，不在编辑器内直接伪造发布/评审状态。
- Markdown 编辑器提供编写/预览。
- 附件通过文件选择上传，可插入 `knowledge-attachment://{id}`。
- 关联代码选择器支持按路径/符号查询 chunk、查看源码和移除引用。
- 保存新修订后刷新列表。

详情与历史：

- 详情安全渲染 Markdown，并列出附件与代码引用。
- 历史以时间线显示只读修订。
- “恢复为新草稿”先二次确认，再生成更高修订。

当前没有拖拽/粘贴上传、替代文本面板、异步扫描进度、离页未保存拦截和发布权限分层 UI。

### 3.4 代码与证据

桌面布局：左侧文件导航，中间文件预览，右侧按需显示检索结果或文件证据。

左侧：

- 从当前仓库已发布快照加载完整文件列表。
- 支持按文件名/路径检索。
- 文件按目录组织并高亮当前项。
- 可消费问答、知识和审查跳转带来的 path、startLine、endLine、symbol 和 relation。

中间：

- 顶部显示文件名、路径、语言、大小、行数、快照、分支和 commit。
- 源码按行显示并支持行号定位。
- Markdown 文件使用文档预览，不显示原始 Markdown 源码。
- BAT/CMD 注册 batch/DOS 高亮，并兼容后端 GB18030 解码。
- JSON、YAML、XML、SQL、Java、Vue、TypeScript 等使用对应或自动语法高亮。
- 未知文本类型按纯文本展示。

顶部混合检索：

- 调用 `/hybrid-search`，不是普通片段分页。
- 显示实际 Snapshot、向量能力、启用通道、不可用通道和降级原因。
- 搜索结果保留文件、符号、行号、内容哈希和通道，不把排序分数展示成概率。
- 前端再次排除旧 Snapshot 命中，并说明排除数量。

右侧文件证据：

- “关系”使用已发布 CodeGraph 的真实路径，展示 CLI 版本、Snapshot、覆盖状态和限制；路径节点可回到源码。
- “知识”只展示直接绑定该文件且当前账号可见的知识，保留修订、审核、发布、来源版本和绑定哈希。
- “审查”展示最近不可变审查对该文件的变更、符号、规则、测试、审批和未知项引用，并区分当前/历史 Snapshot。
- 没有图谱、符号或直接知识时显示事实性空状态，不生成关系或规则。
- `/graph` 只用于旧链接重定向；主导航没有独立调用图谱入口。

失败状态：

- 无仓库：提示先选择仓库。
- 无已发布快照：提示先完成仓库接入/重扫。
- 文件超限、二进制、编码不可识别或路径非法：显示服务端错误。
- 移动端使用“目录 / 代码 / 结果 / 证据”四个面板切换，不同时挤压多栏。

### 3.5 变更审查

页面默认执行绑定当前已发布 Snapshot 的真实变更审查，不把需求描述或检索候选当作代码变化。顶部保留次级“需求影响预估”，并持续标注该模式没有读取真实 Git Diff。

本地 Git 输入：

- READ 账号可选择工作区、单 Commit 或 Commit Range；工作区审查前后核对 Digest，提交审查要求 Head 等于当前 Snapshot Commit。
- 可选任务描述只用于召回参考知识；可选模型只总结已有证据，不改变适用知识、测试、审批、失效知识和未知项。
- 最近审查从不可变历史读取；旧 Snapshot 结果保持只读，不能跳到当前源码冒充历史内容。

PR/MR 输入：

- 只对当前仓库 `canUpdate` 的维护者显示，支持 GitHub Pull Request 和 GitLab Merge Request 编号。
- 项目路径和令牌来自已登记仓库及绑定凭据；企业 API Base 可选，但必须为同主机 HTTPS 地址。
- 提供方 Head 与当前 Snapshot 不一致时停止，并引导先同步远端和完成准备；不使用本地其他版本生成替代结果。
- 同步成功后在同一证据主线展示 Task Review，并显示远端评论是创建还是更新。评论固定声明为提示性结果，不改变合并状态。

结果按“真实改动 → 适用知识 → 测试与审批 → 知识失效 → 未知项 → 可选模型建议”组织。每个确定性结论保留文件、符号、规则、Snapshot/Commit 和来源；部分 Patch、图谱缺失或识别降级必须显示限制，不输出风险概率。

CI 不再增加第二个审查页面。知识编辑器的“开发要求”区域提供两个结构化控件：逐行填写仓库相对禁止路径 Glob，以及是否要求发布知识新修订；详情页原样展示这两类规则。流水线通过不可变审查 ID 调用确定性检查接口，界面中的模型建议、检索候选、图谱单独推断和未知项没有“可阻断”视觉语义。

已完成审查在证据主线后显示“开发结果与人工反馈”：

- 先展示按时间倒序的不可变结果账本，包括具名报告人、最终 Commit、是否精确等于审查 Head、测试/审批/反馈数量和尚未回报的审查义务。
- 回报表单填写完整最终 Commit、实际完成摘要、已执行测试和审批；状态必须显式选择，不预填“通过”。
- 误报只能从本次审查已有对象中选择；漏报填写缺失对象类型、标识和人工依据。适用/失效知识可单独判断是否需要更新，留空表示不作判断。
- 页面持续说明反馈不会修改正式知识；保存后不可编辑，修正必须追加新的具名回报。历史审查也可以追加结果，不会跳转到当前源码冒充历史版本。

### 3.6 项目管理

页面包含摘要带、搜索/新增工具栏、仓库表格和分页。

接入仓库对话框：

- 来源 Tab：本地 Git、远程 Git、GitLab、ZIP。
- 本地 Git 填服务端路径。
- 远程 Git/GitLab 填 HTTPS Git 地址和可选分支，并可选择已有凭据。
- “管理凭据”弹窗支持新增、编辑、检测通用 Git HTTPS Token 与 GitLab PAT；接口不回显令牌明文。
- 私有仓库必须选择与目标主机匹配的凭据，不接受内嵌用户名或 Token。
- ZIP 使用文件选择。
- 导入期间禁用关闭和重复提交。

仓库表格：

- 展示仓库/OWNER、来源、分支/commit、当前快照、CodeGraph 状态和最近扫描。
- 操作由 capabilities 决定：准备/画像、编辑、重扫、内容索引、CodeGraph、成员与权限、删除。
- 重扫按 changed 返回“已发布最新版本”或“代码版本无变化”。
- CodeGraph 构建返回任务终态后提示成功/失败。
- 删除明确说明只删除平台数据和受管派生数据，不修改本地原目录。

“跨仓工程项目”对话框：

- 项目列表展示成员仓库数、契约数和双端证据是否仍为当前；右侧在同一工作台编辑项目身份、仓库服务名和契约，不要求跳转到多个页面拼关系。
- 新建项目至少选择两个可管理且已有当前 Snapshot 的仓库。服务名必须显式填写并在项目内唯一，页面不从仓库说明、README 或模型猜测。
- 每项契约登记提供方、消费方及双方当前内容索引中的证据路径；保存后展示契约 UUID 和“两端证据当前/证据待刷新”。
- 当前账号不能管理全部成员时项目保持只读；删除项目会提示先清理引用其仓库、服务或契约的知识 Scope。
- 该入口只配置进入 Task Review 的受治理跨仓事实，不提供任意多仓搜索，也不把同项目关系自动解释为知识适用。

“准备 / 画像”抽屉：

- 顶部准备轨道固定为代码快照、内容索引、向量索引、调用图谱四阶段，状态来自后端，不模拟百分比动画。
- MAINTAIN 可点击开始/继续准备；系统按 Snapshot、内容、向量、CodeGraph、知识失效五阶段自动推进，FAILED/DEGRADED 阶段在原位提供精确重试，不要求跨页面串联。
- 项目画像展示文件/大小、chunk/向量、知识、图节点/边、语言构成、一级目录和按约定文件名识别的关键入口。
- READ 账号可查看画像和跨页快捷入口；没有维护权限时不展示准备按钮。

治理对话框：

- 查看成员和候选账号。
- 授予 READ/MAINTAIN/MANAGE。
- 撤权和所有权转移携带 ownershipVersion。
- 转移可指定新仓库名和旧 OWNER 后续权限。

### 3.7 索引任务

页面使用一个白色主容器，顶部内层 Tab 与下方内容连续，不留独立标题空白。

Tab 1“索引任务”：

- 左侧任务表，右侧任务详情。
- 工具栏只保留成功/取消数量和刷新，不重复显示“索引任务”区块标题。
- 表格展示仓库、类型、状态、步骤、开始/结束/创建时间。
- 选择行更新右侧详情。
- RUNNING/QUEUED 支持取消；FAILED/CANCELED 支持重试。
- 页面轮询任务，离开组件后停止定时器。
- 底部分页使用统一 AppPagination。

Tab 2“当前向量索引”：

- 不在页面内部再次切换仓库，直接使用顶部全局仓库。
- 不显示“当前生效向量索引/仅展示当前快照”这类无行动价值的重复说明。
- 汇总展示当前快照、commit、代码 chunk、已向量化、缺失、知识数量、模型、维度和更新时间。
- 明细 Tab 为代码片段/知识卡片。
- 支持关键词、EMBEDDED/MISSING 和 chunk 类型筛选。
- 只展示仓库当前数据，不展示历史索引任务产物。

### 3.8 账号权限与审计日志

账号权限和审计日志是“系统管理”下两个独立入口，避免把实时账号操作与日志核对混在同一任务中。

账号权限：

- 搜索姓名/账号、分页、新增。
- 表格展示账号、角色、状态、仓库权限数、最近登录、IP 和版本。
- 操作包括编辑、启停、解锁、重置密码和审计定位。
- 编辑只修改显示名称和平台角色/启用状态，保存携带版本。
- 重置临时密码弹窗只在本次操作展示返回值。

审计日志：

- 进入独立 `/audit` 路由后加载。
- 展示事件、操作者、目标账号、仓库、结果、IP、requestId 和时间。
- 从账号操作跳转时按账号聚焦。

当前 OWNER 账号不能直接停用，页面需引导先在仓库治理中完成所有权转移；没有批量接管向导。

### 3.9 模型配置

页面当前是模型备案中心，不展示路径、备份、任务等未实现设置菜单。

顶部 Tab：问答模型、向量模型。

问答模型：

- 工具栏右侧提供“新增模型”。
- 模型卡展示协议、检测状态、名称、模型、地址、最近成功和输出上限。
- 操作统一位于卡片底部：检测、编辑。
- 保存或编辑后状态回到“待检测”；检测为 AVAILABLE 后可在知识问答页选择。
- 不提供全局“切换使用”“停用”或代码外发开关。

知识问答：

- 顶部命令栏提供问答模型下拉框，列出模型名称和模型标识。
- 默认选择第一个 AVAILABLE 且熔断器为 CLOSED 的模型，不可用项禁用。
- 未选择可用模型时禁用输入与发送，并提示管理员先备案、检测模型。

问答模型对话框：

- 备案名称、协议、地址、模型、API Key。
- 连接/请求超时、最大 Token、Temperature。
- “检测流式能力”只影响连接检测，不代表当前问答已流式输出。
- 保存按钮文案“保存备案”。

向量模型：

- 支持本地字符哈希和 OpenAI-compatible embedding。
- 本地哈希固定 64 维，页面标记为“字符相似度（非语义）”；外部 embedding 维度允许 1–4096，标记为“语义检索”。
- 外部模型填写地址、Key 和超时。
- 卡片展示检索能力、能力限制、运行方式、维度、数据外发和备案时间。
- 卡片提供“检测”按钮，展示检测成功的维度和耗时；切换前服务端再次执行 embedding 探针。

## 4. 统一交互规则

1. 全局仓库选择只影响项目总览、代码与证据、变更审查、问答、知识和当前向量索引；仓库管理列表独立加载。
2. 页面首次进入通过 API 加载，不使用静态 mock 数据。
3. 路由 KeepAlive 可能保留页面局部状态；切仓 watcher 必须清理旧仓库数据并重新请求。
4. capabilities 是仓库动作唯一权威；管理员路由同时由菜单和路由守卫限制。
5. 危险操作使用二次确认，说明影响对象和不可逆部分。
6. 成功提示只由用户动作完成触发；初始化、刷新和轮询不得弹成功 toast。
7. 空状态区分无仓库、无数据、依赖缺失和无权限。
8. API 错误当前按 `code/message/timestamp` 展示，不解析自由文本决定业务状态。
9. Markdown 必须经过 DOMPurify；源码通过文本节点和高亮库输出，不拼接未消毒 HTML。
10. 页面文案采用用户任务名称，不暴露 SQLite、Mapper、HNSW 等实现词，向量详情除外。

后续维护约束：

- 路由页应保持组合面，API 副作用进入 composable 或 feature 容器。
- Props 只读，子组件通过 typed emits 上报。
- 原始状态最小化，列表/标签/按钮可用性使用 computed。
- watcher 只处理切仓、路由参数、轮询等副作用，并清理计时器/请求。
- `SystemSettingsView` 和 `ChunksM0View` 是优先拆分对象，但拆分不改变当前产品行为。

## 7. 响应式与可访问性

1. 760px 以下导航横向化，页面改为单栏。
2. 表格和工作区页签允许横向滚动或紧凑显示。
3. 多栏问答、图谱和设置改为单栏；源码预览当前小屏隐藏右侧，是待改进项。
4. 交互控件提供 aria-label/title；页签使用 role=tablist/tab 与 aria-selected。
5. 键盘可关闭工作区页签；对话框使用 Element Plus 焦点管理。
6. 状态不能只依赖颜色，配合中文文字或图标。
7. Markdown 图片应提供 alt；当前附件插入默认从文件名生成 alt，尚无强制编辑面板。

## 8. 当前 UI 已知债务

1. `SystemSettingsView.vue` 和 `ChunksM0View.vue` 体积较大，未达到路由页仅编排的目标。
2. 路由静态导入导致主 JS 包较大，尚未按页面 lazy load。
3. 移动端源码详情隐藏，无法完成完整预览。
4. 问答已有多轮会话历史，但没有流式状态，不应显示停止生成或断线恢复控件。
5. 知识发布权限和附件扫描状态没有达到目标治理模型。
6. 工作区页签与部分知识卡片存在轻阴影，与旧版“无阴影”规范不一致；本文以当前实现为准。
7. 关键路由已有 Vitest 自动化约束；完整浏览器交互和视觉回归仍依赖人工检查。
