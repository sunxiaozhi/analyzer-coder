# 代码智库系统需求评审

版本：v0.1  
日期：2026-07-19  
评审范围：`01-requirements.md`、`02-tech-selection.md`、`03-design.md` 与当前代码骨架

> 历史评审记录：本文基于 v0.1 阶段材料，仅用于保留决策过程；当前权威需求以 `01-requirements.md` v1.0 为准，账号与仓库权限以 OWNER 模型为准。

## 1. 评审结论

产品方向合理，CodeGraph 结构事实与 RAG 语义检索融合有清晰价值，仓库管理也适合作为首个交付入口。但原 v0.1 的 MVP 范围过宽，若一次性交付，会同时承担 CodeGraph schema、代码切分、向量模型、混合排序、LLM 准确性和图可视化六类高不确定性，难以形成稳定验收。

本轮将需求拆为 M0、M1、M2。当前应先完成 M0 的“多来源仓库导入/同步 -> 索引任务 -> chunk 可追溯查询”闭环，再引入模型能力。

新增的本地 Git、远程 Git、GitLab 和 ZIP 四类来源是合理扩展，但不能共用一套模糊的“路径 + 分支”模型。Git 来源以 branch/commit 标识版本，ZIP 来源必须使用上传版本和内容摘要。ZIP 重新上传属于完整代码版本替换，不是增量合并；远程同步和 ZIP 覆盖都必须先构建临时快照，再原子切换，失败时保留当前可用代码与索引。

## 2. 合理且应保留的需求

1. CodeGraph 通过适配层接入，业务层不依赖原始 SQLite schema。
2. chunk 绑定仓库、commit、符号和行号，保证结果可追溯。
3. 语义检索与结构化查询分工，不让 LLM 推测调用关系。
4. 私有代码默认按敏感数据处理，模型 provider 可替换。
5. 索引作为后台任务执行，并记录阶段和失败原因。

## 3. 原需求中的主要问题

| 级别 | 问题 | 风险 | 处理 |
| --- | --- | --- | --- |
| 高 | MVP 同时包含完整 RAG、问答、调用图和增量索引 | 首期范围失控，任何一项不稳定都会阻断整体验收 | 拆分为 M0/M1/M2 |
| 高 | 本地路径导入与 Web/内网部署边界不清 | 浏览器无法替服务端选择客户端磁盘路径 | 默认单机部署；内网方案另行设计 |
| 高 | 未确定谁负责生成 CodeGraph 索引 | 读取已有 SQLite 与执行 CodeGraph CLI 是两套产品流程 | M0 默认只读已有索引 |
| 高 | 删除仓库含义不明确 | 可能误删源代码或 `.codegraph/` | 明确只删除平台数据 |
| 高 | 登录页与“MVP 不做用户权限”矛盾 | 前端有登录，后端无真实安全边界 | 默认登录页预留，真实鉴权待确认 |
| 中 | “可接受时间”“低置信度”不可验收 | 研发和验收口径不一致 | 增加性能与引用基线 |
| 中 | 增量索引缺少一致性策略 | 失败后可能留下半新半旧索引 | 采用版本化构建后原子切换 |
| 中 | 外部模型发送范围不明确 | 私有代码泄露和合规风险 | 默认关闭，显式配置并留元数据审计 |
| 中 | 支持语言没有优先级和质量标准 | 各语言图谱质量差异无法验收 | 推荐 Java/TypeScript/Python，并建立样例集 |
| 中 | 技术文档仍写 React | 与现有 Vue 3 工程冲突 | 统一为 Vue 3 + Element Plus |

## 4. 当前实现与需求的差距

当前代码已经具备仓库、索引任务、chunk 查询和 CodeGraph 端口的基础骨架，前端已有 Vue 3 + Element Plus 仓库管理页面。以下能力仍属于骨架或尚未形成真实闭环：

1. `SqliteCodeGraphAdapter` 的真实 schema 查询和兼容性测试。
2. Git 元数据、工作区脏状态和索引版本一致性。
3. 持久化数据库、任务恢复及索引版本切换。
4. embedding、向量数据库和混合排序。
5. LLM 问答、引用校验和低证据降级。
6. 真实登录鉴权与权限模型。
7. 远程 Git/GitLab 凭据加密、受管克隆目录和可靠同步任务。
8. ZIP 上传安全校验、版本覆盖、幂等处理和失败回滚。
9. CodeGraph CLI 的安装检测、兼容版本锁定、隔离执行、资源限制和产物发布。

因此，界面中不应把未实现能力展示为“已生成”或“已索引”；状态应来自后端真实任务数据。

## 5. 建议的近期开发顺序

1. 固化四类仓库来源的数据模型、唯一性规则和版本标识。
2. 实现本地 Git 登记、远程 Git/GitLab 受管克隆以及 ZIP 安全解压。
3. 实现同步/覆盖临时快照、原子切换、互斥锁和失败回滚。
4. 固定 CodeGraph CLI 兼容版本，完成环境预检、隔离执行和最小 schema 校验。
5. 将代码同步、CodeGraph 分析和知识索引纳入统一任务模型与仓库级互斥锁。
6. 完成 CodeGraph 与知识索引的版本化产物、原子发布和失败回滚。
7. 用四类固定样例仓库完成符号、调用边、chunk 路径和行号准确性验收。
8. 再选择 embedding provider 和持久化向量库，进入 M1。

## 6. 需要产品方确认的决策

CodeGraph 生成责任已明确为平台调用受支持版本 CLI。当前最优先确认两项：部署形态和是否启用真实登录；同时必须在开发前选定 CodeGraph CLI 的兼容版本、安装方式和单任务资源上限。其余待决策项及推荐默认值已集中记录在 `01-requirements.md` 第 10 节。
## 7. v1.1 开发者入门增强评审

当前页面已经覆盖仓库、任务、检索、问答、图分析和知识，但仍以独立工具为主，新开发者需要自己判断先后顺序并手工拼接架构、业务、运行和验证信息。因此 v1.1 新增 `ONB-01..18` 开发者入门工作台；该能力当前尚未实现，交付前不得显示可点击菜单或在功能指南中表述为已可用。

建议按价值和依赖分三批交付：

1. **M1-A 最小入门闭环**：仓库总览、目标角色、30–60 分钟路径、个人进度、环境预检、复制启动命令和一个人工维护的首个练习。
2. **M1-B 系统理解闭环**：架构地图、基础 API/数据目录、接口/任务到 Mapper/表/测试的场景链路，并复用 CodeGraph、检索和证据轨道。
3. **M2 持续学习闭环**：业务域地图、快照变化摘要、术语表、疑问转知识、路径版本迁移和脱敏学习摘要导出。

不建议首批实现团队排行、学习积分、自动改代码、自动执行任意仓库命令或无证据的“AI 架构结论”。这些功能会稀释快速入门目标，并引入不必要的安全与可信度风险。
## 8. QV1 快速价值版本决策

为了快速出成绩，先交付 QV1，不直接实施完整 ONB。QV1 的产品演示主线固定为：登录 → 选择/接入仓库 → 一键准备 → 查看项目画像 → 点击快捷问题获得引用 → 从检索跳调用影响 → 保存知识草稿 → 查看任务结果。

QV1 复用当前接口和数据，新增范围控制为一个聚合查询、一个幂等准备编排和若干前端跨页动作。验收以“首次可引用结果时间”和“用户能否独立走通三类理解动作”为准，不以新增页面数量衡量。
