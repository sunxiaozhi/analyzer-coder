# 项目—分支与独立共享知识实施方案

状态：R1–R5 已实施并通过回归验证。2026-09-15。

本文是后续开发依据，取代文档 17 中的独立窗口主入口、knowledge family/override、共享基线继承和分支覆盖优先级设计。文档 17 保留作历史与已实现底座说明。

## 1. 已确认的业务规则

一个项目对应一个 Git 仓库的逻辑身份，不因分支增加而复制项目。跨仓工程项目是另一个概念，不混入本次结构。

- 项目包含多个受管分支；不同分支可有不同代码与知识。
- 项目共享知识与分支专属知识是独立资产，各有 cardId、修订、编辑、审核与发布记录。
- 当前分支知识可见集合 = 项目共享知识 ∪ 本分支专属知识。
- 同标题、相似正文甚至完全相同正文的不同知识卡片仍同时展示，不自动合并、覆盖或相互更新。
- 问答引用标注“项目共享”或“分支专属 · 分支名”；若内容矛盾，分别呈现并指出差异，不自行选取优先版本。
- 共享知识的正文统一维护；其代码适用性验证仍按知识修订 × 分支 × 快照记录。
- 从专属转共享是明确的范围修改，会影响可见范围，不是 Git 合并的附带行为。

## 2. 数据与检索边界

| 数据 | 身份 / 可见范围 |
| --- | --- |
| 项目 | projectId；首阶段复用现有 repositoryId 和权限体系 |
| 分支 | projectId + branchId；名称不是永久身份 |
| 代码快照 | projectId + branchId + snapshotId + commitSha |
| 代码展示与向量检索 | 仅当前分支的选定快照 |
| 图谱 | 仅当前分支的选定快照产物 |
| 共享知识 | projectId + cardId + revision；所有受管分支可见 |
| 专属知识 | projectId + branchId + cardId + revision |
| Markdown 来源 | projectId + branchId + snapshotId + path；同路径跨分支不能覆盖 |
| 问答及引用 | 固定阅读上下文，保留来源、快照、知识修订 |

检索必须在召回阶段过滤范围，再排序与截断；不能先全项目召回 top-K 再移除其他分支。代码和知识分别限定范围，合并结果仍保留身份。去重最多消除同一知识修订的重复通道命中，不能消除不同卡片。

向量计算可在同项目、同内容摘要、同模型/维度/能力下复用，但成员关系与可见范围不可复用。无需每分支单建物理向量库。图谱或向量未就绪可明确降级，禁止借用默认分支产物。

## 3. 项目管理与创建流程

页面采用左侧项目列表、右侧选中项目的分支列表。左侧负责搜索、分页、选择和创建；右侧负责分支发现、添加、准备、状态与进入阅读。项目资料、凭据、授权、删除保留独立管理操作。

目标创建流程：新建项目元数据 → 配置代码来源/凭据 → 发现远程分支 → 添加需要管理的分支 → 按需拉取/准备 → 构建向量和图谱。添加受管分支不等于创建远程 Git 分支。

迁移期间保留现有导入流程，并标注“接入项目”；不能把导入按钮仅改名“新建项目”就宣称已完成创建与拉取分离。真正的项目草稿需要新的服务端生命周期、失败重试和权限校验。

每个分支分别显示准备、向量、图谱状态和各自产物快照；旧任务完成不能覆盖当前选择。ZIP 等非 Git 来源保留明确的单版本管理模式，不展示不可执行的远程分支操作。

## 4. 全站切换约定

所有业务页面使用同一个明确的项目/分支选择，并在顶部显示分支与提交。页面内一次阅读固定 snapshotId；新版本完成后由用户显式刷新。

- 切项目时清除旧分支及旧结果，目标项目的分支必须重新解析。
- 切分支时使在途请求失效，原结果不再展示；未准备/无权限/过期时阻止读取，不回退默认分支。
- 代码文件、检索、知识列表、图谱、问答和引用跳转必须携带同一上下文。
- 问答历史必须按分支归属筛选；恢复历史保留原快照，不能直接带到另一个分支续问。
- 浏览器页面之间不依赖服务端工作目录 checkout，多个用户可同时阅读不同分支。

## 5. 迁移与兼容

复用现有分支快照、后台准备/向量队列、CodeGraph、上下文与验证服务。保留既有知识 ID、修订、附件、引用，不按标题合并历史知识。

现有 ALL_BRANCHES 映射项目共享；单分支 SELECTED_BRANCHES 映射专属。既有多分支指定范围保留并标注兼容范围，在明确处理前不自动复制或扩大到所有分支。新建界面以共享/当前分支两种用途为主。

不改写已执行的 V1–V6。项目草稿、来源分支化等新增结构使用前向迁移；上线前验证旧数据数量、摘要、权限和引用完整性。

## 6. 开发阶段与验收

| 阶段 | 工作 | 验收 |
| --- | --- | --- |
| R1 项目—分支入口 | 左项目右分支联动；保留维护入口 | 切项目后没有上一项目分支/异步结果；搜索分页正常 |
| R2 生命周期与统一上下文 | 新建项目与拉取分离；全站分支切换及历史隔离 | 两项目各两分支可交替使用，不串数据；未准备不回退 |
| R3 独立知识 | 共享/专属独立维护，列表/检索/问答来源标识 | 同标题两条同时存在；编辑/归档其中一条不影响另一条 |
| R4 Markdown 与产物 | 来源分支身份、代码/向量/图谱全链路核对 | 同路径两分支内容不同且互不覆盖；所有引用可定位原版本 |
| R5 运维收尾 | 分支归档、引用保护清理、受控并发 | 不删除活动上下文、任务、问答与知识仍引用的产物 |

## 7. 本轮进度

- 已确认新知识规则，旧覆盖/继承方案作废。
- 已确认暂停时的问答试验补丁未落盘，无需迁移该试验代码。
- R1 已实现：项目管理页左侧搜索/分页/选择，右侧受管分支表和准备、向量、验证操作；切换项目重建分支组件，非 Git 项目保留单版本入口。原资料、凭据、权限与默认版本维护入口保留在“项目管理操作”。
- R2 已实现：项目资料草稿先持久化，代码来源可继续配置或失败重试；顶部全局分支选择固定到 contextId/snapshotId/commitSha，项目或分支切换立即清理旧结果。搜索、文件、图谱、问答、知识和 Markdown 统一使用该上下文，问答历史按分支隔离；未准备分支不回退默认版本。
- R3 已实现：新建知识可明确选择“项目共享”或“当前分支”，卡片及其修订仍是彼此独立资产。列表、检索证据与问答引用显示知识归属；提示词要求对矛盾内容分别呈现，不按标题或正文合并。
- R4 已实现：Markdown 来源身份升级为项目 + 分支 + 快照 + 路径，同路径跨分支不再覆盖；生成知识的来源链记录 sourceBranchId。代码证据、图谱查询与图构建均绑定当前分支快照。
- R5 已实现：分支支持逻辑归档/恢复，归档分支不再接受新上下文和新准备任务，历史上下文仍可解析。快照清理前会检查发布指针、活动上下文、各类任务、问答、知识验证及 Markdown 引用。分支准备工作器改为受控并发和分支级数据库锁，不同分支可并行。
- 兼容迁移已补齐：旧默认版本自动镜像到分支快照，后续新建或重扫仓库由触发器保持同步；旧问答、Markdown 和知识引用按可识别的默认分支回填。ZIP 在业务页保持单版本模式，不展示 Git 分支操作。
- 回归结果：后端 232 项测试通过（环境条件限定的 4 项跳过）；前端 30 个测试文件、109 项测试通过，生产构建通过。

界面实现采用 ProjectSelectionList（项目选择）、BranchListTable（分支选择）和已有 BranchWorkspace（分支操作）的组合。沿用应用字体、白底、蓝色选择标记、等宽提交号；层级来自项目与分支关系，不增加装饰性指标。
