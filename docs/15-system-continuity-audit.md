# 系统功能连贯性审计与优化记录

> 历史审计记录：后续已进一步删除变更审查，当前范围以 `01-requirements.md` 为准。

日期：2026-09-08。范围：当前工作区源码、现有功能说明、前端回归测试与构建。结论中的“已修复”指本次代码与测试；“保留”表示产品职责合理，不代表已完成外部服务或生产验收。

## 1. 总体判断

系统的主流程合理：接入仓库 → 发布快照并准备索引 → 检索源码 → 查看关系和知识证据 → 问答或预估影响 → 审查真实改动 → 回报测试/审批 → 人工维护知识。

主要问题出现在页面之间的版本和状态衔接。原实现会在部分入口丢失证据快照，把知识基线当作变更源码版本，以及让旧请求覆盖新选择。此类问题会让用户看到“正确路径上的错误版本”，优先级高于增加图表或菜单。

变更审查与系统审计应保留为两种功能：前者回答“这次代码变化影响什么、需做什么”；后者回答“谁进行了哪些账号或权限操作”。不建议混成一个大列表。

| F13 | 影响预估慢响应跨仓覆盖，确认/排除残留 | 切仓、快照变更和离开页面时使旧分析失效并清理候选状态 | 切走再切回回归 |

| F15 | 历史知识绑定允许用旧行号打开当前源码 | 旧绑定按钮禁用，用户可继续打开知识卡核对原有证据 | 类型与组件回归 |

本次组件职责：代码页协调文件选择与导航；文件证据面板展示关系、知识和审查；变更页协调新建/历史请求；独立 reviewSourceVersion 函数负责版本一致性判断，证据组件通过 props 和 emits 传递来源。没有把版本校验藏在显示文本中。

## 3. 功能逐项评估

以下以当前已交付的操作项为单位，入口和详细使用方法见 [功能与数据流](13-system-usage-map.md)。

| 功能 | 应衔接的前后步骤 | 评估及处理 |
| --- | --- | --- |
| 登录、首次改密、会话恢复 | 登录成功后恢复有权限的工作区 | 保留；相关既有前端回归本次重跑 |
| 账号创建、编辑、停用、解锁、重置密码 | 管理操作后影响登录和仓库可见性 | 保留；不应混入代码变更审查 |
| 当前仓库选择 | 所有代码、问答、知识和审查使用同一范围 | 必要；本次修复代码、关系、预估和审查的异步串扰 |
| 本地 Git 接入 | 服务器路径 → 导入 → 快照 | 保留；应始终解释为后端服务器路径 |
| 远程 Git、GitLab 接入 | 凭据/来源 → 拉取 → 快照 | 保留；实际远端联调未在本次执行 |
| ZIP 接入 | 上传 → 快照 → 阅读/问答 | 保留；移除其进入 Git 审查表单的无效路径 |
| 仓库更新、重新扫描 | 新版本 → 重新准备 → 新证据 | 保留；旧证据应保持原版本，不能默默替换 |
| 凭据绑定、成员权限、所有权治理 | 仓库维护 → 后续读写能力 | 保留；不因前端入口优化放宽后端权限 |
| 项目总览、准备、阶段重试 | 快照 → 内容 → 向量/图谱 → 漂移检查 | 保留；已有准备隔离回归通过；阶段成功语义仍需区分 |
| 文件目录与代码预览 | 选文件 → 对应快照原文与行号 | 核心；已修复缓存竞态、失效路径和快照混用 |
| 关键词检索 | 当前内容索引 → 片段 → 原文 | 核心；已修复旧请求覆盖 |
| 字符向量与语义向量 | 当前模型索引 → 有来源的候选 | 保留；字符相似度不能包装为语义理解 |
| 检索降级诊断 | 不可用通道 → 解释当前结果边界 | 保留；需继续完善后台持久化的失败原因 |
| 关系查询、深度、路径 | 明确符号 + 同版本图谱 → 真实静态边 | 保留；修正方向和覆盖文案，不宣称运行时全链路 |
| 图谱构建、刷新 | 内容已准备 → 后台构建 → 刷新查询 | 补齐刷新和权限入口；真实 CLI 全链路仍需验收 |
| 路径节点打开源码 | 节点位置 → 当前同版本文件 | 保留；图谱响应先过快照校验 |
| 文件关联知识 | 直接绑定 → 知识详情 → 来源版本 | 保留；旧绑定不能套用当前行号 |
| 文件关联审查 | 文件引用 → 对应历史审查 | 原入口中断，已补齐点击跳转 |
| 本地证据问答 | 内容索引 → 摘录、引用 → 保存会话 | 核心；无需强迫配置问答模型 |
| 模型问答、模型选择 | 检索证据 → 可选生成 → 引用核验 | 保留；真实模型联调未在本次执行 |
| 问答历史、重命名、删除 | 保存回答 → 恢复原引用 | 保留；历史源码跳转增加快照保护 |
| 从引用打开知识/关系 | 引用身份 → 对应卡片/符号 | 保留；关系和源码不能使用其他版本代替 |
| 需求影响预估 | 改代码前描述需求 → 候选 → 人工核验 | 合理，但属于调查线索；已修复切仓污染 |
| 候选确认、排除 | 核验 → 复制范围或继续问答 | 当前只在页面内；明确提示，不当作审查结论持久化 |
| 复制影响范围、继续问答 | 调查证据 → 人工计划 | 保留；继续问答不等于已执行代码修改 |
| 工作区审查 | 实际未提交差异 → 版本摘要 → 规则/义务 | 保留；摘要不一致时不能打开当前快照冒充工作区 |
| 单提交、提交范围审查 | 明确 Base/Head → 文件和符号变化 | 保留；源码跳转必须核对真实 Commit |
| PR/MR 审查与评论 | 拉取补丁 → 审查 → 外部评论 | 有价值，但包含外部写入；本次没有调用真实评论接口 |
| 变更事实、符号详情 | Git 事实 → 可追溯的源侧与位置 | 已保留 NEW/OLD 来源字段；完整历史 Diff 浏览仍缺少闭环 |
| 确定性适用知识与参考候选 | 已审核范围命中 / 相似度候选 → 分开展示 | 保留，不能合并为“AI 已确认规则” |
| 测试要求、审批要求 | 规则命中 → 待执行义务 → 具名回报 | 保留；无回报不能显示已通过 |
| 未知项、陈旧知识 | 证据不足 → 人工补证据/维护 | 保留；不能为减少告警而隐藏 |
| 模型引用总结 | 既有审查证据 → 可选建议 | 保留；不改变确定性门禁结果 |
| 审查历史和结果回报 | 不可变审查 → 对应 Commit 的追加回报 | 保留；已修复新旧详情混淆 |
| 知识新建、编辑、分类、标签 | 人工输入 → 新修订草稿 | 保留；正文内容和适用范围职责不同 |
| 来源绑定、适用范围、负责人、执行级别 | 证据与人工规则 → 可验证义务 | 保留；绑定文件不自动证明全仓适用 |
| 知识测试/审批/CI 约束 | 明确约束 → 审查匹配 → 外部执行结果 | 保留；平台不自动执行测试或审批 |
| 附件上传、下载、修订关联 | 附件可访问 → 人工引用 | 保留；不应暗示 PDF/Office 已自动全文入库 |
| 评审、发布、撤回 | 人工审核 → 可检索/参与规则 | 保留；发布成功与向量补建成功仍需分开报告 |
| 修订历史、恢复草稿 | 历史内容 → 新草稿 → 再审核 | 保留；不覆盖原历史事实 |
| Markdown 发现、生成、更新 | 快照文档 → 知识草稿 → 审核发布 | 保留；无需新增独立“自动知识结论”功能 |
| 来源漂移、确认有效/失效 | 指纹变化 → 人工核验 → 记录原因 | 保留；与代码变更审查通过证据关联，而非混成一页 |
| 跨仓项目、服务成员 | 明确服务身份 → 跨仓范围 | 进阶能力；应在单仓链路可靠后使用 |
| 契约添加、更新、过期 | 双端真实文件指纹 → 关联状态 | 保留但需校准认知：指纹一致不等于接口兼容或实际调用 |
| 移除成员/契约/项目 | 检查知识引用 → 解除关系 | 保留引用完整性约束 |
| 索引任务、步骤、取消、重试 | 后台状态 → 诊断与恢复 | 保留；崩溃恢复需故障注入验收 |
| 向量明细、模型切换与补建 | 当前模型空间 → 缺失记录 → 重试 | 保留；代码覆盖率不代表知识覆盖率 |
| 问答/向量模型配置和检测 | 配置 → 连通性 → 可用状态 | 保留；检测成功不等于业务请求全部成功 |
| 系统审计日志及筛选 | 已保存操作事件 → 人员和时间追溯 | 保留；不是代码 Diff，也不是所有业务请求的全量追踪 |
| MCP 接入和证据查询 | Agent 会话 → 同权限 HTTP → 来源证据 | 保留；现有用户修改的 MCP 指南未被覆盖 |
| Agent 结果/误报漏报回报 | 具名反馈 → 人工知识维护 | 保留；不宣称自动学习或自动发布 |
| Webhook 与 CI 门禁 | 签名/已完成审查 → 外部测试审批 → 确定性检查 | 进阶能力；外部集成需要独立端到端验收 |

## 4. 仍不合理或尚未闭环的设计

| 优先级 | 问题 | 建议落点与完成标准 |
| --- | --- | --- |
| P1 | 审查可说明历史改动，但不能完整浏览该版本的文件和前后 Diff | 为仓库授权范围内的固定 Commit/保留快照增加版本化源码读取与差异展示；删除文件走 OLD、新增文件走 NEW；不能靠跳当前文件完成 |
| P1 | 来源无法定位时，目前仍以阻止错误跳转为主 | 在证据详情直接展示不可打开的具体原因，并提供已保存片段或原始变更来源；历史源码存储策略需先确定 |
| P1 | 向量异常在 prepareRepositoryEmbeddings / prepareKnowledgeEmbeddingsSafely 中被吞掉 | 持久化模型、时间、失败阶段及可操作错误；发布成功时单独返回补建状态 |
| P1 | 准备流程的 vectorsReady 主要检查代码 missingChunks | 将知识与代码覆盖分别展示，明确哪些缺失阻塞哪类功能；不要把一个 100% 用于所有向量 |
| P1 | 内容索引完成后继续图谱入队失败主要记录日志 | 使用可恢复的持久化继续任务，并做崩溃、超时、重启故障注入 |
| P1 | 外部 CodeGraph、模型和 PR/MR 评论缺少本轮真实环境验收 | 在隔离仓库跑符号路径、模型失败降级及 PR Head 变化场景；本次没有向外部发布评论 |
| P1 | 只保留合并 V1 的旧库升级路径 | 用备份副本演练迁移，不能删除业务库或强制 repair 掩盖结构差异 |
| P2 | 影响预估确认/排除离开页面丢失 | 如果产品要求长期调查，新增按账号、仓库、快照保存的调查草稿；新快照到来时重新核验，不直接沿用旧确认 |
| P2 | 路由主要依赖当前仓库偏好，链接跨会话分享不够自包含 | 统一带 repositoryId、snapshotId、path/reviewId 的上下文路由，并在加载前检查访问权 |
| P2 | 首屏仍包含多个较重页面，构建有大包提示 | 独立性能迭代：按路由加载、测量首屏资源和交互时间；不以简单调高告警阈值充当优化 |
| P2 | 跨仓契约、附件、结果反馈易被理解成更强自动化能力 | 按真实能力展示“人工关联/附件存储/追加回报”，等实际兼容性验证、文档解析、审批采集接通后再扩展 |

不建议删除变更审查、关系查询或未知项来“简化系统”。应消除错误入口、补齐证据版本与下一步操作，降低用户误判。
