# 功能使用指南

## 1. 登录、账号与权限

使用初始管理员登录后先按提示修改密码。超级管理员在“账号管理”中创建、启停、解锁账号和重置临时密码；账号管理、全局审计、系统配置和备份恢复不向普通账号展示。会话使用 HttpOnly Cookie，修改请求校验 CSRF；退出、改密、停用和恢复会撤销相关会话。

所有启用账号都能创建仓库。仓库名称在同一 OWNER 下大小写不敏感唯一，不同 OWNER 可以同名；页面使用 OWNER 和来源类型消歧。创建成功后，创建者自动成为唯一 OWNER：

- READ：查看、检索、问答、图和已发布知识。
- MAINTAIN：READ + 同步、分析、索引和维护草稿。
- MANAGE：MAINTAIN + 非敏感配置和知识发布，不能分配权限。
- OWNER：MANAGE + 成员授权、专用凭据、所有权转移和删除。

OWNER 在仓库详情的“成员与权限”中给启用账号授予 READ、MAINTAIN 或 MANAGE；超级管理员也可操作全部仓库。普通 MANAGE 账号不能继续转授权限。

## 2. 建立和管理仓库

所有启用账号都能进入“仓库管理”并点击“接入仓库”。普通账号只看到本人创建或被授权的仓库，超级管理员看到全部：

- 本地 Git：填写白名单内的服务端绝对路径。平台只读取 Git 元数据并创建冻结快照，不修改原工作区。
- 远程 Git：填写允许的 HTTP(S) Git 地址和分支。私有仓库当前使用后端运行账号的 Git Credential Manager/系统凭据。
- GitLab：填写服务、项目、分支和一次性 Token，遵循相同网络边界。
- ZIP：上传 ZIP；平台限制文件数、大小、压缩比和路径并形成可追踪快照。

普通账号默认最多拥有 20 个非删除仓库、同时准备 2 个仓库、占用 20 GiB 受管数据。创建失败不会发布仓库、OWNER 或快照，也不占用配额。

仓库行和详情根据服务端 capabilities 显示操作：MAINTAIN 可同步和索引，MANAGE 可修改普通配置，只有 OWNER 和超级管理员可管理成员、专用凭据、转移所有权和删除。

转移所有权时选择启用账号和旧 OWNER 后续权限，默认不保留权限；目标已有同名仓库时还必须指定新名称，重命名和转移原子完成。转移后旧 OWNER 立即失去治理入口。超级管理员停用 OWNER 账号时，必须先把其全部仓库原子转移给指定启用账号并解决每个名称冲突，任何冲突都会取消整次停用。

## 3. 内容索引与任务

在仓库行点击“创建索引”。任务中心展示排队、运行、成功、失败、取消和重试状态。索引从冻结快照读取文件，跳过 `.env`、私钥、证书和常见凭据文件，生成带文件、符号、行号和内容摘要的 chunk，并写入 PostgreSQL。

任务失败时可在任务中心重试；运行中的任务可取消。服务重启后遗留的非终态任务不会永久卡在运行中。

## 4. Chunk 浏览、混合检索和问答

“代码检索”支持按文件、符号和正文关键词浏览 chunk。混合检索将关键词得分与 pgvector 的 64 维本地确定性向量合并，结果绑定当前索引版本。

“代码问答”选择单个仓库后输入问题。当前默认 provider 为 `deterministic-local`：不会向外部发送代码，回答列出相关文件、符号和行号，并在右侧展示可复核引用。没有证据时明确返回“未找到足够证据”。

## 5. CodeGraph 与影响分析

进入“图分析”，选择仓库并点击“构建/重新构建图谱”。后端把冻结快照复制到独立分析目录，运行 CodeGraph CLI，校验 `.codegraph` 后原子发布产物记录；源码快照保持不变。

输入符号名和深度后执行影响分析。页面展示受影响符号、源码位置、关系边、节点/边统计、LOW/MEDIUM/HIGH 风险以及静态分析限制。切换仓库快照后需要为新快照重新构建图谱，旧产物不会冒充当前结果。

## 6. 知识卡片

“知识沉淀”可创建业务规则、技术决策、接口约定和模块说明，状态支持草稿、发布、需要复核和归档。每次编辑都会生成新的修订，不覆盖历史。

点击“历史”可查看所有版本；“恢复为新草稿”会复制所选历史内容并生成更高版本号，原历史完整保留。普通读取只返回已发布卡片，维护权限用于创建、编辑和恢复。

## 7. 系统设置与备份清单

管理员可配置最大检索结果、排除规则、本地模型标识和备份保留天数。敏感设置在读取接口中以掩码返回。

“立即创建备份”当前生成数据库内的一致性清单和 SHA-256 摘要，覆盖账号投影、仓库投影、设置和知识卡片；“校验并恢复”校验清单完整性并使现有登录会话失效。它不是 PostgreSQL 物理备份，生产环境仍需对数据库卷和受管数据目录配置独立加密备份。

## 8. 优先规划：QV1 快速开始（尚未交付）

QV1 将首先提供项目理解首页：选择仓库后查看四项就绪状态，通过“一键准备”补齐 CodeGraph 和内容索引，查看项目画像，并使用“系统做什么、如何启动、核心模块、调用链、测试入口”五个快捷动作。检索、问答、图分析和知识草稿将支持携带上下文互相跳转。

QV1 的代码问答将同步增加历史会话、多轮追问、问题模式、指定证据提问、结构化回答、建议追问、引用跳转、复制带引用答案和保存知识草稿。QV1 完成后再逐步交付完整的角色化学习路径、私人进度、业务域地图和变化摘要。

## 9. 规划功能：开发者快速入门（v1.1，尚未交付）

v1.1 计划新增“开发者入门”。交付后，用户选择一个已授权仓库和目标角色，系统先检查代码快照、CodeGraph、内容索引及本地运行依赖，然后生成可继续的学习路径：

1. 阅读系统定位、技术栈、架构层和业务域总览。
2. 按操作系统完成环境预检并复制启动命令，确认后端、前端、PostgreSQL/pgvector 和 CodeGraph 状态。
3. 选择一个接口、任务或事件，沿入口、应用服务、领域逻辑、MyBatis Mapper、数据表、外部依赖和测试查看完整场景链路。
4. 使用检索或问答回答路径中的验证问题，并把文件、符号和行号作为完成证据。
5. 完成仓库维护者发布的首个练习，运行验收命令并记录结果。
6. 在完成页查看收藏、疑问、阻塞项和下一步，并导出不含源码正文和敏感配置的 Markdown 摘要。

个人笔记和进度只对本人可见；路径、地图和链路绑定具体快照。代码更新后旧进度保留，变化摘要会提示需要重新阅读的模块。平台不会自动执行仓库任意脚本，也不会替用户创建分支、修改或提交代码。
## 10. 当前外部能力边界

- 私有远程仓库当前依赖运行账户的 Git Credential Manager/系统凭据，不提供平台内明文凭据输入或回显。
- 默认问答完全本地、确定性且可引用；尚未启用外部 LLM。设置页中的外部开关默认关闭。
- CodeGraph CLI 是独立组件；未安装时内容索引、检索、问答和知识卡片仍可使用，图分析不可用。
- 当前代码已启用 OWNER 自助建仓、成员授权、单仓所有权转移、服务端 capabilities 与同 OWNER 名称唯一约束。仓库删除先立即隐藏并写墓碑，再由清理 Worker 幂等删除统一受管目录与派生数据；本地 Git 原目录不会被删除。
