# 最小产品需求：代码与知识联合检索

## 目标

系统帮助开发者在一个入口内找到相关源码与项目知识，并验证每条结果来自哪个仓库快照、文件位置或知识卡。

## 用户问题

- 我只知道业务术语，不知道代码文件名。
- 代码和文档分散，查到实现后仍不知道相关约束。
- AI 给出的答案缺少可回查来源。

## 必须实现

1. 接入 Git 或 ZIP 仓库，保存可标识的当前快照。
2. 将源码切分为带路径、符号和行号的片段并建立索引。
3. 创建、编辑、发布知识卡，并绑定路径或符号范围。
4. 提供单一联合检索 API，同时返回代码与已发布知识。
5. 结果明确标注类型、相关度与来源，点击后可回到原文。
6. 所有仓库读取按账户 READ 权限校验。
7. 向 AI 客户端提供只读 `search_project` MCP 工具，复用同一检索服务。

## 可选增强

- 向量语义检索；
- 基于证据的问答与会话历史；
- CodeGraph 关系浏览；
- 知识来源失效提示。

这些能力失败时，不应阻断关键词检索和来源查看。

## 不在范围内

变更审查、需求影响预估、PR/MR Webhook、审查 CI、测试或审批判定、任务结果回报，以及任何基于检索结果自动阻断发布的能力。

## 验收标准

准备一个真实小仓库和至少两条关联知识。输入一个业务问题后：

- 前 10 条结果中出现目标代码；
- 同一列表出现相关知识；
- 代码结果能打开正确文件与行号；
- 知识结果能打开正确卡片并显示关联范围；
- 无权限账户无法读取仓库结果；
- 网页与 MCP 对同一查询使用相同的后端检索逻辑。
