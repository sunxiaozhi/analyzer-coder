# 代码智库系统需求文档

版本：v1.1
日期：2026-07-22
状态：开发者入门增强闭环版

## 1. 文档目标

本文是产品、开发、测试和部署的共同验收基线。每项功能均按“权限与入口、输入、处理、产物、异常恢复、删除保留、验收”描述；未满足任一环节，不视为功能完成。

系统以代码快照为事实边界，将 PostgreSQL/pgvector 的内容与向量检索、CodeGraph 的结构事实、带引用问答和人工知识卡片组合为可追溯的代码智库。

## 2. 范围与产品原则

### 2.1 交付范围

1. M0：账号、仓库、快照、统一任务、CodeGraph、内容索引、系统设置、备份恢复。
2. QV1：快速开始首页、一键准备、项目画像、五个快捷理解动作和现有页面联动优化。
3. M1：向量索引、混合检索、单仓代码问答、开发者入门总览、学习路径、环境预检和基础场景链路。
4. M2：增量索引、多仓检索、调用图、影响分析、知识卡片、业务域地图、快照变化摘要和团队入门沉淀。

### 2.2 不在范围

1. 自动修改代码、提交分支或创建 PR。
2. 替代 IDE、代码托管平台或 CI/CD。
3. SaaS 多租户、计费、企业 SSO 和组织架构。
4. 训练私有代码大模型。
5. 自动执行仓库中的代码、构建脚本、Git hooks 或测试。

### 2.3 强制原则

1. 所有查询结果绑定仓库、快照和产物版本，不混用不同版本。
2. 新产物校验成功后原子发布；失败或取消时旧产物继续可用。
3. 结构关系只能来自 CodeGraph，LLM 和文本相似度不得生成结构事实。
4. 无证据时明确返回证据不足，不生成确定性结论。
5. 权限在列表、详情、任务、查询、历史和引用跳转各层重复校验。
6. 凭据、密码、会话、验证码答案和模型密钥不得明文存储、回显或写入日志。
7. 删除、恢复和权限回收必须立即停止新访问，异步清理失败不得恢复可见性。

## 3. 角色、权限与状态

### 3.1 角色与仓库权限

| 主体 | 平台能力 | 仓库能力 |
| --- | --- | --- |
| 超级管理员 | 账号、审计、全局设置、共享凭据、备份恢复 | 可管理全部仓库并在必要时接管所有权 |
| 普通账号 | 登录、个人改密、创建仓库、访问本人数据 | 查看自己创建或被授权的仓库 |
| READ | 无管理能力 | 查看仓库、任务、产物、检索、问答、图和已发布知识 |
| MAINTAIN | 无授权能力 | READ + 同步、重新扫描、分析、索引和维护草稿 |
| MANAGE | 无授权和所有权转移能力 | MAINTAIN + 编辑非敏感仓库配置、发布知识 |
| OWNER | 仓库唯一所有者；默认是创建者 | MANAGE + 仓库授权、专用凭据、所有权转移和删除 |

每个仓库必须且只能有一个 OWNER。所有启用账号均可创建仓库，创建成功后自动成为 OWNER；OWNER 和超级管理员可以给其他启用账号授予、调整或回收 READ、MAINTAIN、MANAGE，但普通 MANAGE 账号不能继续转授权限。OWNER 可经二次确认把所有权转移给另一启用账号；超级管理员可在 OWNER 停用或离职时强制转移。账号停用时授权和所有者操作权立即失效但记录保留；权限回收后，列表、正在查看的正文、后续流式输出和历史引用立即不可访问。

### 3.2 统一状态

| 对象 | 状态 |
| --- | --- |
| 账号 | `PASSWORD_CHANGE_REQUIRED`、`ENABLED`、`LOCKED`、`DISABLED` |
| 仓库 | `PREPARING`、`READY`、`AUTH_ERROR`、`DELETING`、`DELETED`、`FAILED` |
| 快照 | `PREPARING`、`PUBLISHED`、`RETIRED`、`DELETED` |
| 产物 | `ABSENT`、`BUILDING`、`PUBLISHED`、`STALE`、`FAILED`、`DELETING` |
| 任务 | `QUEUED`、`RUNNING`、`CANCEL_REQUESTED`、`SUCCEEDED`、`FAILED`、`CANCELED` |
| 知识卡片 | `DRAFT`、`PUBLISHED`、`NEEDS_REVIEW`、`ARCHIVED` |
| 备份 | `CREATING`、`READY`、`RESTORING`、`FAILED`、`EXPIRED` |

状态只能按定义路径迁移。任何“当前”指针只指向已发布对象。

## 4. 数据与存储契约

### 4.1 业务存储

1. PostgreSQL 保存账号、权限、仓库、版本、任务、审计、配置、问答、引用、知识卡片和备份清单。
2. pgvector 与 PostgreSQL 同库启用；Flyway 默认开启并负责全部 schema 迁移。
3. 正式运行不得以内存存储替代业务数据库。

### 4.2 受管数据目录

生产部署必须配置 `APP_MANAGED_DATA_ROOT`；开发默认值为 `${java.io.tmpdir}/analyzer-coder`。目录固定如下：

```text
APP_MANAGED_DATA_ROOT/
├── repositories/{repositoryId}/
│   ├── working-copy/                         # 远程 Git、GitLab、ZIP 的受管工作副本；本地 Git 可不存在
│   ├── snapshots/{snapshotId}/content/       # 已发布、只读的代码快照
│   └── artifacts/
│       ├── codegraph/{snapshotId}/{artifactId}/project/.codegraph/
│       └── indexes/{snapshotId}/{indexId}/   # 仅文件型索引产物；业务记录和向量仍在 PostgreSQL/pgvector
├── staging/{operationId}/                    # 未发布临时数据，不属于任何可查询仓库版本
└── backups/{backupId}/
```

1. 每个仓库的受管工作副本、快照和文件型派生产物必须统一放在 `repositories/{repositoryId}` 下，禁止再使用仓库目录之外的快照或 CodeGraph 业务路径。本地 Git 原目录不进入受管目录，平台只保存规范化来源路径，并把用于分析的只读快照复制到该仓库统一目录。
2. 远程 Git、GitLab 和 ZIP 的工作副本进入 `repositories`；用户不能直接编辑。
3. 上传、克隆、解压和分析先进入 `staging`，校验后原子移动到目标目录。
4. 快照只读；索引和 CodeGraph 只能读取已发布快照。
5. 启动时校验根目录绝对路径、可写性、剩余空间及目录互不嵌套；生产环境禁止落入源码目录或系统临时目录。
6. 创建失败清理 staging；删除仓库清理受管副本、快照和产物，但不触碰本地 Git 原目录。
7. 容器部署必须显式挂载受管根目录和允许导入的本地目录。

### 4.3 快照与版本绑定

快照（CodeSnapshot）是仓库在某个确定来源版本上的完整、只读代码副本，包含 `snapshotId`、来源版本、文件清单和内容摘要。它不是工作副本、Git 分支、CodeGraph 产物或备份：工作副本可被下一次同步更新；快照发布后不可修改；CodeGraph 和索引是基于快照生成的派生产物；备份用于灾难恢复。

创建或更新仓库时先在 staging 准备代码，校验完成后生成新快照并原子切换 `currentSnapshotId`。CodeGraph、内容索引、检索、问答、调用图、知识引用和源码跳转只能读取明确的已发布快照。新版本失败时继续使用旧快照；旧快照按保留策略存在，用于历史回答和引用复现。

所有派生产物至少保存：`repositoryId`、`snapshotId`、输入摘要、工具/模型版本、配置版本、创建时间和状态。新快照发布后，旧 CodeGraph、内容索引、向量索引和知识适用性标记为 `STALE`，但在新产物发布前允许按旧版本查看。

### 4.4 OWNER 持久化与升级

1. `repositories.owner_account_id` 非空并引用账号；`repositories.ownership_version` 用于所有权和授权操作的乐观锁。
2. OWNER 不写入普通授权表。授权表只保存 `READ`、`MAINTAIN`、`MANAGE`，并对 `repository_id + account_id` 建立唯一约束。
3. 仓库接口统一返回当前账号的 `relationship` 和服务端计算的 `capabilities`，前端不得自行拼装更高权限。
4. 从旧版本升级时必须通过 `APP_REPOSITORY_MIGRATION_OWNER` 指定一个启用的超级管理员作为现有仓库 OWNER；目标无效或存在无法归属的数据时 Flyway 后置校验失败并阻止业务开放。
5. 升级只补所有权，不改变原授权；迁移结果记录仓库数量、接管账号和关联请求 ID，不记录仓库源码或凭据。

## 5. 功能需求

### 5.1 登录、账号、授权与审计（M0）

#### 5.1.1 功能点

1. 空数据库启动时从环境变量创建唯一初始超级管理员；初始密码不写日志，首次登录强制改密。
2. 登录只返回统一失败信息。连续失败达到阈值后启用持久化验证码，达到锁定阈值后临时锁定。
3. 密码长度 8 至 64 位，至少包含三类字符，不得等于用户名或命中弱密码表；PBKDF2-SHA256 使用独立随机盐。
4. 会话使用服务端随机凭据和 HttpOnly Cookie；写请求校验 CSRF；空闲与绝对超时均生效。
5. 改密、重置密码、停用账号和安全恢复后撤销旧会话。
6. 超级管理员可新增、编辑、启停、解锁和重置账号；仓库 OWNER 与超级管理员可维护该仓库授权；不得停用或降级最后一个启用的超级管理员。停用拥有仓库的账号前必须完成所有权转移，或在同一操作中把全部仓库原子转移给指定启用账号；任一仓库转移失败则账号保持启用。
7. 临时密码仅显示一次、24 小时有效、首次使用后必须更改。
8. 审计记录登录、退出、改密、账号、授权、所有权、凭据、配置、备份和删除操作；支持时间、操作者、目标、仓库、事件和结果筛选。超级管理员查看全局审计；OWNER 只能查看本人仓库的授权、所有权和凭据操作历史，且不返回平台安全事件或敏感详情。
9. 普通账号只能查看自己的最近登录信息；安全审计仅超级管理员可访问。
10. 唯一管理员遗忘密码时，只允许本机救援流程使用部署密钥生成一次性令牌，并记录审计。

#### 5.1.2 闭环

- 成功：身份校验 → 创建/更新主体 → 撤销必要会话 → 写审计 → 返回脱敏结果。
- 失败：事务回滚；不改变原账号、授权或会话；错误不泄露账号是否存在。
- 删除：M0 不物理删除账号，使用停用保留历史主体。

验收：`AUTH-01..09`、`AM-01..07`、`AUD-01..02`、`RP-01..18`。新增 `AM-07` 验证停用 OWNER 必须同步完成全部所有权转移；`AUD-02` 验证 OWNER 只能查看仓库级治理记录；`RP-08` 验证创建者自动成为唯一 OWNER；`RP-09` 验证 OWNER 可授权；`RP-10` 验证 MANAGE 不可转授权限；`RP-11` 验证所有权转移后权限即时切换；`RP-12` 验证停用 OWNER 后由超级管理员接管；`RP-13` 验证重复授权幂等；`RP-14` 验证并发授权发生版本冲突；`RP-15` 验证 OWNER 不能通过授权接口撤销自己；`RP-16` 验证旧 OWNER 权限按转移选择处理；`RP-17` 验证权限回收立即终止新访问；`RP-18` 验证恢复后 OWNER 与授权约束成立。

### 5.2 仓库管理（M0）

#### 5.2.1 通用规则

1. 所有启用账号均可创建仓库；创建者自动成为唯一 OWNER。更新至少需要 MAINTAIN，非敏感配置需要 MANAGE，授权、专用凭据、所有权转移和删除需要 OWNER 或超级管理员。
2. 名称去除首尾空格后 1 至 100 字符；保存规范化名称（首尾去空格并按统一规则转小写），同一 OWNER 的未删除仓库规范化名称唯一，不同 OWNER 可使用同名。创建、重命名和所有权转移均使用同一约束；来源类型创建后不可修改。仓库路由、接口和关联关系只使用不可变 repositoryId，不以名称定位。
3. 创建前校验账号状态、来源策略、个人/系统仓库配额、存储容量和并发上限；普通账号不能绕过允许根目录、网络边界或上传限制。
4. 创建流程为：校验 → staging 准备代码 → 生成内容摘要 → 创建仓库与 OWNER 关系 → 发布快照 → 可选创建 CodeGraph 和索引任务。
5. 仓库、OWNER 关系和首个快照必须在同一业务事务成功后可见；失败不得留下无所有者仓库或可查询半成品。
6. 同一规范化来源和分支只能登记一次；无权用户重复提交已有来源时返回通用冲突，不泄露已有仓库名称、所有者或版本。

#### 5.2.2 来源闭环

| 来源 | 输入 | 受管方式 | 版本标识 | 更新动作 |
| --- | --- | --- | --- | --- |
| 本地 Git | 名称、白名单内绝对路径 | 保留原路径，发布只读快照 | branch、commit、工作区摘要 | 重新扫描 |
| 远程 Git | 名称、HTTPS/SSH URL、分支、凭据引用 | 受管 working copy | branch、commit | 立即同步 |
| GitLab | 名称、服务地址、项目、分支、Token 引用 | 受管 working copy | branch、commit | 立即同步 |
| ZIP | 名称、ZIP 文件、可选源码根 | 安全解压后形成受管版本 | 上传序号、ZIP 摘要、内容摘要 | 重新上传 |

本地 Git：解析真实路径并验证允许根目录；不得执行 pull、checkout、reset 或写入操作；摘要包含已跟踪修改和未忽略的未跟踪文件。

远程来源：连接前和连接时验证协议、端口、DNS 和实际 IP；默认拒绝回环、链路本地、云元数据和未允许内网；HTTPS 校验证书和同源重定向；SSH 使用受管 known_hosts；禁用 hooks、ext 协议、代理绕过和交互提示。

ZIP：禁止绝对路径、路径穿越、符号链接、设备文件、嵌套压缩包和压缩炸弹；限制上传大小、文件数、单文件大小、总解压量、目录深度和超时；相同摘要按无变更处理。

#### 5.2.3 所有权、授权与配额闭环

1. 创建成功在同一数据库事务写入仓库、OWNER 和首个快照清单；文件已发布但事务失败时，由补偿记录和巡检器删除无引用文件。
2. 创建请求使用账号、规范化来源、分支和请求幂等键去重；失败的 staging 和未发布记录不占用配额。
3. 普通账号默认最多拥有 20 个非删除仓库、同时运行 2 个仓库准备任务、占用 20 GiB 受管数据；配置可收紧。超级管理员不受个人数量限制，但仍受系统容量和并发硬上限约束。
4. OWNER 和超级管理员可授予、调整或回收 READ、MAINTAIN、MANAGE；目标必须是启用账号。重复设置相同权限返回当前结果，不新增记录。
5. 授权请求必须携带期望的 `ownershipVersion`；版本不匹配返回冲突和最新版本，不静默覆盖。
6. OWNER 不能通过普通授权接口修改自己的 OWNER 身份；MANAGE 不能授权、转移所有权、管理专用凭据或删除仓库。
7. 所有权转移要求仓库为 READY 或 AUTH_ERROR、目标账号启用、目标不是当前 OWNER，并进行二次确认。若目标 OWNER 已有同规范化名称的未删除仓库，转移请求必须同时提供一个在目标 OWNER 下可用的新名称；重命名与 OWNER 变更在同一事务完成，冲突时均不生效。批量停用接管必须逐仓预检名称并一次性提交冲突仓库的新名称映射。
8. 转移请求必须明确旧 OWNER 后续权限，默认 `NONE`，也可选择 READ、MAINTAIN、MANAGE；变更在同一事务完成并立即刷新授权缓存。
9. 仓库处于 DELETING、恢复中或已有治理操作执行时拒绝转移；治理操作使用独立仓库级锁。
10. 专用凭据继续绑定仓库。新 OWNER 获得掩码管理权，旧 OWNER 立即失去凭据和授权入口；运行中任务继续使用已冻结凭据版本。
11. 账号停用预览必须列出其 OWNER 仓库、受管数据量和运行任务；批量转移与停用任一步失败时整体回滚。
12. 列表和全局选择器的条件固定为 `owner_account_id = 当前账号` 或存在有效授权；超级管理员例外。不同 OWNER 的同名仓库对同一查看者可同时出现，界面和响应必须附带 OWNER 展示名、来源类型与 repositoryId 以消歧。重复来源或名称冲突对无权账号只返回通用冲突。

#### 5.2.4 凭据

1. 凭据是独立受管对象，密文保存，密钥与数据库分离；页面只显示类型、掩码、状态和最近验证时间。
2. OWNER 可新增、替换、停用和删除本人仓库的专用凭据；超级管理员可管理全部专用凭据和系统共享凭据。普通 MANAGE 账号只能使用或测试已有凭据，不能读取、替换或改变引用。
3. 普通账号创建远程仓库时可一次性写入专用凭据，但不能选择或查看其他账号、其他仓库及系统共享凭据。
4. 替换凭据必须先验证后切换；任务冻结凭据版本，已运行任务不受后续替换影响。
5. 删除仓库只解除引用；无引用凭据进入待清理，共享凭据不连带删除。
6. 凭据异常时仓库进入 `AUTH_ERROR`，远程操作停用，当前快照仍可只读访问。

#### 5.2.5 更新与删除

1. 更新在 staging 获取完整新版本，摘要无变化则返回无变更。
2. 新版本校验成功后原子发布快照；认证、网络、分支、解压或摘要失败时保留当前快照。
3. 只有 OWNER 或超级管理员可删除仓库；删除分为预览、逻辑删除、异步清理和墓碑四步，存在运行中写任务时拒绝删除。
4. 逻辑删除立即撤销授权并退出列表、检索、问答和新任务。
5. 清理失败保持 `DELETING` 并从失败阶段幂等重试；完成后仓库 ID 不复用。
6. 历史问答和知识按保留策略隐藏代码证据或匿名化；墓碑不得含名称、地址、源码和凭据。

验收：`RM-01..29`。新增 `RM-21` 验证普通账号创建仓库并成为 OWNER；`RM-22` 验证 OWNER 分配、调整和回收权限；`RM-23` 验证非 OWNER 的 MANAGE 账号不能转授权限；`RM-24` 验证 OWNER 停用前安全转移所有权；`RM-25` 验证个人数量、并发或容量超限时不产生半成品；`RM-26` 验证文件发布后数据库失败可补偿清理；`RM-27` 验证无权账号重复创建同一来源时不泄露已有仓库；`RM-28` 验证旧数据迁移为指定 OWNER 且原授权不变；`RM-29` 验证同一 OWNER 大小写不敏感名称唯一、不同 OWNER 可同名，并验证所有权转移遇到同名时必须原子重命名或整体失败。

### 5.3 统一任务与错误模型（M0）

#### 5.3.1 任务范围

仓库创建、重新扫描、远程同步、ZIP 上传、CodeGraph、全量/增量内容索引、向量索引、知识索引、删除、清理、备份和恢复全部使用统一任务。

#### 5.3.2 任务闭环

1. 创建任务时冻结仓库、快照、上游产物、配置、凭据和外发策略版本。
2. 同仓库写任务使用带租约和心跳的互斥锁；相同幂等键只允许一个非终态任务。
3. 阶段、进度、心跳和有序脱敏事件持久化；刷新页面后恢复真实状态。
4. 取消排队任务直接进入 `CANCELED`；运行任务进入 `CANCEL_REQUESTED`，只在安全点停止。
5. 发布与取消竞争时，事务只允许一个合法终态；未完成产物不得成为当前指针。
6. 重试创建新任务并记录 `retryOf`，不得覆盖原历史。
7. 服务启动扫描非终态任务：可安全接管则续跑，否则以 `TASK_WORKER_LOST` 失败并允许重试。
8. API 和后台任务使用同一错误分类、稳定错误码、关联 ID、是否可重试和建议操作。
9. READ 可查看授权仓库任务；任务创建者且当前至少具有 MAINTAIN、OWNER 或超级管理员可取消普通任务；仓库删除、凭据清理、所有权迁移和恢复任务仅 OWNER 或超级管理员可操作。
10. 任务提交时校验权限并冻结执行输入；每次读取任务、日志和结果时重新校验当前权限。权限回收后任务可由平台继续安全执行，但原用户立即失去可见性和操作权。
11. 所有权转移不取消已经运行的同步、分析或索引任务；新任务使用新治理版本。删除和所有权转移使用治理锁互斥，不能跨状态竞态。

验收：`TASK-01..15`。新增 `TASK-13` 验证权限回收后任务继续安全执行但用户不可见；`TASK-14` 验证所有权转移后新任务使用新 OWNER 治理版本；`TASK-15` 验证删除与所有权转移不能并发成功。

### 5.4 CodeGraph（M0）

1. 支持检测兼容的已有 `.codegraph`，但必须复制到独立分析副本校验后发布，不能依赖源码目录内产物。
2. 首次和重新分析均通过统一任务运行 CLI；禁止执行仓库代码、hooks 和构建脚本。
3. 阶段至少包括准备副本、检测 CLI、分析、校验 schema、统计节点/边、发布和清理。
4. 产物绑定 snapshot、CLI 版本和 schema；目录位于受管 `codegraph`，不得写入只读快照。
5. M0 查询支持符号候选、定义、引用、直接 caller/callee 和关系证据位置。
6. 同名符号必须返回候选，不得静默选择。
7. 新分析失败、取消、超时、资源不足或 schema 不兼容时，旧已发布图保持可用并标记版本。
8. CLI 缺失、版本错误、超时、资源、产物和查询错误分别返回稳定类别。
9. MAINTAIN、MANAGE、OWNER 和超级管理员可发起首次构建、更新、重试或重新构建；READ 只能查看当前已发布图谱及其版本、过期状态，不能创建构建任务。
10. 仓库操作入口与 CodeGraph/调用图页面入口调用同一服务端能力和任务接口。相同仓库、快照和构建类型已有非终态任务时不得重复创建，返回已有 taskId；失败、取消或过期后才允许按规则发起新任务。

验收：`CG-01..16`。新增 `CG-15` 验证 READ 只能查看而 MAINTAIN 及以上可构建；`CG-16` 验证两个入口同时触发时只产生一个非终态任务并返回同一 taskId。

### 5.5 内容索引、向量索引与增量索引（M0/M1/M2）

#### 5.5.1 数据范围和切分

1. 只读取已发布快照；默认索引源码、配置、SQL、Markdown 和纯文本。
2. 永不默认索引二进制、依赖目录、构建产物、`.git`、`.codegraph`、`.env`、私钥、证书、凭据文件和疑似密钥内容。
3. 优先按语言符号切分，无法解析时按文本段落；超长符号生成有序子 chunk。
4. chunk 保存仓库、快照、文件、语言、符号、行号、内容摘要、父子关系和切分器版本。
5. M0 不用 LLM 生成摘要，原始证据与生成内容分离。

#### 5.5.2 发布闭环

1. 内容索引与向量索引独立状态；内容成功后即使 embedding 失败，关键词检索仍可用。
2. 构建写临时版本，完成数量、摘要和引用校验后原子发布。
3. embedding 全部成功才发布向量版本；部分失败保留上一版本。
4. 外部 embedding 默认关闭；启用时只发送过滤后的规范化 chunk 或查询文本，不发送账号、凭据和无关上下文。
5. 重建失败或取消清理临时数据，旧版本继续可用。
6. 删除索引只删除 chunk、向量和检索产物，不删除代码快照或 CodeGraph。

#### 5.5.3 增量索引

1. 比较两个冻结快照，处理新增、修改、删除和重命名文件。
2. 发布结果必须是完整逻辑版本，不得留下旧 chunk。
3. 切分规则、模型或维度变化，变化检测不可靠或变化比例超过阈值时自动转全量。
4. 增量失败保持当前已发布版本。

验收：`IDX-01..15`、`INCR-01..06`。

### 5.6 混合检索（M1/M2）

1. 单仓支持关键词、符号、向量和 CodeGraph 四路召回；M2 增加已发布知识卡片通道。
2. 查询先识别普通代码、符号定位、调用关系或业务知识意图，再决定通道；意图只影响召回，不生成事实。
3. 各通道必须绑定同一目标快照；不一致通道停用并显示降级原因。
4. 合并按仓库、快照、文件、行号和内容摘要去重；保留每个命中通道和排序解释。
5. 结果返回仓库、快照、来源类型、文件、符号、行号、片段、分数和命中原因；点击打开对应历史快照。
6. 单路超时不拖垮其他通道；结构查询缺少 CodeGraph 时不得用语义结果伪装调用关系。
7. 无结果返回已执行通道、降级项和收窄建议。
8. M2 最多联合检索 5 个已授权仓库；结果按仓库归一化并保持多样性，同名符号不跨仓合并，不生成跨仓调用边。

验收：`SRCH-01..17`、`MSRCH-01..07`。

### 5.7 代码问答（M1）

1. 会话创建时绑定一个仓库、账号和起始快照；M1 不跨仓。
2. 每轮执行权限检查、问题规范化、混合检索、证据校验、受限上下文构造、模型生成、引用校验和持久化。
3. 追问可使用会话语义解析指代，但必须重新检索本轮证据。
4. 回答区分已确认事实、推断、冲突、未知和建议；调用关系必须引用 CodeGraph。
5. 引用保存仓库、快照、文件、符号、行号、证据摘要和排序；行号越界或引用不存在时不得发布正常答案。
6. 无有效证据不调用模型；部分证据只回答可确认部分。
7. 模型超时、限流或停止时保留证据并标记回答未完成，允许基于同一证据重试。
8. 外部 LLM 默认关闭；只有全局开关、仓库策略和数据类别同时允许时，才发送当前问题和最小必要证据。
9. 历史回答始终打开回答绑定的快照；仓库升级不自动改写历史答案。
10. 权限回收立即停止生成并禁止访问会话、答案和引用；重新授权后可恢复本人历史。

验收：`QA-01..19`。

#### 5.7.1 QV1 代码问答增强

QV1 不等待外部 LLM 和完整 SSE 状态机，先把现有 `deterministic-local` 问答产品化：

1. **会话与历史**：问答会话绑定账号、仓库和起始 snapshot；左侧展示本人最近会话，支持新建、重命名和删除本人会话。刷新页面可恢复消息、回答和引用。
2. **有限多轮追问**：追问携带 conversationId；服务端只使用最近有限轮次做指代解析，并对本轮问题重新检索，不把旧回答当作新事实。
3. **问题模式**：提供“快速定位、解释实现、梳理流程、影响与风险、测试建议、故障排查”六种模式。模式只影响检索策略和回答模板，不改变证据真实性。
4. **快捷问题**：空状态提供“系统做什么、如何启动、核心模块、关键调用链、测试入口”问题卡；点击后允许编辑再提交，不在前端伪造答案。
5. **指定上下文提问**：检索结果、源码引用和图节点可加入临时证据篮，提问请求携带 chunkId/symbolId；服务端重新校验仓库、snapshot、摘要和权限后使用，非法或过期证据明确拒绝。
6. **结构化回答**：QV1 回答固定为“结论、实现位置、处理流程、限制/未知、建议下一步”五段；没有内容的段落隐藏，事实句必须带引用编号。
7. **证据轨道**：展示引用类型、文件、符号、行号、快照和命中通道；点击在对应版本源码中定位，支持复制版本化引用和从引用发起新问题。
8. **可信度提示**：展示已执行/降级检索通道、证据数量、引用覆盖、provider 和 snapshot。不得输出未经校准的百分比“可信度”；证据不足显示明确拒答和可执行的收窄建议。
9. **追问建议**：根据回答模式、已引用符号和缺失信息生成 2–4 个确定性建议问题；建议只是输入快捷方式，不自动发送。
10. **答案操作**：支持复制带引用 Markdown、基于同一问题重新检索、清空当前草稿；MAINTAIN 及以上可将回答与引用预填为 DRAFT 知识卡片，保存前必须确认编辑。
11. **版本变化**：会话期间仓库 snapshot 变化时显示“历史版本会话”，继续追问仍使用原版本；用户选择“基于最新版本新建会话”后才切换，不混用引用。
12. **隐私与权限**：普通账号只读取本人会话；超级管理员不因角色读取他人问答正文。权限回收立即清除会话列表、消息、证据篮和跨页上下文。

验收：`QA-QV-01..12`，编号依次对应以上十二项。QV1 的 Token 流式输出按 5.7.2 单独验收；仍不包含多仓上下文、自动执行建议和答案自动发布。

#### 5.7.2 QV1 LLM Token 流式输出

1. QV1 支持一个启用的 LLM Provider 以真实增量 Token 生成回答；首个实现采用 OpenAI-compatible HTTP 协议适配器，具体厂商、base URL、模型和密钥通过系统配置注入，不写死在业务代码。
2. 外部 Provider 默认关闭。只有系统外发开关、仓库策略、数据类别、敏感扫描和 Provider 健康检查全部通过时才允许调用；否则继续使用 `deterministic-local` 完整响应并明确标记未使用 LLM。
3. 客户端使用可携带 Cookie、CSRF 和 AbortSignal 的 `fetch` 流读取，不使用无法可靠携带自定义安全头的原生 EventSource。响应媒体类型为 `text/event-stream`。
4. 事件顺序为 `accepted → retrieving → evidence_ready → generating(delta)* → validating → completed`，异常终态为 `insufficient_evidence`、`failed`、`stopped`。每个事件携带 conversationId、messageId、sequence 和 requestId。
5. `delta` 仅是生成中草稿，不视为已验证事实。服务端完成后校验引用、仓库、snapshot、文件、行号和结构关系；只有 `completed` 事件中的最终答案可标记成功并进入历史。
6. 用户可停止生成。停止请求使 Provider 调用和下游读取尽快取消，回答进入 `stopped`；已验证证据和已接收草稿可保留并明确标记未完成，不进入知识检索或正式知识。
7. 浏览器断线不自动重复提交问题。客户端使用 messageId 查询最终状态；若服务端仍运行则可恢复事件摘要，若已失败则由用户显式重试。重试创建新 message attempt 并关联原消息，不覆盖历史。
8. 首 Token 超时、总超时、限流、Provider 5xx、非法流帧、上下文超限和引用校验失败使用稳定错误码；可重试错误提供动作，不可重试错误只展示关联 ID 和收窄建议。
9. 流式链路限制单次证据数、上下文字符、输出 Token、事件大小、空闲时间和总时间；慢客户端采用有界缓冲，超过上限停止请求，不能无限占用线程或内存。
10. 权限回收、账号停用、仓库删除、会话失效或外发策略收紧时立即取消进行中的流，后续事件不得继续发送；日志与指标不记录问题正文、证据正文或生成 Token。

验收：`QA-STREAM-01..10`，编号依次对应以上十项。必须使用可控的流式 Provider stub 覆盖正常增量、停止、断线、超时、限流、非法帧、引用失败和权限回收。

### 5.8 调用图与影响分析（M2）

1. 用户先选择精确符号候选，再选择上游、下游或双向，默认深度 1、最大默认深度 3。
2. 节点保存符号、类型、文件、行号、仓库和快照；边保存关系类型和证据位置。
3. 遍历记录最短深度，保留循环边；动态分派展示候选，不声称唯一运行时目标。
4. 支持符号、文件和模块聚合，聚合结果可展开到底层证据。
5. 节点、边、路径或耗时达到限制时返回部分图，并明确截断位置和原因。
6. 影响清单区分直接、间接和入口影响；测试分为结构关联和命名建议，不把命名相似宣称为覆盖关系。
7. 风险由影响规模、入口、跨模块、核心路径、测试证据缺失、截断和未解析关系确定，并展示构成因素。
8. LLM 只可总结已加载图和统计；模型失败时结构图和确定性清单仍可用。
9. 旧图可按旧快照查看，所有节点和边跳转到绑定版本。

验收：`GRAPH-01..10`、`IMPACT-01..07`。

### 5.9 知识卡片（M2）

1. 类型包括模块说明、业务规则、技术决策、接口约定、FAQ 和变更知识。
2. 卡片保存仓库、标题、正文、标签、适用快照/版本、引用、状态、作者、复核人和不可覆盖修订号。
3. 支持手工创建和从问答预填；生成内容只能成为草稿，必须人工确认。
4. MAINTAIN 可创建和编辑草稿；MANAGE 才能发布、撤回、归档或确认复核。
5. 发布前校验标题、正文、引用存在性、行号、证据摘要和版本适用性。
6. 发布新修订时，旧发布修订在新索引完成前继续可用；失败不得发布半成品。
7. 源码变化导致引用失效或冲突时进入 `NEEDS_REVIEW`，同步退出新检索和问答；异步清理失败也不恢复召回。
8. 恢复历史版本创建新的 `DRAFT` 修订，不覆盖历史。
9. 并发编辑使用修订号检测冲突；草稿作者失权后由仓库管理者接管。
10. 卡片与当前代码或 CodeGraph 冲突时，代码事实优先并显示冲突。

验收：`KC-01..19`。

### 5.10 系统设置与运行配置（M0-M2）

1. 仅超级管理员可读写全局设置；普通账号不能获取配置数据。
2. 配置分组：存储路径、Git/网络、任务资源、安全会话、索引切分、embedding、LLM、检索、CodeGraph、保留和备份。
3. 配置使用版本号和乐观锁；保存形成新版本，运行中任务继续使用冻结版本。
4. 非敏感配置支持查看历史并恢复为新版本；敏感值不从历史明文恢复。
5. 敏感配置加密保存、读取掩码、写入或替换不回显；密钥不可用时相关外部能力保持关闭。
6. 路径配置验证绝对路径、允许根、权限、容量和嵌套关系。
7. Git、GitLab、embedding 和 LLM 支持独立连接测试；失败不替换当前有效配置。
8. 自定义端点统一执行协议、端口、DNS、实际 IP、TLS、重定向和代理策略。
9. 仓库外发策略为 `INHERIT`、`LOCAL_ONLY`、`ALLOW_EXTERNAL`；普通账号只能收紧，不能放宽。
10. 影响索引或模型语义的配置变化将相关产物标记 `STALE` 并提示重建。

验收：`SET-01..15`。

### 5.11 备份与恢复（M0）

1. 必备范围：业务数据库、账号授权、加密配置与凭据密文、任务审计、仓库和产物元数据、备份清单、删除墓碑。
2. 快照、CodeGraph 和大型索引是否直接备份由策略决定；未备份项必须记录重建来源、工具版本、预计时间和风险。
3. 默认每日备份，保留 7 个日备份和 4 个周备份；备份加密并生成不可变清单和完整性摘要，主密钥分离保存。
4. 创建备份是可追踪任务；只有校验完整的备份进入 `READY`。
5. 恢复前校验格式、版本、摘要、schema、空间、密钥和运行中写任务，并展示覆盖范围和停机影响。
6. 预检通过后进入维护模式，拒绝新业务写入和新任务；创建恢复前安全备份。
7. 在隔离目录恢复并执行账号、授权、指针、文件、摘要、产物和凭据校验；全部成功后原子切换。
8. 失败回到恢复前状态，不开放数据库与文件指针混合版本。
9. 恢复应用删除墓碑和保留期，旧备份不得复活后来删除的数据。
10. 恢复后撤销全部旧会话；缺失但可重建的产物标记 `STALE` 并创建任务。开放服务前验证每个未删除仓库恰有一个存在的 OWNER、同一 OWNER 下规范化名称唯一、授权表不含 OWNER，且授权唯一约束成立；无效 OWNER 必须在预检阶段映射到指定恢复接管账号，映射造成同名时必须提供重命名映射，不能随机选择。
11. 默认业务元数据 RPO 24 小时、RTO 4 小时；完整检索恢复目标 24 小时；每季度执行恢复演练并保存结果。

验收：`BAK-01..11`。新增 `BAK-11` 验证恢复后每个未删除仓库 OWNER 唯一有效、同一 OWNER 下规范化名称唯一、授权不重复且删除数据不复活。

### 5.12 前端（随里程碑交付）

1. 页面包括登录/改密、开发者入门、账号与审计、仓库、任务、CodeGraph、内容与检索、问答、图分析、知识、设置和备份恢复。
2. 菜单与路由按角色和仓库权限生成；直接访问仍由后端授权，隐藏菜单不能替代接口鉴权，未交付能力不展示假入口。
3. 全局仓库选择器显示来源、当前版本和产物新鲜度；切换仓库清理旧页面敏感状态。
4. 长任务显示状态、阶段、进度、阻塞原因、脱敏事件、取消和重试；刷新后从后端恢复。
5. 危险操作展示影响预览并二次确认；本地仓库删除明确说明不删除原目录。
6. 代码和证据查看器显示仓库、快照、文件、符号和行号；历史引用不得跳到当前版本。
7. 加载、空状态、降级、失败、无权限和已删除使用不同反馈。
8. 用户内容按纯文本渲染；Markdown 必须消毒，不执行脚本；前端不持久化明文敏感信息。
9. 桌面端为主，关键操作支持键盘、可见焦点、语义标签和足够对比度。
10. CodeGraph 构建提供两个上下文入口，但不同时作为同等级主按钮：仓库列表操作列的“更多”菜单作为管理入口，CodeGraph/调用图页面按产物状态提供就地入口。

#### 5.12.2 菜单与路由闭环

1. 登录或刷新会话后，根据服务端返回的角色和权限重新生成菜单，不使用前端硬编码身份作为唯一依据。
2. 普通账号直接访问管理员路由时跳转到首个有权页面，并展示无权限提示；对应 API 返回 403 且不返回业务数据。
3. 超级管理员被降级、账号被停用或会话权限变化时，立即移除管理员菜单、清理已加载的账号、审计、配置和备份数据并离开当前页面。
4. 普通账号只有至少一个已授权仓库时才展示检索、问答、图分析和知识入口；无授权时展示不含仓库统计的空状态。
5. 菜单隐藏、按钮隐藏、路由守卫和后端授权必须使用同一权限语义；任一前端绕过不得扩大后端权限。
6. 仓库列表和详情使用后端返回的 `relationship` 与 `capabilities` 控制操作，至少包含 `canUpdate`、`canIndex`、`canBuildCodeGraph`、`canConfigure`、`canGrant`、`canManageCredential`、`canTransferOwnership`、`canDelete`。
7. OWNER 在仓库详情查看成员与仓库级治理记录；非 OWNER 不显示授权、所有权转移、专用凭据和删除入口。停用 OWNER 的账号管理弹窗必须先完成批量转移。
8. 仓库操作列的“更多”菜单按状态显示：无产物为“构建 CodeGraph”，产物过期为“更新 CodeGraph”，最近构建失败为“重新构建”，构建中改为“查看构建进度”；PUBLISHED 时可提供次级“重新构建”，不得占用行内主要操作位。
9. CodeGraph/调用图页面按状态显示上下文操作：无产物的空状态显示主按钮“立即构建”，过期或失败显示原因及“更新/重试”，PUBLISHED 时页面标题区只显示次级“重新构建”，构建中显示真实进度并链接任务详情。READ 用户只看到状态和已发布内容，不显示构建按钮。
10. 两个入口均以服务端 `canBuildCodeGraph` 和任务状态为准，并调用同一接口；任一入口已成功创建非终态任务后，另一入口立即切换为“查看构建进度”，不得重复提交。

### 5.13 开发者入门工作台（M1/M2）

目标：让第一次接触仓库的开发者在 30–60 分钟内完成“知道系统做什么、成功运行、看懂一条业务链路、定位关键代码、完成一个可验证练习”的最小闭环。入门工作台编排仓库、任务、CodeGraph、检索、问答和知识卡片，不复制这些模块的事实，也不自动修改代码。M1 交付总览、路径、进度、环境预检、基础场景链路和首个练习；M2 增加业务域地图、完整 API/数据目录、快照变化摘要、术语表和团队沉淀。

#### 5.13.1 系统总览与就绪度

1. 每个有权仓库提供“开始入门”入口；首页展示一句话定位、技术栈、模块/业务域数量、关键入口、外部依赖、启动方式、当前快照与产物新鲜度。
2. 总览区分“代码扫描得到的事实”“人工发布的团队知识”“模型生成的解释”；每项可追溯到文件、符号、行号、配置或知识修订。
3. 就绪度按环境、架构、业务域、数据、API、测试和运维七项分别显示已确认、待补充、已过期、不可用，不合并成误导性的单一准确率。
4. 缺少 CodeGraph、内容索引或知识时显示真实降级能力和下一步；READ 仅查看，具备相应 capability 的账号可就地发起构建任务。

#### 5.13.2 引导式学习路径

1. 内置“后端入门、前端入门、业务排障、接口开发、数据变更”路径模板；OWNER 或超级管理员可复制模板并为仓库发布自定义路径。
2. 路径由 `READ`、`RUN`、`TRACE`、`QUERY`、`VERIFY` 五类步骤组成，每步包含目标、预计耗时、前置条件、操作、证据和完成标准。
3. 学习进度按账号、仓库、snapshotId 和路径版本保存；访问页面不自动算完成，必须由用户确认或提交健康检查、检索结果、链路节点、测试结果等可验证证据。
4. 用户可暂停、继续、重置进度和选择目标角色；路径更新不覆盖历史进度，新版本由用户显式迁移。
5. 首次进入根据可用产物推荐最短路径，但允许跳过非强制步骤；缺失权限、依赖或环境时记录阻塞原因，不伪装完成。

#### 5.13.3 系统理解能力

1. 架构地图展示分层、模块、入口、依赖方向、外部服务和复杂度热点；节点可跳到文件、符号、调用图、相关任务和知识卡片。
2. 业务域地图展示业务域、实体、规则、状态、角色和主流程；人工知识与代码推导关系使用不同视觉和数据类型。
3. 场景链路允许从 HTTP 接口、后台任务、事件或定时任务出发，沿 Controller/Handler → Application Service → Domain → Mapper/表 → 外部依赖 → 测试展示可折叠路径。
4. API 目录展示方法、路径、权限、请求/响应类型、稳定错误码、实现入口、数据访问和关联测试；示例请求默认脱敏且不得携带真实凭据。
5. 数据模型浏览器展示表、关键字段、主外键、索引、Flyway 来源和读写入口，并明确区分业务 PostgreSQL 与 CodeGraph 只读 SQLite。
6. 版本变化摘要比较两个已发布快照，展示新增/删除/变化模块、接口、表、调用关系和已过期知识，并为新人生成“先看这些变化”的阅读清单。

#### 5.13.4 运行、调试与首个练习

1. 环境检查覆盖 Java、Node.js、PostgreSQL/pgvector、Flyway、CodeGraph CLI、受管目录、端口、必要环境变量和服务健康；敏感值只显示是否配置及掩码。
2. 启动手册按当前操作系统给出复制命令、启动顺序、健康检查、停止方式和常见失败修复；命令来源必须是 OWNER/超级管理员发布的受信任清单。
3. 平台不得自动执行仓库任意脚本、hooks 或 README 命令。可执行检查使用类型化 allowlist、固定参数、超时、资源限制、工作目录限制和审计；READ 默认只能复制命令，不能在服务端执行。
4. 调试手册支持“请求失败、任务失败、索引不新鲜、数据库迁移失败、CodeGraph 不可用”场景，串联日志关联 ID、任务事件、配置项、代码入口和建议测试。
5. 首个练习由仓库维护者定义目标、允许修改范围、推荐入口和验收命令；平台只保存步骤与结果，不创建分支、不提交代码、不宣称代码正确。

#### 5.13.5 个人学习空间与团队沉淀

1. 用户可收藏文件、符号、链路、知识卡片和问答，添加仅本人可见的笔记；最近浏览按仓库隔离并受当前权限二次校验。
2. 仓库术语表维护术语、别名、解释、业务域、代码证据和责任人；已发布术语可被检索和问答引用。
3. 用户可对步骤标记“已理解、仍有疑问、内容过期”，形成待补充清单；只有人工确认后才能转为知识卡片或更新正式路径。
4. 入门完成页输出已完成步骤、关键链路、收藏、阻塞项和建议下一步，可导出不含代码正文和敏感配置的 Markdown 摘要。

#### 5.13.6 权限、版本与验收

1. READ 可使用已发布路径和公共入门内容；MAINTAIN 可维护草稿；MANAGE、OWNER 或超级管理员可发布仓库路径和术语；系统级模板仅超级管理员管理。
2. 个人进度、笔记和收藏仅本人可见；超级管理员不因平台角色读取私人笔记正文。权限回收后入口、历史和导出立即不可访问。
3. 所有自动生成地图、链路、API、数据模型和变化摘要绑定 `repositoryId + snapshotId + artifactVersion`；新快照发布后旧结果标记过期，不跳到当前代码冒充历史证据。
4. 删除仓库时个人索引立即隐藏，并按仓库保留/删除策略清理；路径发布、运行检查、导出和知识转化写审计事件。

### 5.14 快速价值版本 QV1（优先交付）

目标：不等待完整入门工作台，在现有仓库、任务、CodeGraph、索引、检索、问答、图分析和知识卡片基础上，让用户在接入仓库后 10 分钟内看到可验证结果，30 分钟内理解系统基本结构。QV1 不新增向量库、图数据库、命令执行器或复杂学习路径表；允许接入一个受控的 OpenAI-compatible LLM Provider，用于真实 Token 流式问答。

#### 5.14.1 项目理解首页

1. 登录后的默认页调整为“快速开始”，无仓库时只显示接入仓库动作；有仓库时记住用户最近一次有权仓库，但不泄露已失权仓库信息。
2. 顶部展示当前仓库、OWNER、来源版本和“代码快照、CodeGraph、内容索引、最近任务”四项就绪状态；状态直接来自现有权威表和任务，不另存重复状态。
3. 就绪项可点击跳转到仓库、任务、检索或图分析，并携带 repositoryId、snapshotId、taskId 或 symbol 上下文，避免用户重复选择。
4. 首屏展示最近失败任务及脱敏原因、建议动作和“查看详情/重试”；没有失败时显示最近一次成功更新时间。

#### 5.14.2 一键准备与项目画像

1. 对 MAINTAIN 及以上提供“一键准备理解环境”：按缺失状态幂等创建 CodeGraph 和内容索引任务；已有当前 PUBLISHED 产物时跳过，不做无意义重建。
2. CodeGraph 是内容索引的前置依赖时使用任务依赖顺序执行；任一步失败保留旧产物，首页显示失败阶段和可重试动作。重复点击返回现有非终态任务。
3. READ 用户不显示构建按钮，只显示状态、负责人建议和已发布结果。
4. 项目画像只使用当前快照的 README、构建文件、目录和已发布索引/CodeGraph，展示语言/框架线索、顶层目录、关键配置、入口候选、模块/符号/chunk 数量和测试分布。
5. 无法确定的框架、入口或模块标记“未识别/候选”，不得由文件名直接宣称为确定事实；每项可跳转代码证据。

#### 5.14.3 五个快捷理解动作

首页提供固定且可解释的快捷动作，复用现有检索、问答和图分析接口：

1. **这个系统做什么**：优先检索 README、模块说明和已发布知识卡片。
2. **如何启动**：定位构建文件、compose、application 配置和运行文档，只展示仓库已有命令，不自动执行。
3. **核心模块有哪些**：结合目录、包、CodeGraph 模块/符号统计输出带证据列表。
4. **跟踪一条调用链**：先搜索入口符号，再带 symbol 跳转图分析；CodeGraph 不可用时退化为入口代码与引用检索。
5. **测试从哪里开始**：定位测试目录、测试类、构建命令和与所选符号相关的测试候选。

快捷动作必须预填问题但允许编辑；回答仍遵循证据不足即停止推断、引用绑定 snapshot、外发策略和当前权限。

#### 5.14.4 现有页面联动优化

1. 检索结果增加“查看调用影响”“带此证据提问”“复制版本化引用”动作；只有满足依赖时显示。
2. 问答结果增加“保存为知识草稿”，预填标题、摘要、repositoryId、snapshotId 和引用；用户确认后调用现有知识卡片接口，不自动发布。
3. 图分析节点增加“查看源码”“检索同名符号”“带此符号提问”，保持仓库和快照上下文。
4. 任务失败按依赖缺失、凭据、资源、超时、兼容、完整性和内部错误展示建议；前端基于稳定错误码映射动作，不解析自由文本。
5. 仓库列表增加“快速开始”入口；产物未准备时进入首页直接看到准备动作，已准备时进入项目画像。

#### 5.14.5 范围控制与效果指标

QV1 暂不实现：自定义学习路径、私人笔记、业务域地图、完整 API/数据目录、服务端运行命令、快照变化摘要、团队排行、自动修改代码和自动提交。它们保留在 5.13 的 M1/M2 目标中，不阻塞 QV1。

| 编号 | 验收场景 |

## 6. 跨模块闭环

### 6.1 仓库到知识的主链路

```text
来源校验
  → staging 准备
  → 发布只读快照
  → CodeGraph / 内容索引任务
  → 原子发布版本化产物
  → 混合检索
  → 带引用问答 / 图分析
  → 人工确认知识卡片
  → 代码变化触发过期或复核
```

每一步只消费上一步已发布版本；任一步失败不回滚已发布的旧版本，也不把半成品暴露为当前结果。

### 6.2 权限闭环

```text
授权 → 列表可见 → 操作前校验 → 任务与产物继承范围
     → 查询与引用二次校验 → 回收后立即停止访问 → 审计留痕
```

### 6.3 删除闭环

```text
影响预览 → 阻塞检查 → 二次确认 → 逻辑删除与撤权
        → 异步清理受管数据 → 历史证据隐藏/匿名化
        → 墓碑与保留期 → 幂等重试 → 最终清除
```

### 6.4 恢复闭环

```text
选择恢复点 → 完整性与兼容性预检 → 维护模式
          → 恢复前备份 → 隔离恢复 → 一致性和安全校验
          → 应用删除墓碑 → 原子切换 → 撤销会话 → 重建缺失产物
```

### 6.5 开发者入门闭环

```text
选择仓库与目标角色 → 检查环境和产物 → 阅读系统/业务总览
                  → 跟踪一条真实场景链路 → 运行或复制验证步骤
                  → 完成首个练习 → 保存进度与疑问 → 人工沉淀知识
                  → 新快照触发变化摘要、内容过期和复习建议
```

入门内容只编排已授权的版本化事实。代码变化不会改写已完成记录；旧路径保持可复现，新路径和变化摘要显式提示用户迁移。
## 7. 非功能要求

### 7.1 准确性与追溯

1. 代码、图、检索、回答和知识均能追溯到仓库、快照、产物、文件和行号。
2. 引用发布前验证文件存在、行号合法和证据摘要一致。
3. 结构事实、代码正文、人工知识和模型生成内容在数据模型和界面中明确区分。

### 7.2 性能基线

参考环境：8 核 CPU、16 GB 内存、本地 SSD、单实例、同内网数据库、10 万行/2 万文件/2 GB 单仓。

| 能力 | 目标 |
| --- | --- |
| 关键词查询 | P95 < 2 秒 |
| M1 综合检索 Top 20 | P95 < 3 秒，不含外部 provider 异常 |
| CodeGraph 直接关系查询 | P95 < 2 秒 |
| 入门总览（缓存命中） | P95 < 2 秒，缺失产物时返回明确降级 |
| 三层影响图 | P95 < 5 秒或明确截断 |
| M0 全量内容索引 | < 15 分钟 |

### 7.3 安全

1. 生产传输使用 TLS；Cookie 设置 HttpOnly、SameSite，并在 HTTPS 下设置 Secure。
2. 外部 embedding 和 LLM 默认关闭；任何外发都执行全局、仓库、数据类别三层策略。
3. 文件读取、ZIP、Git、CodeGraph、引用跳转和清理均防止路径穿越和符号链接逃逸。
4. 网络端点执行 SSRF、DNS 重绑定、TLS、重定向、代理和端口控制。
5. 用户错误只包含稳定错误码、脱敏摘要和关联 ID；受保护日志也不得含凭据或完整代码正文。

### 7.4 可靠性与可观测性

1. PostgreSQL、文件产物和当前指针变更采用事务或可恢复的两阶段发布。
2. 服务重启后非终态任务必须接管、重新排队或明确失败。
3. 指标至少覆盖请求、任务、队列、阶段耗时、失败分类、检索通道、provider 和存储容量。
4. 日志关联请求 ID、任务 ID、仓库 ID 和快照 ID，不记录敏感正文。

### 7.5 容量、兼容与保留

1. M0 单实例默认最多 100 个仓库、单仓 2 GB、2 万文件；超限在准备阶段拒绝。
2. 支持 Windows 和 Linux 服务端；浏览器支持当前两个主要版本的 Chromium 和 Edge。
3. 删除、审计、问答、知识和备份保留期由管理员配置；法定策略优先。

## 10. 完成定义

一个功能只有同时满足以下条件才可标记完成：

1. 前端入口、后端授权、业务处理和持久化全部存在。
2. 成功结果可查看、可追溯，并绑定正确版本。
3. 输入非法、依赖不可用、任务取消和服务重启都有确定结果。
4. 重试幂等，失败不覆盖旧数据，不发布半成品。
5. 权限回收和逻辑删除立即阻断新访问。
6. 受管文件、数据库记录、任务和审计生命周期一致。
7. 自动化测试覆盖主流程、权限、失败回滚和版本一致性。
8. 对应验收编号通过，使用和运维文档已更新。
9. 面向开发者的功能同步更新入门路径、场景链路或明确标记不影响入门内容。
