# 代码智库系统需求规格

版本：v3.1
日期：2026-07-31
状态：当前实现基线
实现基准：1.0.0 发布候选工作区（基于 Git commit `61155a43101e39c0c1c92858b8a851151959fb01`）

> 本文描述当前代码已经提供的产品行为。未在当前路由、接口或持久化链路中形成闭环的能力统一放入“后续规划”，不得作为当前交付能力宣传或验收。

## 1. 产品定位与当前范围

### 1.1 产品定位

系统面向需要理解、审查和持续维护软件项目的人与智能体，提供仓库接入、项目总览、项目资产索引、源码检索、证据问答、调用图谱、知识卡片和任务上下文能力。所有结果以当前已发布快照为读取边界，并保留来源路径与版本证据。

### 1.2 当前交付页面

| 路由 | 页面 | 当前用途 | 访问范围 |
| --- | --- | --- | --- |
| `/login` | 登录 | 登录、验证码、首次改密 | 公开入口 |
| `/overview` | 项目总览 | 无需关键词查看结构、资产、准备状态并生成 Agent Context Pack；根路径默认页 | 有仓库 READ 权限 |
| `/ask` | 知识问答 | 单仓检索问答、历史记录与证据查看 | 有仓库 READ 权限 |
| `/knowledge` | 知识卡片 | 卡片、修订、附件和代码引用 | READ/MAINTAIN |
| `/graph` | 调用图谱 | CodeGraph 构建与影响分析 | READ；构建需 MAINTAIN |
| `/search` | 源码检索 | 当前快照目录、文件和 Markdown/源码预览 | READ |
| `/repositories` | 仓库管理 | 接入、准备、项目画像、编辑、重扫、索引、治理和删除 | 登录账号 |
| `/indexing` | 索引任务 | 任务列表、详情、取消、重试和当前向量索引 | 按仓库权限 |
| `/accounts` | 账号管理 | 账号与审计 | 超级管理员 |
| `/settings` | 系统设置 | 问答模型和向量模型备案 | 超级管理员 |

当前不提供“快速开始”和“开发者入门”页面；不得展示对应菜单或假入口。

### 1.3 当前交付能力状态

| 功能域 | 状态 | 说明 |
| --- | --- | --- |
| 身份、账号、仓库、源码预览 | 已形成可用链路 | 仍有生产安全约束 |
| 一键准备与项目画像 | 已形成最小闭环 | 前端推进同步、索引与 CodeGraph；画像来自当前已发布事实 |
| 内容索引、向量索引、单仓混合检索 | 已形成可用链路 | Git 增量已交付，多仓未交付 |
| 问答、调用图、知识卡片 | 多轮问答基础链路可用 | SSE、停止/断线恢复、精细治理未交付 |
| 模型设置 | 问答与向量模型可用 | 其他系统配置分组未交付 |
| 备份恢复、快速开始、开发者入门 | 未交付 | 仅作为后续规划 |

### 1.4 不在当前范围

1. 自动修改代码、创建分支、提交代码或创建 PR。
2. 自动执行仓库构建、测试、脚本、Git hooks 或 README 命令。
3. SaaS 多租户、计费、企业 SSO 和组织架构。
4. 训练私有代码模型。
5. 多仓检索、流式问答会话、备份恢复、快速开始和学习路径。

## 2. 全局业务规则

1. 当前代码事实来自仓库的 `currentSnapshotId/currentSnapshotPath`；源码浏览、chunk 和引用均绑定快照标识。
2. 普通账号只能看到本人拥有或被授权的仓库；超级管理员可以访问全部未删除仓库。
3. 前端隐藏入口不代替后端鉴权；所有仓库接口再次校验 READ、MAINTAIN、MANAGE 或 OWNER。
4. 当前仓库选择保存到账号偏好；无权或已删除仓库不会恢复为当前仓库。
5. 工作区页签只保存路由名称、标题和路径到浏览器 localStorage，不保存源码、模型密钥或回答正文。
6. 系统只清理平台受管目录，不删除本地 Git 原目录。
7. 后端错误当前统一为 `code + message + timestamp`；前端展示服务端消息，不具备旧设计中的 category、retryable 和 suggestedAction 字段。
8. 生产部署不得直接使用开发默认密码、默认模型主密钥、当前目录导入根或临时受管目录。

## 3. 角色、权限与状态

### 3.1 平台角色

- `SUPER_ADMIN`：账号、审计、系统设置和全部仓库治理。
- `NORMAL`：创建仓库并访问本人拥有或被授权的仓库。

### 3.2 仓库关系与权限

| 关系/权限 | 当前能力 |
| --- | --- |
| `READ` | 查看仓库、任务、源码、检索、问答、图和知识 |
| `MAINTAIN` | READ + 重扫、内容索引、CodeGraph 构建、知识卡片创建/编辑 |
| `MANAGE` | MAINTAIN + 仓库资料编辑和配置能力 |
| `OWNER` | MANAGE + 成员授权、所有权转移和删除 |
| `SUPER_ADMIN` | 对所有仓库按治理最高权限处理 |

每个未删除仓库只有一个 OWNER。服务端返回 `relationship`、`ownershipVersion` 和 capabilities，页面按钮以 capabilities 为准。

### 3.3 当前状态

- 账号：`PASSWORD_CHANGE_REQUIRED`、`ENABLED`、`LOCKED`、`DISABLED`。
- 仓库：代码中使用 `PREPARING/READY/DELETING/DELETED/FAILED` 等状态；已逻辑删除仓库不再出现在普通查询中。
- 任务：`QUEUED`、`RUNNING`、`CANCEL_REQUESTED`、`SUCCEEDED`、`FAILED`、`CANCELED`。
- 任务类型：`FULL`、`INCREMENTAL`、`CODEGRAPH`；当前 `INCREMENTAL` 未实现差异算法，不得宣传为真实增量。
- 知识发布：`DRAFT`、`PUBLISHED`、`ARCHIVED`；人工评审：`UNREVIEWED`、`APPROVED`、`CHANGES_REQUESTED`；来源版本：`UNVERIFIED`、`CURRENT`、`STALE`。
- 模型连接：`UNCONFIGURED`、`UNTESTED`、`AVAILABLE`、`DEGRADED`、`UNAVAILABLE`。
- 向量状态：`EMBEDDED`、`MISSING`。

## 4. 当前端到端链路

```text
登录 → 选择或接入仓库 → 发布当前快照
→ 创建内容索引任务 → 生成 chunk 与当前模型维度的向量
→ 源码检索 / 混合检索 / 知识问答
→ 查看引用源码或调用图 → 保存知识卡片
```

仓库页提供“准备 / 画像”入口：前端调用幂等准备接口推进快照刷新、内容/向量索引和 CodeGraph，并轮询后台任务；页面关闭不影响已入队任务，再次打开可继续推进。任务中心用于查看内容索引和 CodeGraph 任务。

## 5. 功能需求

### F01 身份与会话

1. 空账号库在应用就绪时根据 `APP_INITIAL_ADMIN_USERNAME/APP_INITIAL_ADMIN_PASSWORD` 创建首个超级管理员并要求改密。
2. 用户名为 3–32 位字母、数字、点、下划线或连字符。
3. 密码为 8–64 位，至少包含四类字符中的三类，不得等于用户名或命中内置弱密码表。
4. 密码使用 PBKDF2WithHmacSHA256、独立盐和固定迭代参数保存。
5. 连续失败 3 次要求验证码；失败 5 次锁定，默认 15 分钟。
6. 会话使用随机 Token 的 SHA-256 摘要持久化；默认空闲 30 分钟、绝对 12 小时。
7. Cookie 名为 `AC_SESSION`，设置 HttpOnly、SameSite=Lax、Path=/ 和与绝对会话时长一致的 Max-Age；生产环境通过 `APP_SESSION_COOKIE_SECURE=true` 增加 Secure。
8. 非 GET/HEAD/OPTIONS 请求必须携带 `X-CSRF-Token`。
9. 首次改密期间只允许 `/me`、改密和退出。
10. 改密、重置、停用和角色变化撤销相关会话。
11. 管理员重置密码返回安全随机临时密码，有效 24 小时；重置会撤销旧会话，账号下次登录必须先改密。
12. 当前没有本机救援令牌接口。

验收：登录、验证码、锁定、首次改密、CSRF、空闲/绝对超时和会话撤销必须以接口测试覆盖。

### F02 账号、审计与仓库治理

1. 超级管理员可分页查询、新增、编辑、启停、解锁和重置账号。
2. 编辑字段为显示名称、平台角色和启用状态，请求携带账号版本；版本冲突返回 409。
3. 系统不得停用或降级最后一个启用的超级管理员，也不得停用当前登录账号。
4. OWNER 仍拥有仓库时，账号停用请求直接拒绝；当前没有“批量转移全部仓库并停用”的单次接口。
5. OWNER 或超级管理员可在仓库治理页授予 READ、MAINTAIN、MANAGE，撤回权限或转移所有权。
6. 治理请求携带 `expectedOwnershipVersion`；冲突不覆盖新状态。
7. 所有权转移可同时处理仓库重命名和旧 OWNER 后续权限。
8. 当前审计记录登录、账号和仓库治理等事件，返回事件类型、结果、requestId、来源 IP、操作者、目标账号、仓库和时间。
9. 当前审计页仅提供全局管理员读取，没有 OWNER 级仓库审计视图。
10. `/api/accounts/{id}/permissions/{repositoryId}` 保留兼容入口，但服务端要求改用仓库治理接口。

### F03 仓库接入与快照

1. 所有启用账号可创建仓库并成为 OWNER。
2. 当前来源类型为 `LOCAL_GIT`、`REMOTE_GIT`、`GITLAB`、`ZIP`。
3. 本地 Git 输入服务端路径，必须位于允许根目录；读取 Git 元数据并复制发布只读快照，不修改原仓库。
4. 远程 Git 和 GitLab 使用 HTTPS Git URL、分支和可选加密凭据；不接收 URL 内嵌凭据。凭据支持通用 HTTPS Token 与 GitLab PAT，按创建人隔离，超级管理员可查看全部脱敏记录。
5. 凭据可在接入页创建、编辑、选择和检测，Token 使用独立主密钥加密，通过临时 GIT_ASKPASS 注入，不写入 URL、命令参数或日志。
6. 远程导入当前在 HTTP 请求中同步执行 shallow clone，默认超时 180 秒；不是统一后台任务。
7. ZIP 限制最多 20000 个条目、单文件解压后 20 MiB、总解压量 500 MiB并阻止路径穿越；当前没有完整的链接、魔数、压缩比、嵌套压缩和恶意内容扫描。
8. ZIP 导入后在受管目录初始化本地 Git 并生成导入提交，但产品展示可隐藏 Git 版本。
9. 远程和 ZIP 导入成功后移动到受管工作副本并登记仓库；失败尝试清理 staging 和已创建记录。
10. 仓库名称最长 100 字符，同一 OWNER 下按规范化名称唯一。
11. 当前没有完整实现旧需求中的仓库数量、并行准备和 20 GiB 用户配额。

### F04 仓库维护、浏览与删除

1. MANAGE 可编辑名称、500 字符内描述和默认分支，请求携带 repositoryVersion。
2. 重扫比较当前 Git/工作区版本；有变化时发布新快照，无变化返回 `changed=false`。
3. 当前分支编辑和重扫为同步接口，没有 staging 候选任务的完整阶段展示。
4. 源码文件列表只读取当前快照普通文件并忽略符号链接。
5. 单文件在线预览上限默认 2 MiB；含 NUL 字节视为二进制并拒绝。
6. 默认按 UTF-8 严格解码；BAT/CMD 在 UTF-8 失败后回退 GB18030；其他非 UTF-8 文本拒绝预览。
7. 支持 Java、Kotlin、TypeScript/JavaScript、Vue、Python、Go、Rust、C/C++、C#、PHP、Ruby、Shell、BAT/CMD、Markdown、YAML、JSON、XML、HTML、CSS、SQL、properties/TOML/INI/conf/env 等语言标识。
8. Markdown 使用前端 marked + DOMPurify 预览；源码使用 highlight.js，未知类型按文本展示。
9. OWNER 或超级管理员可删除仓库；删除先标记 `DELETING`、写墓碑并撤出可见列表，后台 Worker 清理受管派生数据，失败后重试。
10. 删除不得触碰 LOCAL_GIT 原目录。
11. Git/GitLab HTTPS 凭据可复用并与远程仓库绑定；当前不支持 SSH 私钥、GitLab 项目枚举与 Webhook。
12. READ 可查看当前项目画像；画像仅统计已发布快照的文件、语言、一级目录、约定入口、chunk、向量、知识和当前 CodeGraph 产物。
13. MAINTAIN 可执行一键准备；接口先刷新仓库快照并启动 FULL/INCREMENTAL 内容索引，内容就绪后把当前快照 CodeGraph 构建加入后台队列。

### F04A 项目总览、资产与 Agent 上下文

1. 登录后默认进入项目总览；选择仓库后无需检索词即可查看根目录、一级模块、主要语言、入口文件和准备轨道。
2. 索引片段必须标明资产类型：`CODE`、`DOCUMENT`、`RULE`、`TASK`、`CONFIG`。
3. 项目画像返回各资产类型数量，并识别 README、架构/设计文档、Agent 指令、规则、任务和 gate 等关键资产。
4. READ 可调用 `POST /api/repositories/{id}/context-pack`，按任务生成当前快照的只读上下文包。
5. Context Pack 必须返回 repository、snapshot、commit、生成时间，以及每条证据的路径、行号、chunk、资产类型和内容哈希。
6. 请求限制任务描述、最大条目数和总字符数；结果支持复制或下载 Markdown。
7. Context Pack 不自动执行代码、不写回仓库、不创建分支或提交。
8. 外部会话、评审、工单和文档连接器不在本轮交付范围。
9. READ 可调用 `GET /api/repositories/{id}/architecture-map`，无需检索词查看当前快照的项目级模块地图。
10. 架构地图展示项目包含关系、跨模块静态依赖、运行资源连接、分析覆盖率、循环依赖和分层边界提醒，并保留最多三个来源文件样例。运行资源包含从代码或配置中识别的数据库、缓存、消息队列、对象存储和 HTTP 服务；模块与资源节点支持一跳聚焦，关系样例可直接下钻到对应源码或配置文件。
11. 运行资源定位信息必须去除凭据、路径、查询参数和片段；外部明文 HTTP 以及领域层直接连接运行资源应产生架构提醒。所有提醒均为静态分析建议，不作为构建门禁；动态端点、反射、依赖注入装配和未分析文件必须在覆盖说明中明确。
12. READ 可按架构模块查询当前快照已索引的非空代码符号，接口必须校验模块确实存在，并限制单次最多返回 200 个符号；前端支持模块内筛选、精确源码定位和携带真实符号进入调用图。

### F05 索引任务

1. MAINTAIN 可创建 `FULL` 或接口保留的 `INCREMENTAL` 内容索引任务。
2. 同仓库任一非终态索引/CodeGraph 任务存在时，重复创建返回现有任务。
3. 内容索引 Worker 轮询领取 `QUEUED` 任务，扫描当前快照、切分 chunk、替换仓库 chunk、生成向量并结束任务。
4. 当前切分优先识别类、接口、record、enum、函数、方法和 Markdown 标题；大段按最多 120 行、20 行重叠切分。
5. 任务支持请求取消；运行任务只在处理器检查点结束为 CANCELED。
6. 重试创建新任务；当前不持久化原任务到重试任务的链式标识。
7. 应用启动时将遗留非终态任务恢复为确定结果，页面轮询刷新列表。
8. 任务详情返回状态、步骤、请求类型、实际执行模式、增量回退原因、错误、开始/结束/创建时间；CodeGraph 任务额外返回心跳、固定超时和稳定失败代码。当前没有完整事件流与统一百分比模型。
9. CodeGraph 使用同一 `index_jobs` 表，由独立 Worker 领取；任务返回心跳、固定超时截止、失败代码和失败原因。
10. 仓库导入、附件上传和删除清理没有统一展示在索引任务页。

### F06 CodeGraph 与调用图谱

1. MAINTAIN 可构建，READ 可查看当前已发布产物和影响结果。
2. 平台复制当前快照到独立分析目录，运行配置的 CodeGraph CLI，不直接在源仓库内生成产物。
3. 构建成功记录仓库、快照、CLI 版本、产物路径、节点数和边数；失败不产生新的已发布产物。
4. 构建接口只入队并返回 HTTP 202；Worker 执行复制、CLI 构建和发布，支持心跳、固定超时、取消和遗留任务回收。
5. 新产物通过单一事务切换发布状态；新构建成功前保留旧发布产物，构建期间快照切换时拒绝发布旧版本。
6. 当前图接口以用户输入符号作为中心，深度限制 1–5；后端支持 BOTH/UPSTREAM/DOWNSTREAM，当前前端固定传 BOTH。
7. 风险按边数量给出 LOW/MEDIUM/HIGH，并明确反射、动态分派等静态分析限制。
8. 当前没有符号候选选择、文件/模块聚合、结构证据位置、图截断协议和历史快照图浏览。
9. CodeGraph 不可用不影响内容索引、源码检索和本地问答降级。

### F07 内容与向量索引

1. 内容索引扫描当前发布快照，跳过二进制、敏感文件、依赖和构建目录等过滤项。
2. chunk 保存仓库、快照、commit、文件、符号、语言、类型、行号、正文、摘要和创建时间。
3. 当前发布通过 `replaceRepositoryChunks` 替换仓库 chunk；没有独立内容索引版本指针。
4. 代码和已发布知识向量保存在 PostgreSQL pgvector；本地哈希固定 64 维且只表示字符相似度，外部 embedding 支持 1–4096 维并表示语义检索。
5. 向量模型支持 `LOCAL_HASH` 和 OpenAI-compatible embeddings；同一时间只有一个激活向量模型。
6. 向量模型卡片提供独立检测；外部模型检测调用 `/embeddings`，并要求返回长度与备案维度一致。
7. 检索或索引发现当前模型缺失向量时按需补建，使用 `content_hash + model + dimension + retrieval_capability` 判断缺失。
8. 当前向量索引页面仅展示所选全局仓库的当前数据，不提供页面内仓库切换，也不展示历史任务产物。
9. 页面汇总代码 chunk、已向量化/缺失数量、知识卡片数量、模型、维度和更新时间；明细支持代码/知识、关键词、向量状态和 chunk 类型过滤。
10. `INCREMENTAL` 使用 Git name-status 识别新增、修改、删除、重命名和复制；缺少基线、工作区脏、差异失败或变更比例超过 35% 时回退全量，并记录实际模式和原因。

### F08 单仓混合检索

1. 当前只支持单仓检索。
2. 查询分析器拆分自然语言、符号和路径术语。
3. 召回通道包括代码关键词、启发式调用引用、代码字符相似度或外部 embedding 语义向量；问答额外包含知识关键词及对应向量通道。
4. 排序器融合通道权重，返回综合分、关键词分、相似度分、相似度类型和命中通道。
5. 单通道失败时保留其他成功通道；响应统一返回启用通道、不可用通道、模型、快照、各通道/融合召回数、耗时和降级原因。
6. 搜索结果绑定 chunk 的当前 snapshotId、文件、符号、行号和 contentHash。
7. 当前没有多仓选择、跨仓归一化和多仓权限聚合。

### F09 质量评测与发布门禁

1. 金标准固定覆盖 50 个源码定位、30 个带人工证据问答和 20 个已知修改范围任务，且覆盖后端、前端和运维自动化三类项目形态。
2. 发布指标包括 Recall@10、引用覆盖率、人工陈述支持率、变更文件召回率和 P95 延迟。
3. 结果必须覆盖全部用例；陈述支持判断必须记录具名人工评审者与评审时间。
4. 版本标签发布必须提供与数据集版本一致的实际评测结果并通过 `evaluation/thresholds.json`，缺少结果直接阻断发布。

### F10 知识问答

1. READ 用户选择一个仓库和一个检测可用的问答模型后提交问题；缺少任一选择时前端明确提示。
2. 每次请求重新鉴权并执行代码与已发布知识联合检索，最多取 10 条证据。
3. 无证据时不调用模型，返回 `INSUFFICIENT` 和收窄问题建议。
4. 有证据时，按请求携带的 modelConfigId 调用对应模型；配置必须为 AVAILABLE 且熔断器为 CLOSED。
5. Prompt 最多拼接约 14000 字符证据，每条正文最多 2400 字符，并要求事实句使用 `[S编号]`；其中凭据、访问密钥和私钥先脱敏。
6. 模型回答按事实段引用覆盖标记为 `CITATION_COMPLETE` 或 `CITATION_INCOMPLETE`，只表达机械覆盖，不表达语义蕴含；引用非法时为 `MODEL_OUTPUT_REJECTED` 并使用本地确定性回答，其他未调用/调用失败状态为 `DEGRADED`。
7. 本地回答只列出高相关代码/知识位置，不模拟模型解释或 Token 动画。
8. 每次问答生成新的 conversationId，并将问题、回答、账号、仓库、快照和引用保存到 `qa_conversations/qa_citations`。
9. 每次问答保存为会话中的独立轮次，首轮问题摘要作为默认标题；支持按当前仓库查看、恢复、重命名和删除整段会话。
10. 历史记录持久化完整回答状态和引用快照；恢复后不得将降级或证据不足错误显示为引用校验通过。
11. 当前问答为普通 JSON 请求并支持多轮上下文：最近问题参与检索消歧，最近问答参与模型生成；暂不提供 SSE、停止生成或断线恢复。
12. 页面支持引用卡片、源码跳转、知识跳转和调用图谱跳转；所有跳转显式携带引用所属仓库。
13. 每轮回答持久化检索诊断；历史恢复保留当时的快照、模型、启用/不可用通道、召回数、耗时和降级原因。

### F11 知识卡片与附件

1. 当前类型为业务规则、技术决策、接口约定和模块说明。
2. 卡片保存标题、类型、Markdown、标签、修订、发布状态、人工评审状态、来源版本状态、附件和代码引用，三类状态互不替代。
3. 创建和编辑生成修订历史；历史可恢复为新的草稿修订，不覆盖原历史。
4. 编辑器支持 Markdown 编写/预览、附件上传、插入内部附件链接和关联代码选择。
5. Markdown 通过 marked 渲染后由 DOMPurify 消毒；服务端同时保存安全渲染结果。
6. 附件允许图片和 PDF/TXT/MD/CSV/JSON/DOCX/XLSX/PPTX 等受控扩展名，校验大小、扩展名和部分魔数后保存到按 SHA-256 去重的受管对象目录。
7. 下载附件时重新校验仓库 READ 权限。
8. 当前没有外部恶意内容扫描服务、上传进度任务、替代文本信息面板、拖拽/粘贴上传和离页未保存保护。
9. MAINTAIN 可创建和编辑卡片，保存统一生成草稿和未评审修订；MANAGE 才可执行具名人工评审与独立发布。未通过评审或来源已过期的卡片不能发布。
10. 已发布知识参与问答关键词与向量检索；附件正文不参与检索。

### F12 系统设置与模型

1. 仅超级管理员可访问系统设置。
2. 当前页面只有“问答模型”和“向量模型”两个 Tab。
3. 问答模型支持多个 OpenAI-compatible 配置备案，字段包括名称、Base URL、模型、API Key、连接/请求超时、输出 Token、Temperature 和流式能力检测开关。
4. API Key 加密保存；读取只返回是否已配置。新建可不填 Key，编辑留空保留既有 Key。
5. 保存和检测是两个独立动作；保存不自动检测，检测为 AVAILABLE 后即可在知识问答页面选择。
6. 连接检测异步执行格式、目标、TLS、鉴权、最小生成和可选首 Token 阶段，支持轮询与取消；固定探针不携带仓库数据。
7. 知识问答页列出所有备案模型，仅 AVAILABLE 且熔断器为 CLOSED 的模型允许选择。
8. 问答请求直接携带模型配置 ID，不再维护全局问答模型激活选择。
9. 真实调用失败记录最近成功/失败、错误码和熔断状态；达到阈值后降级本地。
10. 检索命中的代码片段在凭据和私钥脱敏后发送给本轮所选模型，不再使用全局外发开关。
11. 向量模型支持本地哈希和 OpenAI-compatible，两者与问答模型独立备案、密钥和激活。
12. 当前没有仓库级外发策略、路径、网络、任务、安全、索引参数、保留策略和备份恢复 UI。

### F13 源码检索与 UI 工作区

1. 主导航顺序为知识问答、知识卡片、调用图谱、源码检索、仓库管理、索引任务；管理员追加账号管理和系统设置。
2. 登录后默认进入知识问答。
3. 顶部全局仓库选择器加载当前账号可见仓库，并把选择写入服务端账号偏好。
4. 工作区页签对已访问路由去重，支持关闭、关闭其他和关闭全部；页签元数据保存在 localStorage。
5. 路由组件使用 KeepAlive，最多缓存 12 个页面实例。
6. 源码检索左侧显示当前快照文件树/文件列表，右侧显示文件元数据与预览；Markdown 使用独立预览组件，BAT/CMD 使用 batch 高亮。
7. 索引任务页内层 Tab 为“索引任务”和“当前向量索引”，Tab 与内容位于同一白色容器中。
8. 知识问答页顶部提供模型选择；系统设置中的问答模型卡片只负责新增、检测和编辑。
9. 页面采用纯白侧栏、浅灰画布、Action Blue 主色、紧凑内容区、细边框和少量轻阴影。
10. 当前路由为静态导入，生产构建未按页面拆包。

## 6. 数据与存储要求

1. PostgreSQL 为唯一运行期业务数据库；新环境由 Flyway 依次执行 `V1__init_schema.sql` 至当前版本迁移，已有环境按迁移历史向前升级。
2. pgvector 扩展必须可用，代码和知识使用可变维度 `vector` 字段；查询按当前模型和维度隔离。
3. 当前核心表包括账号/会话/验证码、仓库/权限/治理/墓碑、任务、chunk/向量、CodeGraph、问答、知识/附件、系统设置和模型配置。
4. `git_credentials/repository_credential_bindings` 提供 Git/GitLab HTTPS 凭据与仓库绑定；问答记录由 `qa_conversations/qa_citations` 唯一持久化。
5. 仓库工作副本、快照、CodeGraph 产物和知识附件保存在 `APP_MANAGED_DATA_ROOT` 下。
6. 生产环境必须显式配置数据库凭据、受管根、允许导入根、模型主密钥和初始管理员；默认值仅允许本地开发。

## 7. 非功能与发布约束

### 7.1 当前验证基线

- Java 17、Spring Boot 3.5、MyBatis、PostgreSQL/pgvector。
- Vue 3.5、TypeScript、Vite、Pinia、Element Plus。
- `mvn test` 执行无外部依赖的后端单元/组件测试；Linux 专属 CodeGraph CLI 契约测试按操作系统启用。
- `APP_RUN_POSTGRES_IT=true mvn -pl backend -Dtest='*IT' test` 执行真实 Flyway/MyBatis/pgvector、快照切换和仓库导入到问答链路；默认 Linux CI 自动启动 pgvector 并执行。
- `npm test` 验证关键路由，`npm run build` 通过 vue-tsc 与 Vite 生产构建。

### 7.2 当前剩余发布评审项

1. 敏感启动值已从 `application.yml` 移除，生产 Compose/systemd 模板要求显式配置；发布时仍需验证 HTTPS、Secure Cookie、密钥和目录权限。
2. 远程导入允许 HTTP，尚未完成完整的 SSRF、DNS 重绑定、重定向和实际 IP 策略。
3. ZIP 已有路径、数量、大小、压缩比和部分魔数校验，但未覆盖全部链接、嵌套包和恶意内容扫描。
4. 浏览器视觉回归与完整 UI 操作端到端尚未自动化；当前端到端覆盖服务层“导入→索引→问答”真实数据库链路。
5. 备份恢复、HTTPS、Secure Cookie、密钥和目录权限仍需在预发布环境演练。
