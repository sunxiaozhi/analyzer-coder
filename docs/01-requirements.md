# 代码智库系统需求文档

版本：v0.6

日期：2026-07-20

状态：需求闭环复审已完成

## 1. 背景

团队希望基于 CodeGraph 构建一个代码智库系统，将代码结构解析后的 SQLite 数据与 RAG 能力结合，为代码理解、代码检索、调用链分析、影响范围分析、研发问答和知识沉淀提供统一入口。

传统 RAG 对代码的理解主要依赖文本相似度，容易遗漏调用关系、定义位置、符号依赖和跨文件影响。CodeGraph 可以补充结构化代码事实，包括符号、文件、调用边、引用关系和影响面。系统目标是把“语义检索”和“结构化代码图谱查询”结合起来，输出带代码引用、可追溯、可验证的回答。

## 2. 产品目标

### 2.1 核心目标

1. 支持导入一个或多个代码仓库，自动构建代码内容索引。
2. 同时利用 RAG 向量检索和 CodeGraph SQLite 结构化数据进行混合检索。
3. 支持自然语言代码问答，并返回代码文件、符号和行号引用。
4. 支持函数、类、文件级别的调用链和影响范围分析。
5. 支持增量索引，使仓库变更后知识库可以更新。

### 2.2 非目标

当前规划不优先覆盖以下能力：

1. 自动修改代码并提交 PR。
2. 完整替代 IDE。
3. 大规模企业级权限矩阵和审计系统。
4. 跨组织公网 SaaS 多租户计费。
5. 训练私有代码大模型。

## 3. 目标用户

1. 研发工程师：快速理解陌生模块、查找实现位置、定位调用链。
2. 架构师 / Tech Lead：评估模块依赖、改动影响面、架构边界。
3. 新成员：通过问答快速理解代码库和业务逻辑。
4. 代码审查人员：辅助判断改动是否影响其他模块。
5. 运维 / SRE：定位运行链路中对应的代码实现。

## 4. 典型场景

### 4.1 功能定位

用户问题：

> 登录鉴权逻辑在哪里实现？

系统应返回：

1. 相关文件和符号。
2. 核心函数或类说明。
3. 代码引用位置。
4. 相关入口和调用方。

### 4.2 调用链分析

用户问题：

> validateToken 被哪些地方调用？

系统应返回：

1. 直接调用方。
2. 多层调用链。
3. 文件路径、符号名、行号。
4. 可视化调用图数据。

### 4.3 改动影响分析

用户问题：

> 如果修改 OrderService.createOrder，会影响哪些模块？

系统应返回：

1. 直接和间接受影响的调用方。
2. 相关测试文件。
3. 高风险依赖。
4. 建议验证范围。

### 4.4 业务知识问答

用户问题：

> 订单取消后库存是如何回滚的？

系统应返回：

1. 语义相关代码片段。
2. 关键业务流程总结。
3. 涉及的服务、函数、事件或数据库操作。
4. 引用来源。

### 4.5 代码资产沉淀

用户希望系统沉淀：

1. 模块说明。
2. 架构说明。
3. API 说明。
4. 常见问题。
5. 代码变更知识。

## 5. 功能需求

### 5.1 账号登录与账号管理

优先级：P0

首次交付：M0

#### 5.1.1 功能目标

账号功能为平台提供真实身份边界，使用户登录后按账号类型和仓库授权使用系统，并由超级管理员维护账号及仓库权限。M0 实现超级管理员、普通账号和仓库级授权，不实现企业 SSO、组织架构或按具体接口自由组合的复杂权限策略。

本功能包含：

1. 初始超级管理员初始化。
2. 用户名和密码登录、退出及会话校验。
3. 用户修改自己的密码。
4. 超级管理员新增、编辑、停用、启用、解锁和重置账号密码。
5. 超级管理员和普通账号两种账号类型。
6. 普通账号按仓库分配只读、维护或管理权限。
7. 登录、账号变更和仓库授权的基础安全记录。

#### 5.1.2 初始超级管理员

1. 系统首次启动且不存在账号时，必须创建一个初始超级管理员。
2. 初始用户名由部署配置指定；初始密码通过部署密钥或首次启动流程设置，不得写入源码、默认配置文件或普通日志。
3. 初始超级管理员首次登录后必须修改密码，修改前只能访问修改密码和退出功能。
4. 系统至少始终保留一个启用中的超级管理员，不允许停用最后一个启用超级管理员或将其改为普通账号。
5. 唯一可用超级管理员无法登录时，允许部署管理员在服务端本机进入救援模式；救援模式要求暂停普通登录、验证部署级密钥，并生成短时一次性重置令牌，不提供远程匿名重置接口。
6. 救援令牌默认 15 分钟失效且使用一次即作废；完成重置后强制修改密码、使该账号全部旧会话失效，并记录不可删除的安全事件。

#### 5.1.3 登录

登录页包含用户名、密码和登录操作，不提供自助注册和“忘记密码”入口。

登录流程：

1. 用户输入用户名和密码。
2. 系统校验账号是否存在、状态是否允许登录以及密码是否正确。
3. 校验成功后创建登录会话，记录成功时间和来源 IP，并进入平台首页。
4. 校验失败时返回统一提示“用户名、密码或账号状态不正确”，不得暴露账号是否存在。
5. 连续失败达到阈值后要求输入验证码；继续失败达到锁定阈值后临时锁定账号。
6. 被停用的账号不能登录；已登录账号被停用后，其现有会话应立即失效。

默认安全阈值：

1. 同一账号连续失败 3 次后要求验证码。
2. 连续失败 5 次后锁定 15 分钟。
3. 登录成功、超级管理员解锁或锁定期结束后，连续失败计数清零。
4. 阈值、锁定时长和验证码开关允许由超级管理员配置。

#### 5.1.4 会话与退出

1. 会话凭据必须由服务端安全生成，浏览器端不得保存明文密码。
2. 默认空闲 30 分钟失效，最长持续 12 小时；两个时长均可配置。
3. 用户主动退出后，当前会话立即失效并返回登录页。
4. 用户修改密码或超级管理员重置密码后，该用户除当前改密流程外的全部旧会话失效。
5. 用户访问无权限功能时返回“无权限”，会话失效时返回登录状态失效；两者不得混用。
6. 同一账号允许多端登录；超级管理员可以使该账号的全部会话失效。

#### 5.1.5 密码规则

1. 密码长度默认为 8 至 64 个字符。
2. 密码至少包含大写字母、小写字母、数字和特殊字符中的三类。
3. 密码不得与用户名相同，不得使用系统维护的常见弱密码。
4. 密码必须使用专用密码哈希算法加盐保存，不得可逆加密或明文保存。
5. 新增账号和超级管理员重置密码时使用一次性临时密码，用户下次登录必须修改。
6. 用户修改密码时必须输入当前密码；超级管理员重置他人密码不需要知道原密码。
7. 密码规则后续可配置，但降低规则不得影响已存在密码，直到用户下次修改。
8. 临时密码默认 24 小时失效，只能在创建或重置成功结果中向操作者显示一次；页面离开后不可再次查看，日志、通知和导出均不得包含正文。
9. 临时密码过期后账号保持“待修改密码”且不能进入业务页面，由超级管理员重新重置；重置新临时密码立即作废旧临时密码。

#### 5.1.6 账号管理

账号列表仅超级管理员可访问，至少展示用户名、显示名称、账号类型、状态、已授权仓库数量、最近登录时间、最近登录 IP、创建时间和更新时间。

超级管理员可以：

1. 新增账号，填写用户名、显示名称、账号类型和临时密码。
2. 修改显示名称和账号类型；用户名创建后不可修改。
3. 停用或重新启用账号。
4. 解锁因登录失败被临时锁定的账号。
5. 重置密码并使旧会话失效。
6. 分配、调整或回收普通账号的仓库权限。
7. 查看账号的最近登录、账号变更和仓库授权记录。

账号规则：

1. 用户名去除首尾空格后长度为 3 至 32 个字符，仅允许字母、数字、点、下划线和连字符。
2. 用户名不区分大小写且全局唯一；页面保留创建时的显示形式。
3. 显示名称长度为 1 至 50 个字符。
4. M0 不物理删除账号，使用“停用”保留历史主体和记录。
5. 超级管理员不能停用当前登录账号；需要由另一超级管理员操作。
6. 账号类型、状态或仓库授权变化后立即生效，不要求用户重新登录。

#### 5.1.7 账号类型与平台权限

| 能力 | 超级管理员 | 普通账号 |
| --- | --- | --- |
| 登录、查看本人账号和修改本人密码 | 允许 | 允许 |
| 查看全部仓库 | 允许 | 仅限已授权仓库 |
| 创建仓库 | 允许 | 不允许 |
| 使用或维护仓库 | 允许 | 按该仓库的授权级别 |
| 删除仓库 | 允许 | 仅具有该仓库“管理”权限时允许 |
| 修改系统设置 | 允许 | 不允许 |
| 管理账号和仓库授权 | 允许 | 不允许 |

超级管理员不需要逐仓库授权，始终可以查看和操作全部仓库。普通账号创建后默认没有任何仓库权限。

#### 5.1.8 仓库权限

普通账号的仓库权限由超级管理员逐仓库分配。每个“账号 + 仓库”最多存在一条有效授权，权限级别如下：

| 权限级别 | 允许操作 |
| --- | --- |
| 未授权 | 仓库不可见，不得通过列表、搜索、直接地址或接口获取仓库及其派生数据 |
| 只读 | 查看仓库、任务、代码、chunk 和已有分析结果；使用代码检索、问答、调用图和影响分析 |
| 维护 | 包含只读；可以重新扫描、同步、重新上传、触发 CodeGraph 分析和代码内容索引，以及新增或编辑知识卡片 |
| 管理 | 包含维护；可以修改仓库非敏感配置、发布或删除知识卡片，以及删除仓库和平台派生数据 |

授权规则：

1. 只有超级管理员可以新增、修改或回收仓库授权；普通账号即使具有“管理”权限也不能转授权。
2. 超级管理员可以从账号详情按仓库分配权限，也可以从仓库详情批量选择普通账号并设置权限。
3. 新建仓库默认仅超级管理员可见，普通账号必须显式授权。
4. 权限变更立即生效。回收权限后，仓库应从该账号的列表、全局搜索和最近访问中消失。
5. 权限降低或回收时，由该账号已触发的后台任务继续按系统任务执行，但该账号不能再查看或操作超出新权限范围的任务。
6. 停用普通账号时保留其仓库授权；重新启用后恢复原授权。账号改为超级管理员时保留授权记录但不参与校验；改回普通账号时重新按原授权生效。
7. 删除仓库时同步删除该仓库的全部授权记录。
8. 未授权访问不得返回仓库名称、路径、代码、任务或索引等敏感信息。
9. 仓库列表、任务中心、代码检索、问答、调用分析、知识卡片和相关统计均必须按仓库授权过滤。
10. 权限校验必须由服务端执行，不能只依赖前端菜单、按钮或路由控制。

#### 5.1.9 状态

账号状态包括：

1. 启用：可以登录并按角色使用功能。
2. 停用：禁止登录，已有会话失效，只能由超级管理员重新启用。
3. 临时锁定：因连续登录失败暂时禁止登录，锁定期结束或超级管理员解锁后恢复启用。
4. 待修改密码：可以登录，但只能修改密码或退出。

临时锁定是安全状态，不得覆盖账号原本的停用状态。

#### 5.1.10 安全记录

M0 至少记录：

1. 登录成功、登录失败、退出、会话失效和账号锁定。
2. 账号创建、账号类型修改、停用、启用、解锁和密码重置。
3. 仓库权限分配、权限变更和权限回收。
4. 操作者、目标账号、目标仓库、变更前后权限、结果、时间和来源 IP。

安全记录不得保存明文密码、临时密码、会话凭据或验证码答案。普通账号只能查看自己的最近登录信息，超级管理员可以按操作者、目标账号、目标仓库、动作、结果和时间检索安全记录并查看脱敏详情。安全记录使用稳定事件类型、结果和关联请求 ID，支持稳定分页；M0 不提供含敏感正文的导出。

#### 5.1.11 M0 不支持

1. 用户自助注册和通过邮件或短信找回密码。
2. LDAP、OIDC、OAuth、SAML 或企业 SSO。
3. 多因素认证和扫码登录。
4. 组织、用户组、岗位、字段级权限和自定义权限策略。
5. 永久删除账号。
6. 完整合规审计平台和审计记录导出。

#### 5.1.12 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AUTH-01 | 初次部署系统 | 创建初始超级管理员，首次登录必须修改密码 |
| AUTH-02 | 使用正确账号密码登录 | 创建有效会话并进入平台 |
| AUTH-03 | 用户名不存在、密码错误或账号停用 | 返回统一错误，不泄露账号是否存在 |
| AUTH-04 | 连续登录失败 | 按阈值启用验证码并临时锁定账号 |
| AUTH-05 | 会话空闲超时 | 会话失效并要求重新登录 |
| AUTH-06 | 用户退出 | 当前会话立即失效 |
| AUTH-07 | 用户修改密码 | 修改成功，其他旧会话全部失效 |
| AM-01 | 超级管理员新增普通账号 | 账号使用临时密码登录后必须修改密码，默认无仓库可见 |
| AM-02 | 超级管理员停用账号 | 账号无法登录，已有会话立即失效 |
| AM-03 | 超级管理员调整账号类型 | 新的平台权限立即生效 |
| AM-04 | 普通账号访问账号管理 | 拒绝访问且不返回账号数据 |
| AM-05 | 停用或降级最后一个启用超级管理员 | 操作被拒绝并说明原因 |
| AM-06 | 超级管理员重置密码 | 生成临时密码，目标账号旧会话全部失效 |
| AUTH-08 | 临时密码超过有效期或重复使用 | 拒绝进入业务页面，要求超级管理员重新重置 |
| AUTH-09 | 唯一超级管理员遗忘密码 | 仅可通过本机救援模式和部署密钥生成一次性令牌，完成后旧会话失效并留痕 |
| AUD-01 | 超级管理员检索安全记录 | 按权限返回脱敏事件，普通账号不能读取他人记录 |
| RP-01 | 为普通账号分配仓库只读权限 | 账号可查看和查询该仓库，但不能触发维护操作 |
| RP-02 | 将仓库权限提升为维护 | 账号可同步代码并触发分析和索引 |
| RP-03 | 将仓库权限提升为管理 | 账号可修改仓库配置和删除仓库 |
| RP-04 | 回收仓库权限 | 仓库及关联任务、搜索结果立即对该账号不可见 |
| RP-05 | 普通账号直接访问未授权仓库 | 拒绝访问且不泄露仓库信息 |
| RP-06 | 普通账号尝试给他人授权 | 拒绝操作，即使其具有仓库管理权限 |
| RP-07 | 超级管理员查看仓库 | 无需单独授权即可查看和操作全部仓库 |

### 5.2 仓库管理

优先级：P0

首次交付：M0

#### 5.2.1 功能目标

仓库管理负责把代码来源转换为平台可识别、可版本化、可分析的仓库。平台只管理来源、代码快照及派生数据，不修改用户的本地仓库。

用户应能创建仓库、查看当前代码版本、安全更新代码、触发后续分析与索引，以及删除平台数据而不误删本地源码。

#### 5.2.2 前置条件

1. 用户已登录；创建仓库仅限超级管理员，更新代码至少需要该仓库“维护”权限，删除需要“管理”权限。
2. 仓库名称在平台内唯一，去除首尾空格后长度为 1 至 100 个字符。
3. 服务端已配置受管数据目录和允许导入的本地根目录。
4. 创建时可选择“导入后自动分析并建立索引”，默认关闭。

#### 5.2.3 来源类型

| 来源 | 用户输入 | 平台保存方式 | 当前版本标识 | 更新动作 |
| --- | --- | --- | --- | --- |
| 本地 Git | 名称、本地路径 | 保存来源路径；任务开始时创建受管只读快照 | branch、commit、工作区内容摘要 | 重新扫描 |
| 远程 Git | 名称、Git URL、默认分支、认证信息 | 平台受管副本 | branch、commit | 立即同步 |
| GitLab | 名称、项目地址或项目 ID、默认分支、Access Token | 平台受管副本 | branch、commit | 立即同步 |
| ZIP | 名称、ZIP 文件 | 安全解压后的平台受管快照 | 上传版本、ZIP SHA-256、内容摘要 | 重新上传 |

来源类型创建后不可修改；更换来源类型时应创建新仓库。

#### 5.2.4 创建仓库

通用流程：

1. 用户选择来源并填写字段。
2. 系统校验格式、安全性、重复性和可访问性。
3. 系统准备代码并生成不可变快照。
4. 系统识别代码版本，检测是否存在可用的 .codegraph 目录。
5. 系统创建仓库并将新快照设为当前版本。
6. 开启自动处理时，按“CodeGraph 分析、代码内容索引”的顺序创建任务；否则等待手动触发。

创建完成前不得发布可查询的半成品仓库。失败可以保留任务记录，但不得发布不完整快照。

本地 Git：

1. 路径必须存在、可读且为有效 Git 仓库。
2. 规范化路径及符号链接真实路径必须位于允许根目录内；同一路径只能登记一次。
3. 平台不得对用户工作区执行 pull、checkout、reset 等修改操作。
4. 版本包含 branch、HEAD commit 和工作区内容摘要；摘要包含已跟踪修改及未被 Git 忽略的未跟踪文件。
5. 任务使用开始时冻结的快照，原目录后续变化不得影响本次任务。

远程 Git：

1. 支持 HTTPS 和 SSH，不接受本地路径或 file 协议地址。
2. 默认分支必填，创建前验证远端分支存在。
3. 凭据只允许写入或替换，接口、页面和日志不得回显明文。
4. 同一规范化远端地址和同一分支只能登记一次。
5. 平台受管副本不得由用户直接修改。
6. HTTPS 必须校验证书和主机名；重定向次数受限，每次重定向重新执行协议、主机和网络边界校验，禁止把凭据转发到不同源。
7. SSH 必须使用受管 known_hosts 或超级管理员确认的主机指纹，禁止首次连接静默信任未知主机；私钥只写入受限临时文件或密钥代理。
8. URL、分支和 SSH 参数按数据处理，不得拼接为 shell 命令；禁用 Git hooks、ext 等外部协议和仓库自带配置触发的外部命令。

GitLab：

1. 支持项目地址或项目 ID；私有化 GitLab 同时提供服务地址。
2. 创建前验证连通性、令牌、项目权限和目标分支。
3. 支持 Personal Access Token 和 Project Access Token，Token 加密保存且可替换。
4. 唯一性按规范化服务地址、项目标识和分支判断。
5. 服务地址执行与远程 Git 相同的 TLS、重定向和网络边界校验；访问内网地址必须命中超级管理员配置的明确允许清单。

所有远程来源：

1. 创建、测试连接和同步前解析目标主机，并在连接时再次校验实际 IP，防止回环、链路本地、云元数据地址、DNS 重绑定和代理绕过。
2. 允许访问的公网、内网网段、端口和代理由超级管理员配置；默认拒绝云元数据地址及未显式允许的内网目标。
3. 网络策略拒绝时使用稳定安全错误，不发起认证，不在错误中泄露目标网络探测结果。

ZIP：

1. 仅接受 ZIP，仓库名称不得从文件名推断。
2. 单一顶层目录自动剥离；多个源码根无法判断时要求指定解压根目录。
3. 禁止绝对路径、路径穿越、越界符号链接、设备文件和嵌套压缩包。
4. 限制包大小、文件数、单文件大小、解压总量、压缩比、目录深度和超时；默认值由系统设置定义。
5. 同一仓库重复上传相同 ZIP SHA-256 或内容摘要时按幂等操作处理。

#### 5.2.5 仓库列表与详情

仓库列表至少展示名称、来源、当前代码版本、来源更新状态、CodeGraph 状态、代码内容索引状态、最后成功时间及当前任务进度。Git 展示 branch、commit 短值与工作区状态；ZIP 展示上传版本与摘要短值。失败时展示脱敏错误摘要。

详情还应展示来源专属信息、完整版本标识、派生产物绑定的代码版本、最近任务和可执行操作。凭据不得回显。派生产物对应旧代码时标记“已过期”，但允许查看旧版本数据。

#### 5.2.6 更新代码

本地 Git 重新扫描：

1. 重新读取 branch、commit 和工作区内容，生成只读快照。
2. 不访问远端、不执行 pull、不修改用户工作区。
3. 内容摘要未变化时返回“无变更”，不创建新版本或后续任务。

远程 Git 与 GitLab 同步：

1. 在临时目录获取目标分支最新 commit，完成检出和校验。
2. commit 未变化时返回“无变更”。
3. 校验成功后才原子发布新快照。
4. 认证、网络、分支或检出失败时保留当前快照和派生产物。

ZIP 重新上传：

1. 新 ZIP 是完整新版本，不与旧目录合并。
2. 按“上传、安全校验、临时解压、内容扫描、生成快照、原子发布”执行。
3. 内容未变化时不创建上传版本或后续任务。
4. 成功后仓库 ID 和历史不变；失败时保留旧版本。

#### 5.2.7 版本变化与派生状态

1. 新快照发布后，未绑定该快照的 CodeGraph 和代码内容索引标记为“已过期”。
2. 已过期不等于不可用；新产物发布前旧产物仍可查询，但必须显示其旧代码版本。
3. 自动处理关闭时手动触发分析和索引；开启时仅在代码变化后串行创建任务。
4. 不得把新代码与旧 CodeGraph 或旧索引组合成“最新结果”。

#### 5.2.8 并发与幂等

1. 同一仓库的重新扫描、同步、ZIP 覆盖、CodeGraph 分析和代码内容索引任务互斥。
2. 相同操作重复提交时返回现有排队中或运行中任务。
3. 新快照发布后，依赖它的后续任务才能开始。
4. 服务重启后，未完成任务必须恢复或明确失败并允许重试。

#### 5.2.9 仓库配置与凭据生命周期

1. 具有仓库“管理”权限的账号可修改仓库显示名称、默认分支、自动处理开关，并按第 5.10.7 节收紧仓库级外发策略；来源类型、规范化来源地址或项目标识不可原地修改，变更时创建新仓库。
2. 修改默认分支前必须验证目标分支存在；成功后生成该分支的新快照并使原派生产物过期，失败时保留原分支、快照和凭据。
3. 远程 Git 和 GitLab 凭据支持“测试连接、替换、停用、删除引用”，任何读取接口、任务参数、日志和审计事件均不得返回明文。
4. 替换凭据采用先验证后切换；验证失败不得覆盖当前可用凭据。切换后新任务使用新版本，已启动任务继续使用其启动时冻结的凭据版本。
5. 凭据为独立受管对象并记录引用计数。删除仓库只移除该仓库的凭据引用；无其他引用的专用凭据进入待清理状态，共享凭据不得连带删除。
6. 凭据失效、停用或权限不足时，仓库标记“认证异常”，禁止需要远端访问的操作，但当前快照、历史查询和本地派生产物仍可按权限访问。
7. 凭据变更、测试、停用和删除均记录操作者、仓库、凭据类型、结果与时间，不记录密钥正文。
8. 只有超级管理员可以新增、替换、停用或删除仓库凭据；具有仓库“管理”权限的普通账号可以使用现有凭据测试连接，但不得读取掩码之外的信息或改变凭据引用。

#### 5.2.10 删除仓库与历史证据

1. 删除采用“逻辑删除、异步清理、最终清除”三阶段；删除前展示影响预览、预计保留项和不可恢复项，并要求二次确认。
2. 逻辑删除生效后立即回收仓库授权，仓库、任务和派生产物不再用于列表、搜索、问答或新任务；仅超级管理员可在删除任务中查看脱敏状态。
3. 有排队中或运行中任务时拒绝删除并返回阻塞任务；用户先取消并等待任务进入终态后方可删除。
4. 异步清理删除受管副本、快照、CodeGraph、内容索引、chunk、缓存、仓库配置和凭据引用，但不得删除或修改本地 Git 原目录。
5. 已发布知识卡片和历史问答默认保留业务记录，但其仓库正文、代码片段和可点击定位立即隐藏；记录改为“来源仓库已删除”，仅保留问题、回答、卡片正文、版本号、操作者、时间及证据摘要哈希等最小审计信息。
6. 若部署策略要求彻底清除，最终清除同时匿名化或删除历史问答与知识卡片正文，仅保留不可反推源码的审计墓碑；删除预览必须明确展示受影响数量。
7. 审计墓碑至少包含原仓库不可逆摘要、删除操作者、删除时间、清理结果和关联记录计数，不得包含仓库名称、来源地址、源码、凭据或可恢复正文。
8. 最小证据保留期默认 180 天，审计墓碑保留期默认 365 天，均可由超级管理员配置；法定或组织保留策略优先，界面必须展示实际到期日。
9. 最终清除完成前状态为“删除中”，失败时任务进入失败终态并允许从未完成阶段幂等重试；完成后仓库 ID 不得复用。

#### 5.2.11 M0 不支持

1. 自动同步和 GitLab Webhook。
2. Git submodule 初始化与更新。
3. Git LFS 实体自动下载。
4. 一个仓库记录管理多个分支。
5. 在受管副本中编辑或提交代码。
6. 增量索引。

### 5.3 CodeGraph 集成

优先级：P0

首次交付：M0

#### 5.3.1 功能目标

CodeGraph 集成负责把代码快照转换为可验证、可版本化的结构化代码事实，为符号定义、引用、调用关系和后续代码内容索引提供确定性数据。

本功能包含：

1. 检测并导入代码快照中已有的 CodeGraph 产物。
2. 由平台调用受支持版本的 CodeGraph CLI 执行首次分析和重新分析。
3. 以后台任务展示阶段、进度、日志摘要和失败原因。
4. 校验、发布、保留和回滚版本化 CodeGraph 产物。
5. 通过稳定查询能力读取文件、符号、定义、引用、caller 和 callee。
6. 在分析成功后按配置串行触发代码内容索引。

#### 5.3.2 前置条件与权限

1. 仓库已存在可读取的当前代码快照。
2. 检测、查看状态和查询结构事实至少需要仓库“只读”权限。
3. 开始分析、重新分析、取消和重试至少需要仓库“维护”权限。
4. 平台已配置 CodeGraph CLI 的受支持版本、可执行文件位置、任务超时及 CPU、内存和临时磁盘上限。
5. 当前快照正在变更或同仓库已有互斥任务时，不得立即开始分析。

#### 5.3.3 检测与导入已有产物

1. 创建或更新代码快照后，系统检测源码根目录下是否存在 .codegraph 目录。
2. 不存在已有产物不影响仓库和快照发布，CodeGraph 状态为“未生成”。
3. 存在已有产物时，系统检查目录结构、元数据、SQLite 文件可读性、完整性、CLI/schema 版本和最小查询能力。
4. 校验通过后，将产物复制到平台受管的不可变产物目录，再发布为当前 CodeGraph；查询不得长期直接读取用户目录中的 SQLite 文件。
5. 已有产物必须能够绑定当前代码快照。无法证明版本一致时，不得作为当前可用产物导入，可标记为“不兼容”并提示重新分析。
6. 导入过程不得修改或删除源码目录中的 .codegraph 内容。
7. 已有产物校验失败不阻止仓库使用，但结构化查询不可用，并展示可操作的失败原因和“重新分析”入口。

最小校验至少包括：

1. SQLite 文件可只读打开且完整性检查通过。
2. 受支持 schema 所需的表、字段和索引存在。
3. 文件、符号、定义和调用关系的抽样查询可执行。
4. 文件路径为仓库内相对路径，行号不为负且起止范围合法。
5. 产物声明的代码版本、CLI 版本和 schema 版本满足兼容规则。

#### 5.3.4 首次分析与重新分析

1. 未生成可用产物时展示“开始分析”；已有产物时展示“重新分析”。
2. 每次分析固定绑定任务创建时的代码快照，运行期间仓库来源变化不得改变本次输入。
3. CLI 在临时工作目录中生成新产物，不覆盖当前已发布产物。
4. 新产物完成校验后才能原子发布为当前 CodeGraph。
5. 首次分析失败后状态仍为“未生成”，并关联最近失败任务。
6. 重新分析失败或取消时保留上一版产物及其原代码快照绑定，不影响旧版本结构事实查询。
7. 重试始终从环境预检开始，不复用失败任务留下的未发布产物。
8. 用户取消任务后系统终止 CLI、清理临时产物并保留当前已发布产物。

#### 5.3.5 任务阶段与进度

分析任务至少包含：

1. 等待执行。
2. 环境预检。
3. 准备只读代码快照。
4. 扫描源码与识别语言。
5. 解析文件和符号。
6. 建立定义与引用。
7. 建立调用关系。
8. 写入临时产物。
9. 产物完整性和抽样校验。
10. 发布产物。
11. 清理临时文件。

任务详情至少展示任务状态、当前阶段、阶段说明、进度百分比、已处理数量、总量（可获取时）、开始时间、最近更新时间、耗时、目标代码版本、CLI 版本和脱敏日志摘要。

CLI 无法提供精确总量时可以展示不确定进度，但不得伪造百分比；至少应持续更新当前阶段和心跳时间。

#### 5.3.6 任务状态与产物状态

任务状态复用第 5.11 节统一状态机：QUEUED（排队中）、RUNNING（运行中）、CANCEL_REQUESTED（取消中）、SUCCEEDED（成功）、FAILED（失败）、CANCELED（已取消）。本节不得新增或改变状态迁移语义。

CodeGraph 产物状态描述当前仓库相对于当前代码快照的可用性：

1. 未生成：没有已发布产物。
2. 可用：已发布产物绑定当前代码快照且校验通过。
3. 已过期：存在已发布产物，但绑定的是旧代码快照。
4. 不兼容：检测到产物，但版本或 schema 不受支持，不能查询。

排队中、分析中和最近失败属于任务信息，不覆盖产物状态。例如重新分析失败后，旧产物仍可保持“可用”或“已过期”，页面同时展示最近任务失败。

#### 5.3.7 产物版本与发布

每个已发布产物至少记录：

1. 产物 ID 和仓库 ID。
2. 绑定的代码快照 ID、来源版本和内容摘要。
3. CodeGraph CLI 版本和 schema 版本。
4. 产物生成时间、发布时间、文件大小和内容摘要。
5. 语言识别与覆盖情况、文件数、符号数、引用数和调用边数。
6. 校验结果及必要的兼容性告警。

发布规则：

1. 产物发布采用不可变版本和当前指针切换，不在原目录上原地覆盖。
2. 指针切换前，所有查询继续使用旧产物；切换完成后，新查询统一使用新产物。
3. 不得在一次查询中混用两个 CodeGraph 版本。
4. 代码快照变化后，旧产物立即标记“已过期”。
5. 查询已过期产物时，源码预览和行号必须关联其绑定的旧快照，不得跳转到当前新代码。
6. 旧产物按可配置保留期延迟回收；仍被代码内容索引或历史任务引用时不得提前删除。

#### 5.3.8 结构化查询

M0 至少支持：

1. 按符号名称和类型搜索符号。
2. 获取符号定义、文件路径、语言和起止行。
3. 获取文件内的符号列表。
4. 获取符号的直接 caller 和 callee。
5. 获取符号引用位置。
6. 读取与符号行号对应的源码片段。

所有结果必须包含仓库、CodeGraph 产物版本、代码快照版本、文件路径和行号。业务功能只能通过稳定适配层查询，不得依赖 CodeGraph 原始 SQLite 表名和字段。

同名符号必须返回可区分的候选项，不得仅按名称静默选择一个结果。文件不存在、符号不存在和 CodeGraph 不可用应返回不同的业务提示。

#### 5.3.9 并发与自动串行

1. 同一仓库的代码更新、CodeGraph 分析和代码内容索引任务互斥。
2. 对同一代码快照重复触发分析时，返回现有排队中或运行中的任务。
3. 排队期间代码快照已变化时，旧任务不得分析新快照；系统应取消旧任务或明确按旧快照继续，并在完成后标记产物已过期。
4. “分析成功后建立代码内容索引”默认关闭。
5. 开启后，只有新 CodeGraph 成功发布才创建代码内容索引任务；失败、取消或发布相同产物时不得创建。
6. 自动创建的代码内容索引任务必须明确记录其上游 CodeGraph 任务和产物版本。

#### 5.3.10 异常与用户提示

至少区分以下失败类别：

1. CLI 未安装或不可执行。
2. CLI 版本不受支持。
3. 代码快照不存在、不可读或已损坏。
4. 没有可分析的受支持语言文件。
5. CLI 启动失败或非正常退出。
6. 任务超时。
7. CPU、内存或临时磁盘资源不足。
8. SQLite 写入不完整或完整性检查失败。
9. schema 不兼容或最小查询校验失败。
10. 任务被用户取消或服务重启中断。

页面展示稳定错误类别、脱敏摘要、失败阶段和建议操作。完整命令、堆栈和原始日志仅进入受保护的服务日志，不得包含仓库凭据或其他敏感配置。

#### 5.3.11 执行安全

1. 代码仓库按不可信输入处理；分析过程不得执行仓库中的构建脚本、Git hooks 或任意代码。
2. CLI 只读访问冻结的代码快照，只能写入隔离的临时产物目录。
3. CLI 进程不得继承仓库访问令牌、用户会话、模型密钥等无关敏感环境变量。
4. 默认禁止分析进程访问外部网络；确需联网的能力必须单独配置并记录。
5. 对 CLI 设置超时、并发数、CPU、内存、临时磁盘和输出文件大小限制。
6. 导入外部 SQLite 时使用只读模式完成校验，不执行其中的扩展、触发器或外部程序。

#### 5.3.12 M0 不支持

1. CodeGraph 增量分析。
2. 定时自动分析。
3. 同一仓库同时维护多个当前 CodeGraph 版本。
4. 用户任意选择未验证的 CLI 版本。
5. 跨仓库调用关系合并。
6. 在页面直接编辑 CodeGraph 原始数据。

#### 5.3.13 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| CG-01 | 仓库没有已有产物并开始分析 | 后台任务成功后发布可用产物 |
| CG-02 | 仓库包含兼容的已有产物 | 校验并复制到受管目录后发布，不直接依赖源码目录 |
| CG-03 | 已有产物 schema 不兼容 | 标记不兼容，禁止查询并提供重新分析入口 |
| CG-04 | 查询符号定义、引用、caller 和 callee | 返回绑定版本、文件和合法行号 |
| CG-05 | 同名符号查询 | 返回可区分候选项，不静默选错符号 |
| CG-06 | 代码快照更新 | 原产物标记已过期，旧版本查询仍可追溯 |
| CG-07 | 重新分析成功 | 原子切换新产物，新查询不混用旧版本 |
| CG-08 | 重新分析失败或取消 | 旧产物继续可用，最近任务显示失败或已取消 |
| CG-09 | CLI 缺失、版本错误、超时或资源不足 | 返回不同错误类别和可操作提示 |
| CG-10 | 重复触发同一快照分析 | 返回已有任务，不创建重复执行 |
| CG-11 | 无维护权限的账号触发分析 | 拒绝操作且不启动任务 |
| CG-12 | 开启自动代码内容索引 | 仅在新产物发布成功后创建绑定版本的索引任务 |
| CG-13 | 服务在分析中重启 | 任务被恢复或明确失败并允许从头重试 |
| CG-14 | 恶意仓库包含构建脚本或 Git hooks | 分析过程不执行仓库代码 |

### 5.4 代码内容索引（RAG 索引）

优先级：P0

首次交付：M0 内容索引；M1 向量索引

#### 5.4.1 功能目标

代码内容索引负责把已发布代码快照中的源码和文档切分为可追溯的 chunk，并发布为独立版本的检索产物。

索引分两层交付：

1. M0 内容索引：完成文件过滤、结构化切分、chunk 存储、浏览和关键词查询，不生成 embedding。
2. M1 向量索引：在内容索引基础上生成 embedding 和向量数据，为语义检索提供召回能力。

内容索引和向量索引必须分别展示状态。内容索引成功后，即使向量生成失败，M0 的 chunk 浏览和关键词查询仍可使用。

#### 5.4.2 前置条件与权限

1. 仓库存在当前代码快照。
2. 源代码结构化切分要求存在绑定同一代码快照且状态可用的 CodeGraph 产物。
3. 查看索引状态、浏览 chunk 和执行关键词查询至少需要仓库“只读”权限。
4. 创建、重建、取消和重试索引至少需要仓库“维护”权限。
5. 删除当前已发布索引需要仓库“管理”权限并二次确认。
6. 同仓库存在代码更新或 CodeGraph 分析任务时，代码内容索引不得并发执行。

#### 5.4.3 索引数据范围

默认纳入：

1. CodeGraph 已识别的源代码文件。
2. 测试代码。
3. README、Markdown 和仓库内 API 文档。
4. 不含敏感值的关键配置结构。
5. 超级管理员配置的其他文本文件类型。

默认排除：

1. .git、.codegraph、node_modules、dist、build、target、vendor 等依赖或生成目录。
2. 二进制、压缩包、数据库、媒体和不可识别编码文件。
3. .env、私钥、证书、凭据文件及命中敏感文件规则的内容。
4. 超过单文件大小、单行长度或总索引规模限制的文件。
5. 符号链接指向快照外部的文件。
6. 由全局或仓库排除规则命中的文件。

范围规则：

1. 全局规则由超级管理员配置；具有仓库“管理”权限的账号可以为该仓库增加排除规则，但不能取消全局强制排除项。
2. 排除规则、敏感文件规则或纳入类型发生变化后，当前内容索引标记“已过期”并提示重建。
3. 每次任务记录纳入、排除、跳过和失败的文件数量及原因分类。
4. 配置文件只索引通过敏感检测的键名和必要上下文，不得把疑似密钥值写入 chunk。

#### 5.4.4 Chunk 切分规则

源代码：

1. 优先使用 CodeGraph 的函数、方法、类、接口和模块边界切分。
2. 方法 chunk 保留所属类型、函数签名和必要的相邻声明上下文。
3. 类和方法可以形成父子 chunk，但必须记录关系，避免检索时把重叠内容当作不同证据重复引用。
4. 超长符号按最大字符数或 token 估算继续拆分，子 chunk 必须保留准确行号、父符号 ID 和顺序。
5. CodeGraph 未覆盖但允许索引的文本文件，可以按文件和固定窗口降级切分；此类 chunk 明确标记“无结构边界”。

文档：

1. Markdown 优先按标题层级和段落切分，保留标题路径。
2. 普通文本按段落和最大长度切分。
3. 代码块尽量保持完整；超长代码块拆分后记录顺序和原始行号。

通用规则：

1. 空内容、纯空白和仅包含生成标记的内容不创建 chunk。
2. chunk 大小、重叠窗口和最小长度可配置，并记录到索引版本。
3. 相同索引版本内，仓库、文件路径、符号、起止行和 chunk 类型共同确定稳定位置；内容摘要用于判断内容是否相同。
4. M0 不调用 LLM 生成文件摘要或符号摘要，避免把生成内容混入原始证据。

#### 5.4.5 Chunk 元数据

每个 chunk 至少包含：

1. chunk ID、仓库 ID 和索引版本 ID。
2. 代码快照 ID、来源版本及内容摘要。
3. CodeGraph 产物 ID。
4. 文件相对路径、语言和文件类型。
5. 符号 ID、符号名、符号类型和父符号 ID（适用时）。
6. 起止行、子 chunk 顺序和标题路径（适用时）。
7. chunk 类型、结构边界类型和证据类型。
8. 原始文本、规范化文本摘要和内容摘要。
9. 创建时间及切分规则版本。

Git 和 ZIP 统一通过代码快照 ID 追溯。Git 可附带 branch 和 commit，ZIP 可附带上传版本和摘要，但不得要求 ZIP 伪造 commit。

#### 5.4.6 M0 内容索引

M0 内容索引至少支持：

1. 按仓库、索引版本、语言、chunk 类型和路径浏览 chunk。
2. 按关键词、符号名和文件路径查询已发布 chunk。
3. 查看 chunk 原文、元数据和对应源码片段。
4. 查询文件数、chunk 总数、语言分布、类型分布和排除统计。
5. 从 chunk 跳转到其绑定代码快照的准确文件和行号。

关键词查询只读取当前已发布内容索引。查看历史任务或已过期索引时，页面必须明确展示版本，不能与当前版本结果混合。

#### 5.4.7 M1 向量索引

1. 仅对通过敏感过滤且允许发送给所选 provider 的 chunk 生成 embedding。
2. 每条向量记录绑定 chunk ID、内容索引版本、provider、模型、维度、生成时间和文本摘要。
3. 同一向量索引版本只能使用一个模型及维度，不得混用不同模型生成的向量。
4. provider、模型、维度或发送规则变化后，向量索引标记“已过期”并要求重建；内容索引不受影响。
5. embedding 支持批量调用、限流、可配置重试和失败统计。
6. 必需 chunk 未完成 embedding 时，不得把不完整向量索引发布为“可用”；已发布的上一版向量索引继续保留。
7. 外部 provider 调用仅记录 provider、模型、字符数、耗时和结果，不记录发送的明文代码正文。

#### 5.4.8 任务阶段与进度

代码内容索引任务至少包含：

1. 等待执行。
2. 校验代码快照和 CodeGraph 依赖。
3. 枚举文件。
4. 应用范围、敏感和大小过滤规则。
5. 读取符号边界并切分源码。
6. 切分文档和其他文本。
7. 写入临时 chunk 产物。
8. 建立关键词索引。
9. 生成 embedding（M1）。
10. 写入并校验向量索引（M1）。
11. 校验 chunk 路径、行号、数量和摘要。
12. 发布索引版本。
13. 清理临时数据。

任务详情至少展示任务状态、当前阶段、进度、已处理/总文件数、已生成 chunk 数、embedding 成功/失败数（适用时）、开始时间、最近更新时间、耗时、依赖版本和脱敏错误摘要。

#### 5.4.9 任务状态与索引状态

任务状态复用第 5.11 节统一状态机：QUEUED（排队中）、RUNNING（运行中）、CANCEL_REQUESTED（取消中）、SUCCEEDED（成功）、FAILED（失败）、CANCELED（已取消）。本节不得新增或改变状态迁移语义。

内容索引和向量索引分别具有：

1. 未建立：没有已发布版本。
2. 可用：已发布版本与其依赖一致且校验通过。
3. 已过期：代码快照、CodeGraph、过滤规则或模型配置发生相关变化。

失败和取消属于任务状态，不覆盖上一版索引的可用状态。页面应同时展示当前已发布版本和最近任务结果。

#### 5.4.10 版本发布与一致性

1. 每次全量索引创建不可变索引版本，不在当前版本上原地修改。
2. 索引版本绑定唯一代码快照和 CodeGraph 产物。
3. 新版本在临时区域完成构建和校验后，原子切换当前指针。
4. 发布前查询继续使用旧版本；发布后新查询统一使用新版本，不得混用新旧 chunk。
5. 代码快照或 CodeGraph 版本变化后，已发布内容和向量索引按依赖关系标记“已过期”。
6. 旧索引按保留策略延迟清理；仍被问答引用、知识卡片或历史记录引用时保留必要元数据和证据快照。
7. 每个版本记录切分配置、过滤规则版本、文件数、chunk 数、总字符数、内容摘要和发布时间。

#### 5.4.11 并发、幂等、取消与重试

1. 同一仓库同一时刻最多运行一个代码更新、CodeGraph 或代码内容索引任务。
2. 对相同代码快照、CodeGraph 产物、规则版本和索引类型重复触发时，返回已有排队中或运行中的任务。
3. 取消任务后停止后续处理并清理未发布数据，不影响当前已发布索引。
4. 重试从依赖校验开始，不复用失败任务的临时产物。
5. 服务重启后，运行中任务必须恢复或明确失败并允许重试，不得永久停留在运行中。
6. 上游 CodeGraph 产物在排队期间变化时，任务不得静默改用新依赖；应取消旧任务或按原绑定版本继续并在完成后标记已过期。

#### 5.4.12 重建与删除

1. “重建索引”始终创建新的全量版本，成功前保留当前版本。
2. 用户可选择仅重建内容索引，或在 M1 同时重建内容和向量索引。
3. 删除索引前展示将删除的内容版本、向量版本、chunk 数和影响范围并二次确认。
4. 删除当前索引不删除仓库代码快照、CodeGraph 产物和用户本地代码。
5. 删除完成后内容索引状态为“未建立”，关键词、语义检索和依赖该索引的问答不可用。
6. 存在运行中索引任务时拒绝删除，并展示阻塞任务。

#### 5.4.13 异常与用户提示

至少区分：

1. 当前代码快照不存在或不可读。
2. CodeGraph 缺失、已过期或版本不匹配。
3. 文件枚举或读取失败。
4. 敏感规则、排除规则或配置无效。
5. chunk 路径或行号校验失败。
6. 数据库、磁盘空间或索引存储写入失败。
7. embedding provider 未配置、认证失败、限流、超时或模型维度不匹配。
8. 任务被取消、服务重启中断或资源超限。

页面展示失败阶段、稳定错误类别、脱敏摘要和建议操作。单个非关键文件无法读取时可以跳过并告警；依赖不一致、产物写入失败或引用准确性校验失败必须使任务失败。

#### 5.4.14 M0 不支持

1. embedding 和向量检索。
2. 增量索引。
3. LLM 自动生成文件或模块摘要。
4. 多模型并存的向量版本。
5. 跨仓库联合索引。
6. 自动定时重建。

#### 5.4.15 M2 增量索引

增量索引只优化内容和向量索引构建，不降低版本完整性：

1. Git 来源优先使用前后代码快照的 Git diff，并以文件内容摘要复核新增、修改、删除和重命名。
2. 本地 Git 脏工作区和无法可靠获得 diff 的来源使用文件摘要比较。
3. ZIP 新版本默认全量索引；只有内容摘要清单完整且校验可靠时才允许增量处理。
4. 增量任务依赖绑定当前代码快照的可用 CodeGraph；CodeGraph 本身是否增量由 CLI 能力决定。
5. 源码文件变化后重建该文件及受结构边界影响的 chunk；删除文件必须从新版本移除全部相关 chunk 和向量。
6. 符号移动、重命名、拆分或合并时以新 CodeGraph 边界为准，不能仅按旧 symbol ID 更新。
7. 文档和普通文本按文件摘要更新。
8. 过滤规则、切分规则、embedding 模型、向量维度或 CodeGraph schema 变化时强制全量重建。
9. 变化文件比例超过可配置阈值时自动转为全量任务，并在开始前说明。
10. 增量构建仍生成新的完整逻辑索引版本，使用复制复用或等价机制；不得直接修改当前已发布版本。
11. 新版本完成数量、摘要、引用和抽样查询校验后原子发布，失败时旧版本继续可用。
12. 任务详情展示新增、修改、删除、重命名、复用和重建的文件及 chunk 数量。

增量验收：

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| INCR-01 | 修改一个函数 | 只重建受影响文件或符号，发布新的完整逻辑版本 |
| INCR-02 | 删除或重命名文件 | 新版本无孤立旧 chunk，引用仍合法 |
| INCR-03 | 修改切分规则或模型 | 自动转为全量重建 |
| INCR-04 | 增量构建失败 | 当前已发布索引保持不变 |
| INCR-05 | 变化比例超过阈值 | 明确转为全量任务 |
| INCR-06 | 本地 Git 存在脏工作区 | 使用冻结快照和内容摘要准确识别变化 |

#### 5.4.16 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| IDX-01 | 为当前快照创建内容索引 | 发布可浏览、可关键词查询的版本 |
| IDX-02 | 浏览任意源码 chunk | 可追溯到正确仓库、快照、文件、符号和行号 |
| IDX-03 | 索引 Markdown 文档 | 按标题和段落切分并保留标题路径 |
| IDX-04 | 索引超长函数 | 生成有序子 chunk，行号合法且绑定父符号 |
| IDX-05 | 文件命中敏感或排除规则 | 不写入 chunk，并在任务统计中记录原因 |
| IDX-06 | 同参数重复触发索引 | 返回已有任务，不重复执行 |
| IDX-07 | 重建过程中查询 | 新版本发布前始终读取旧版本 |
| IDX-08 | 重建失败或取消 | 临时数据被清理，旧版本继续可用 |
| IDX-09 | 代码或 CodeGraph 版本变化 | 当前索引标记已过期且仍可追溯旧版本 |
| IDX-10 | 删除当前索引 | chunk 和检索产物被删除，代码及 CodeGraph 保留 |
| IDX-11 | 无维护权限账号触发重建 | 拒绝操作且不创建任务 |
| IDX-12 | 服务在索引中重启 | 任务被恢复或明确失败并允许重试 |
| IDX-13 | M1 embedding 全部成功 | 发布与内容版本、模型和维度绑定的向量索引 |
| IDX-14 | M1 embedding 部分失败 | 不发布不完整向量版本，上一版向量索引保留 |
| IDX-15 | 外部 provider 启用 | 仅发送通过过滤的内容并记录不含正文的调用元数据 |

### 5.5 混合检索

优先级：P0

首次交付：M1

#### 5.5.1 功能目标

混合检索负责在同一仓库、同一代码版本范围内组合关键词、符号、向量和 CodeGraph 结构事实，为代码定位、代码问答和影响分析提供可解释、可追溯的候选证据。

本功能应做到：

1. 精确标识符、文件路径和错误文本能够通过关键词检索命中。
2. 自然语言功能描述能够通过向量检索命中语义相关代码。
3. 符号定义、引用和调用关系由 CodeGraph 提供。
4. 多路结果经过版本校验、归一化、去重和排序后统一返回。
5. 每条结果说明命中来源、命中原因和对应代码位置。
6. 部分检索能力不可用时安全降级，不伪装成完整结果。

#### 5.5.2 前置条件与权限

1. 用户至少具有目标仓库“只读”权限。
2. 关键词检索依赖可用的内容索引。
3. 语义检索依赖可用的向量索引。
4. 符号、引用和调用关系检索依赖可用的 CodeGraph 产物。
5. 默认只检索一个明确选中的仓库，不自动跨仓库扩展。
6. 服务端在召回前执行仓库权限校验，未授权仓库不得参与检索或计数。

#### 5.5.3 查询输入

用户可以输入：

1. 自然语言功能描述，例如“订单取消后库存如何回滚”。
2. 函数、方法、类、接口或变量等符号名。
3. 文件名、相对路径或路径片段。
4. 错误码、异常信息、日志片段或配置键名。
5. 调用关系问题，例如“谁调用 validateToken”。

查询规则：

1. 去除首尾空格后不能为空。
2. 默认最大长度为 2000 个字符，可由超级管理员调低。
3. 超长错误日志应截断或提示用户缩小范围，不得无上限写入检索日志。
4. 查询中的代码标识符、路径分隔符、大小写和特殊符号应尽量保留，不能按普通自然语言全部归一化。
5. 用户可以设置语言、路径前缀、chunk 类型、符号类型和是否包含测试代码等过滤条件。

#### 5.5.4 检索模式

系统提供：

1. 自动：识别查询意图并选择适合的召回组合。
2. 综合：同时执行当前可用的关键词、符号、向量和结构召回。
3. 关键词：只使用文本、符号名和路径匹配。
4. 语义：只使用向量相似度。
5. 符号：优先精确或模糊定位符号及其定义。
6. 调用关系：定位中心符号后查询 caller、callee 和引用。

用户可以手动选择模式。手动选择后系统不得静默切换为其他模式；所需依赖不可用时应明确提示并允许用户改用可用模式。

#### 5.5.5 查询意图

自动模式至少识别：

1. 功能定位。
2. 符号解释。
3. 文件或配置定位。
4. 调用方或被调用方查询。
5. 改动影响分析。
6. 测试定位或测试建议。
7. 架构和模块说明。
8. 错误排查。

意图识别结果应记录在检索轨迹中。无法可靠判断时使用综合模式，不得仅因分类失败返回无结果。

#### 5.5.6 召回通道

关键词召回：

1. 匹配 chunk 原文、符号名、文件名和相对路径。
2. 精确符号名、完整文件名和完整错误码优先于普通文本包含。
3. 支持大小写敏感与不敏感匹配策略；代码标识符默认同时尝试原始形式和规范化形式。

向量召回：

1. 使用当前已发布向量索引检索语义相近 chunk。
2. 只查询与当前内容索引版本绑定的向量版本。
3. 支持按语言、路径、类型和测试文件过滤。

符号召回：

1. 使用 CodeGraph 查找精确符号、模糊符号和文件内符号。
2. 同名符号返回候选集合，并结合路径、类型和查询上下文排序。
3. 未明确目标符号时不得静默选择唯一答案。

结构召回：

1. 对已确定的符号查询定义、引用、直接 caller 和直接 callee。
2. M1 默认只扩展一层关系；更深调用图由 M2 影响分析功能处理。
3. 结构事实以 CodeGraph 为准，向量或关键词结果不得覆盖相反的结构关系。

知识卡片召回（M2）：

1. 使用独立的知识卡片索引召回当前仓库已发布、已成功索引且不处于“需要复核”的当前修订。
2. 支持按标题、正文、标签、类型、模块和引用符号匹配；卡片结果必须携带卡片 ID、修订号和适用代码版本。
3. 卡片用于补充团队约定、设计背景和已审核说明，不得覆盖当前源码或 CodeGraph 的相反事实。
4. 综合模式默认启用卡片通道；纯代码、符号和调用关系模式可降低其权重或关闭，但必须在检索轨迹中记录。
5. 同主题卡片互相冲突时并列返回并标记冲突，不以相关度分数静默裁决。

#### 5.5.7 版本一致性

1. 一次检索只能使用绑定同一代码快照的内容索引、向量索引和 CodeGraph 产物；知识卡片必须明确适用于该快照或经复核仍适用。
2. 默认使用仓库当前已发布且版本一致的最新组合。
3. 某一路只有旧版本数据时，不得与当前版本结果混合；系统应停用该路并说明原因。
4. 用户显式查看历史版本时，所有召回通道都必须切换到该历史代码快照；缺少对应产物的通道标记不可用。
5. 每次响应返回实际使用的代码快照、内容索引、向量索引、CodeGraph 和知识卡片索引版本。
6. 检索执行期间当前指针发生切换时，本次请求继续使用开始时冻结的版本组合。

#### 5.5.8 合并、去重与排序

1. 各召回通道先将原始分数转换为可比较的通道内标准分，再进行融合。
2. 精确符号、完整路径和确定性结构关系优先于模糊文本匹配；知识卡片的人工审核只提高团队说明可信度，不提高其中代码结构事实的优先级。
3. 功能定位提高语义和关键词权重；调用关系提高符号和结构权重。
4. 相同仓库、快照、文件、符号和重叠行号的结果应合并，保留全部命中来源和最高价值片段。
5. 父子 chunk 或高度重叠 chunk 不得作为多条独立证据重复占满结果。
6. 同一文件结果数量应有限制，避免单个大文件淹没其他相关文件。
7. 最终排序至少考虑精确匹配、语义相关度、结构距离、版本新鲜度和结果多样性。
8. 融合权重和每路召回数量可配置，但每次响应应记录实际使用的策略版本。

M1 不承诺一个固定权重公式。权重调整不得改变结构事实本身，只影响候选展示顺序。

#### 5.5.9 检索结果

每条结果至少包含：

1. 结果 ID、来源类型、仓库 ID 和代码快照版本。
2. 源码或文档结果包含文件路径、符号名、符号类型和起止行；卡片结果包含卡片 ID、修订号、标题、类型和适用版本。
3. 代码、文档或卡片摘要；卡片正文按权限和结果展开策略返回。
4. 证据类型：关键词、语义、符号、定义、引用、caller、callee 或知识卡片。
5. 综合分、通道分和可读的命中原因。
6. 内容索引、向量索引和 CodeGraph 版本（适用时）。
7. 是否来自测试文件、是否为已过期历史版本。

结果支持分页或游标继续加载。相同查询、过滤条件、策略版本和索引版本下，结果顺序应稳定。

用户点击结果时，应打开其绑定代码快照中的源码并高亮对应行号，不得跳转到其他版本的当前文件。

#### 5.5.10 降级与无结果

1. 向量索引不可用时，自动和综合模式降级为关键词、符号和结构检索，并明确提示“语义检索不可用”。
2. CodeGraph 不可用时，降级为关键词和向量检索，调用关系模式不可执行。
3. 内容索引不可用时，关键词检索不可用；若其他通道可用，可以继续返回结果。
4. 所有可用通道均无结果时，返回“未找到匹配证据”，并建议检查仓库、版本、关键词或过滤条件。
5. 因过滤条件过严无结果时，应允许用户一键清除过滤条件，但不得自动扩大到未授权仓库。
6. 降级响应必须返回实际执行和跳过的通道及原因，不能显示为完整综合检索。
7. 知识卡片索引不可用时，M2 综合模式继续使用代码通道并提示“团队知识不可用”；不得回退到未发布、待复核或旧修订卡片。

#### 5.5.11 权限与数据安全

1. 仓库权限在查询开始和读取结果详情时都要校验。
2. 权限在检索过程中被回收时，后续详情读取应拒绝；尚未返回的流式或分页结果不得继续泄露。
3. 未授权仓库不得出现在自动补全、候选符号、结果数量、耗时明细或错误提示中。
4. 检索服务不得把代码正文发送给外部 LLM；向量查询只发送查询文本给已配置的 embedding provider。
5. 查询文本可能包含日志或敏感信息，外部发送前应用查询侧敏感检测和长度限制。
6. 检索日志默认记录查询摘要、过滤条件、命中数量、耗时和策略版本；是否保存完整查询文本由超级管理员配置。

#### 5.5.12 可观测性与性能

每次检索记录：

1. 查询意图和检索模式。
2. 实际使用、降级和跳过的召回通道。
3. 各通道耗时、召回数量、过滤数量和错误类别。
4. 合并前后候选数量、最终结果数量和策略版本。
5. 使用的代码与索引版本。

性能目标：

1. M0 单路关键词查询 P95 小于 2 秒。
2. M1 综合检索在单仓库 10 万行、返回前 20 条结果时，服务端 P95 小于 3 秒，不含外部 embedding 查询异常。
3. 单个召回通道超时不得无限阻塞整体请求；自动和综合模式可以在标记降级后返回其他通道结果。

#### 5.5.13 M1 不支持

1. 默认跨仓库联合检索。
2. 深度超过 1 的调用图扩展。
3. 基于独立模型的重排器。
4. 由 Agent 自主执行不受限的多轮检索。
5. 自动修改代码或生成补丁。
6. 用语义相似度推断不存在的调用关系。

#### 5.5.14 M2 多仓库联合检索

1. 用户可以选择多个有“只读”权限的仓库进行联合检索，默认最多 5 个。
2. 每个仓库独立冻结自己的当前代码快照和产物版本，不假设多个仓库共享 commit。
3. 未授权仓库在选择器、候选、结果和统计中均不可见。
4. 各仓库先独立召回和标准化，再执行跨仓合并和排序，避免大仓库仅因候选多而垄断结果。
5. 结果始终展示仓库名称、代码版本、文件、符号和证据类型。
6. 同名符号按仓库、路径和类型区分，不跨仓静默合并。
7. 默认保证结果仓库多样性，同时允许用户按单仓库过滤。
8. 某个仓库的向量或 CodeGraph 不可用时仅对该仓库降级，并返回分仓降级说明。
9. 多仓检索不推断跨仓调用边；只有显式配置且有确定证据的外部依赖关系可以作为补充标记。
10. M2 多仓能力先用于代码检索，不自动扩展到多仓问答和影响分析。
11. 5 个基线规模仓库、返回前 20 条时，服务端 P95 目标小于 5 秒。
12. 知识卡片通道按每个已授权仓库独立召回符合状态和适用版本的卡片，结果保留仓库与修订标识；不得把一个仓库的卡片作为另一个仓库的事实，也不得跨仓合并同名卡片。

多仓验收：

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| MSRCH-01 | 选择两个已授权仓库 | 返回带仓库标识的联合结果 |
| MSRCH-02 | 两仓存在同名符号 | 分开显示，不静默合并 |
| MSRCH-03 | 其中一个仓库向量不可用 | 仅该仓降级，其他仓正常检索 |
| MSRCH-04 | 选择未授权仓库 | 选择器不可见，直接请求被拒绝 |
| MSRCH-05 | 大小仓库联合检索 | 排序归一化并保留合理仓库多样性 |
| MSRCH-06 | 查询疑似跨仓调用 | 不伪造跨仓调用边 |
| MSRCH-07 | 多仓检索命中不同仓库知识卡片 | 按仓库分开返回，不跨仓复用、合并或覆盖代码事实 |

#### 5.5.15 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| SRCH-01 | 搜索完整符号名 | 精确符号及定义优先返回 |
| SRCH-02 | 搜索文件名或路径片段 | 返回匹配文件中的可追溯 chunk |
| SRCH-03 | 用自然语言描述功能 | 向量与关键词结果共同参与排序 |

### 5.6 代码问答

优先级：P0

首次交付：M1

#### 5.6.1 功能目标

代码问答负责把用户的自然语言问题转换为仓库内检索，并由 LLM 基于检索证据生成带引用、可复核的回答。

系统应：

1. 支持围绕一个仓库连续提问。
2. 使用混合检索获取源码、文档、CodeGraph 结构事实，以及 M2 已审核知识卡片。
3. 只基于可追溯证据回答仓库事实。
4. 区分代码事实、合理推断和未找到证据。
5. 允许用户逐条打开引用并查看对应版本的源码。
6. 在模型或部分检索能力不可用时给出明确状态，不伪造答案。

#### 5.6.2 前置条件与权限

1. 用户至少具有目标仓库“只读”权限。
2. 仓库至少存在可用内容索引；语义问答还需要可用向量索引。
3. 调用关系等结构问题需要可用且版本一致的 CodeGraph。
4. 系统已配置可用的本地或外部 LLM provider，且超级管理员已允许其处理代码上下文。
5. 用户只能创建和查看自己的问答会话；超级管理员不因角色自动获得普通用户的会话正文查看权限。
6. 仓库权限被回收后，用户不得继续读取该仓库的历史问答正文和引用。
7. 使用外部 LLM 或 embedding 时，系统级开关、仓库级外发策略和当前数据类别必须同时允许；任一层禁止即不得外发。

#### 5.6.3 会话管理

1. 创建会话时必须选择一个仓库，M1 会话不能跨仓库。
2. 会话记录创建者、仓库、标题、创建时间、更新时间和当前使用的代码版本。
3. 标题可以由首个问题自动生成，用户可以手动修改。
4. 用户可以查看自己的会话列表、继续会话和删除会话。
5. 删除会话同时删除其消息、引用和检索轨迹；已人工沉淀为知识卡片的内容不随会话删除。
6. 会话默认固定到创建时的代码快照和索引版本，保证后续追问与前文处于同一代码语境。
7. 仓库发布新版本后，会话显示“存在新版本”。用户可以继续旧版本或显式切换到最新版本。
8. 切换版本在会话中形成清晰分界，切换后的新消息使用新版本，历史消息及引用保持原版本不变。
9. 已绑定版本因保留策略被清理时，会话正文仍可查看，但相关引用应标记“证据版本已归档或不可预览”，不得跳转到当前代码冒充原引用。

#### 5.6.4 提问与追问

1. 问题去除首尾空格后不能为空，默认最大长度为 4000 个字符。
2. 支持中文和英文提问，代码标识符和路径保持原始形式。
3. 支持功能定位、符号解释、调用关系、错误排查、业务流程、测试建议和架构说明等问题。
4. 用户可选择是否包含测试代码、文档和配置文件。
5. 追问可以引用会话中的符号、文件和上一轮主题。
6. 历史对话仅用于解析“它”“这个方法”等指代，不能替代本轮仓库检索证据。
7. 当追问目标存在多个候选符号时，应要求用户选择或在回答中并列说明，不得静默选择。
8. 用户可以停止正在生成的回答；停止后保留已生成内容并标记“生成已停止”，不得显示为完整答案。

#### 5.6.5 问答流程

每次提问按以下顺序执行：

1. 校验会话归属、仓库权限和绑定版本。
2. 结合有限会话上下文重写当前问题，但保留用户原问题。
3. 识别查询意图并执行第 5.5 节混合检索。
4. 校验检索结果的仓库、快照和索引版本一致性。
5. 评估证据数量、相关性、结构事实完整性和引用有效性。
6. 证据充分时构造受限上下文并调用 LLM。
7. 对模型输出执行引用存在性、文件路径、行号和结构事实校验。
8. 校验通过后保存并返回回答；校验失败时降级为证据列表或“不足以回答”。

任一步骤失败都应保留用户问题和失败状态，允许重试，但不得保存一个看似成功的无引用答案。

#### 5.6.6 上下文构造

1. 只使用本轮冻结版本组合中的证据。
2. 每段上下文分配稳定的来源 ID，并包含文件、符号、行号和证据类型。
3. 对调用关系使用 CodeGraph 事实摘要，不让 LLM 从代码片段自行猜测边。
4. 去除父子 chunk、重叠行和多路召回造成的重复内容。
5. 在上下文预算不足时优先保留精确符号、结构事实和高相关代码，再保留补充文档。
6. 截断代码时必须明确省略位置，引用行号仍指向原文件。
7. 不把密码、令牌、私钥、被排除文件或敏感检测命中的内容发送给模型。
8. 仓库代码和文档中的提示性文字均按不可信数据处理，不能改变系统约束、调用工具或索取更多数据。

#### 5.6.7 回答结构

回答至少包含：

1. 直接结论。
2. 必要的实现流程或理由。
3. 文件、符号和行号引用。
4. 证据限制、未覆盖范围或版本说明。

根据问题类型可补充：

1. 调用方和被调用方。
2. 相关测试和建议验证范围。
3. 代码版本、调用深度和结果数量限制。
4. 明确标记的推断。

回答不得输出仓库中不存在的文件、符号、调用边或业务规则。模型常识可以用于解释通用概念，但必须与仓库事实分开，且不能在用户只询问仓库实现时替代证据。

#### 5.6.8 引用规则

每条引用至少包含：

1. 来源 ID、来源类型、仓库 ID和代码快照 ID。
2. 内容索引版本和 CodeGraph 产物版本（适用时）。
3. 文件相对路径、起止行。
4. 符号 ID、符号名和符号类型（适用时）。
5. 证据类型和对应的原始片段。
6. 来源为知识卡片时，包含卡片 ID、修订号、标题、适用版本、发布与复核状态；文件、行号和符号字段可以为空，但卡片自身引用的代码证据仍须可追溯。

引用约束：

1. 回答中的每个仓库事实必须映射到至少一个引用。
2. 一个引用必须真实存在于本轮检索结果或结构查询结果中。
3. 引用文件必须属于绑定快照，行号不得越界。
4. 调用关系引用必须来自 CodeGraph，不得仅引用语义相似代码。
5. 点击引用打开对应历史或当前代码快照并高亮行号。
6. 多个事实共用一个引用时，该引用必须能直接支持所有相关事实；否则拆分引用。
7. 推断必须明确标记“推断”，并引用作为推断基础的证据。
8. 知识卡片可以支持团队约定和设计背景；涉及当前代码实现、调用、定义或引用时，必须同时引用源码或 CodeGraph，不能只引用卡片。

#### 5.6.9 证据不足与置信度

系统从以下维度判断证据是否足够：

1. 是否找到直接相关的文件或符号。
2. 检索结果是否来自一致版本。
3. 结构问题是否存在 CodeGraph 事实。
4. 关键结论是否都有有效引用。
5. 多个证据是否互相冲突。

处理规则：

1. 完全没有有效证据时返回“未找到足够证据”，不调用 LLM 编造答案。
2. 只有部分证据时可以回答已确认部分，并明确列出无法确认的部分。
3. 证据冲突时展示冲突来源，不擅自选择结论。
4. CodeGraph 不可用时，不回答确定性的调用关系，只返回可用代码片段及限制。
5. 向量索引不可用时可以基于关键词和结构事实回答，但必须说明未执行语义检索。
6. 不向用户展示没有定义依据的虚假精确百分比；使用“证据充分、部分证据、证据不足”等等级和原因。

#### 5.6.10 模型调用与降级

1. 模型 provider 和模型由超级管理员配置，回答记录实际使用的 provider、模型和配置版本。
2. 外部模型默认关闭；启用前明确展示可能发送的查询和代码上下文范围。
3. 每次调用限制上下文字符数或 token 数、输出长度和超时时间。
4. 模型超时、限流或服务不可用时，保留检索证据并提示“答案生成失败”，允许用户查看证据或重试。
5. 重试默认复用原问题、冻结版本和已校验证据，避免同一问题因版本变化得到不可比较结果；用户可以选择“基于最新版本重新提问”。
6. 模型输出为空、格式无效或引用校验失败时不得发布为正常回答。
7. 本地模型和外部模型遵守同一证据、引用和敏感过滤规则。
8. 发起调用前展示实际执行位置“本地”或“外部”；外部调用还展示仓库外发策略和本次数据类别，策略不允许时降级到本地模型或返回明确不可用原因。

#### 5.6.11 历史记录与隐私

每条消息记录：

1. 会话、发送者、原问题和重写后的检索问题。
2. 回答正文、状态、引用和检索轨迹。
3. 绑定的仓库、代码快照及产物版本。
4. provider、模型、耗时、token 用量和错误类别。
5. 创建、开始生成和完成时间。

用户问题和回答可能包含私有代码信息：

1. 会话仅创建者本人可见。
2. 超级管理员可以查看用量和错误统计，但默认不查看会话正文。
3. 服务日志不记录完整问题、回答、代码上下文或模型原始响应。
4. 会话保留期限由超级管理员配置，用户可以提前删除自己的会话。
5. 用于质量评估或导出前必须进行权限校验和敏感处理。

#### 5.6.12 权限变化

1. 提交问题和读取回答时均校验仓库权限。
2. 生成过程中权限被回收时，应停止后续输出，不保存尚未完成的模型内容，并禁止查看引用。
3. 权限从只读提升或降低不影响问答使用；完全回收仓库权限后，该仓库会话不可访问。
4. 重新授权后，用户可以恢复访问本人历史会话，但仍受历史证据版本可用性限制。
5. 会话接口不得通过标题、摘要、计数或错误信息泄露未授权仓库内容。

#### 5.6.13 可观测性与性能

每次问答至少记录：

1. 意图识别、检索、上下文构造、模型调用和引用校验各阶段耗时。
2. 各检索通道命中数、最终证据数和降级原因。
3. 输入/输出 token、模型错误类别和是否因证据不足停止。
4. 回答状态：生成中、成功、部分回答、证据不足、生成失败或已停止。

性能目标：

1. 提交问题后 2 秒内展示“正在检索”等首个可见状态。
2. 正常模型服务下，完整回答目标小于 10 秒。
3. 用户停止生成或权限被回收后，应尽快停止流式输出和后续模型消费。

#### 5.6.14 M1 不支持

1. 跨仓库联合问答。
2. 联网搜索或使用仓库外知识回答仓库事实。
3. 上传临时附件参与单次问答。
4. Agent 自主执行命令、修改代码或调用任意外部工具。
5. 多模型自动路由和模型投票。
6. 会话共享、评论和协作空间。
7. 自动把回答写入知识库；M2 由用户人工确认后保存。

### 5.7 调用图和影响分析

优先级：P1

首次交付：M2

#### 5.7.1 功能目标

调用图用于展示符号、文件和模块之间可验证的上下游关系；影响分析用于根据这些结构事实推导修改目标后需要关注的调用方、入口、模块和测试范围。

本功能应：

1. 支持从符号、文件或模块选择分析中心。
2. 展示直接和多层 caller、callee 关系。
3. 提供从入口到目标或从目标到下游的路径。
4. 按符号、文件和模块聚合大型关系图。
5. 基于结构事实生成带证据的影响摘要和测试建议。
6. 明确区分“CodeGraph 已确认关系”和“系统推导的可能影响”。

#### 5.7.2 前置条件与权限

1. 用户至少具有目标仓库“只读”权限。
2. 仓库存在可用或用户明确选择的历史 CodeGraph 产物。
3. 源码预览需要对应 CodeGraph 所绑定的代码快照仍可访问。
4. 影响摘要如使用 LLM，还需要可用模型配置；模型不可用时仍应返回结构图和确定性统计。
5. 所有图查询、节点详情、路径和摘要都必须执行仓库权限校验。

#### 5.7.3 分析中心

用户可以选择：

1. 函数或方法。
2. 类、接口或其他类型符号。
3. 源码文件。
4. 系统根据路径规则识别的模块。

选择规则：

1. 支持从代码检索结果、问答引用、源码预览和符号搜索进入调用图。
2. 直接输入符号名时先执行符号消歧，展示路径、类型、签名和语言。
3. 同名符号不得静默选择。
4. 文件作为中心时，用户可以查看文件内符号关系或聚合后的文件级关系。
5. 模块边界由可配置路径规则或项目元数据确定；无法识别模块时只提供文件和符号级分析。
6. 每次分析固定绑定一个仓库和一个 CodeGraph 产物版本。

#### 5.7.4 查询方向和深度

支持：

1. 上游：查询直接和间接 caller。
2. 下游：查询直接和间接 callee。
3. 双向：同时查询上下游。
4. 引用：查看定义、读取或其他引用位置（CodeGraph 支持时）。

规则：

1. 默认深度为 1，M2 最大默认深度为 3，可由超级管理员调低。
2. 深度 0 仅返回中心节点。
3. 图展开必须记录每个节点距中心的最短深度。
4. 出现循环调用时保留关系边，但同一节点只创建一次，并标记环路。
5. 用户可以从任意已加载节点继续按一层展开，但不得突破全局深度和节点上限。
6. 方向切换或过滤条件变化后，应清楚区分新查询结果与已缓存图。

#### 5.7.5 图节点与关系

节点至少包含：

1. 节点 ID、仓库和 CodeGraph 版本。
2. 符号 ID、名称、类型和签名（适用时）。
3. 文件路径、起止行和语言。
4. 所属文件和模块。
5. 相对中心的方向、最短深度和聚合状态。
6. 是否为测试、入口、外部依赖或无法解析目标。

关系边至少包含：

1. 来源节点和目标节点。
2. 关系类型，例如调用、引用、实现或继承（以 CodeGraph 实际支持为准）。
3. 调用或引用发生的文件和行号。
4. 是否直接关系、是否处于环路及是否为动态分派候选。
5. 结构事实来源和 CodeGraph 版本。

没有 CodeGraph 证据的关系不得显示为确定性边。启发式关联必须使用不同关系类型和视觉标识。

#### 5.7.6 图遍历与路径

1. 多层遍历以 CodeGraph 边为准，并遵守方向、深度、过滤和节点上限。
2. 同一符号通过多条路径到达时保留必要关系边，并以最短路径作为默认定位路径。
3. 用户选择两个已加载节点时，可以查看它们之间当前图内的最短调用路径。
4. 路径中的每条边都必须可打开对应调用或引用位置。
5. 动态分派存在多个候选实现时应全部标记为候选，不得伪装成唯一运行时目标。
6. 反射、依赖注入、事件总线、消息队列或配置驱动关系无法由 CodeGraph 确认时，应在限制说明中列出。

#### 5.7.7 聚合与过滤

用户可以按以下条件过滤：

1. caller、callee 或双向。
2. 最大深度。
3. 语言、符号类型、文件路径和模块。
4. 是否包含测试代码、外部依赖和无法解析节点。
5. 关系类型。

聚合规则：

1. 支持符号级、文件级和模块级三种视图。
2. 文件级节点展示被聚合符号数和内部/外部关系数。
3. 模块级节点展示文件数、符号数和跨模块关系数。
4. 聚合不得丢失底层版本和证据；用户可以展开到文件或符号。
5. 过滤只影响当前展示和统计，不改变原始 CodeGraph 事实。

#### 5.7.8 图规模控制

1. 单次默认最大深度为 3、最大节点数为 500、最大边数为 2000，均可由超级管理员调低。
2. 达到任一上限时停止继续扩展，保留已加载结果并明确显示截断原因。
3. 优先保留距中心更近的节点、确定性关系和跨模块关键路径。
4. 高出度节点可以折叠并按文件或模块聚合，用户按需继续展开。
5. 页面不得因为部分节点超限而显示一个看似完整的影响范围。

#### 5.7.9 图形交互

1. 支持缩放、平移、适应画布、重置布局和中心节点定位。
2. 节点必须用形状、图标或文字区分类型，不能只依赖颜色。
3. caller、callee、测试、外部依赖和风险状态具有可辨识标记。
4. 点击节点显示符号详情、源码位置、直接上下游和最短路径。
5. 点击边显示关系类型、发生位置和结构证据。
6. 支持折叠/展开文件或模块聚合节点。
7. 图例、当前版本、方向、深度、过滤条件和截断状态始终可见。
8. 选中节点后可以设为新的分析中心。

#### 5.7.10 影响范围

影响分析至少输出：

1. 直接影响：目标的直接 caller、直接引用方和明确依赖者。
2. 间接影响：在指定深度内可通过结构边到达的上游节点。
3. 下游依赖：目标直接或间接调用的能力。
4. 入口影响：控制器、接口、任务、事件处理器等可识别入口。
5. 模块影响：涉及的文件和模块及跨模块关系。
6. 测试范围：直接关联测试和建议补充验证的测试模块。
7. 分析限制：深度、节点上限、未解析关系和可能遗漏的动态行为。

“被结构路径连接”表示可能受影响，不等于修改一定造成行为变化。摘要必须使用“直接依赖”“间接可能影响”等准确措辞。

#### 5.7.11 测试关联与建议

测试关联依据依次包括：

1. CodeGraph 中测试符号到目标的直接调用或引用。
2. 测试文件与被影响源码之间的明确结构路径。
3. 可配置的测试目录、命名和模块对应规则。
4. 关键词或语义相关性，仅作为补充候选。

规则：

1. 有结构证据的测试标记为“直接相关测试”。
2. 仅通过目录、命名或语义规则找到的测试标记为“建议验证”，不得宣称一定覆盖目标。
3. 未找到测试不表示没有测试，应说明当前索引和识别规则的限制。
4. 每条测试建议提供文件、符号、关联原因和证据类型。

#### 5.7.12 风险分级

影响风险使用“高、中、低、未评估”，不输出没有校准依据的精确概率。

分级至少考虑：

1. 直接调用方和入口数量。
2. 跨模块关系数量。
3. 是否位于公共接口、核心服务或高出度节点。
4. 是否存在环路、动态分派或未解析关系。
5. 是否找到直接相关测试。
6. 图是否因深度、节点或边上限被截断。

每个风险等级必须展示触发因素。风险只用于排序和提示，不替代人工代码审查。

#### 5.7.13 版本一致性

1. 图节点、关系、源码和影响摘要必须来自同一 CodeGraph 产物及其代码快照。
2. 当前 CodeGraph 已过期时，用户可以查看旧图，但页面持续显示旧版本标识。
3. 不得用当前新源码替换旧图节点的源码预览。
4. 分析过程中当前产物指针切换时，本次请求继续使用开始时冻结的版本。
5. 重新基于最新版本分析需要用户显式刷新或重新打开，不在现有图中混入新关系。

#### 5.7.14 摘要生成与证据

1. 不使用 LLM 时，系统仍可根据结构统计生成确定性影响清单。
2. 使用 LLM 时，只允许总结已加载图、测试候选和结构统计。
3. 摘要中的结构事实必须引用具体节点、关系或路径。
4. LLM 不得补充图中不存在的调用关系。
5. 证据不足、图被截断或存在未解析动态关系时必须写入限制说明。
6. 模型调用失败不影响图和确定性清单的使用。

#### 5.7.15 权限与安全

1. 图查询前、节点展开、源码预览和摘要读取时均校验仓库权限。
2. 权限在分析过程中被回收时停止后续加载，并清除客户端未授权图数据。
3. 未授权仓库的节点、名称、路径和统计不得出现在跨页面候选或最近访问中。
4. 外部模型只接收通过敏感过滤的必要图摘要和代码证据。
5. 图查询为只读操作，不得执行仓库代码或构建脚本。

#### 5.7.16 异常与降级

1. CodeGraph 不可用或不兼容时，调用图不可执行，并提供重新分析入口。
2. 中心符号不存在时返回可选候选，不创建空白图冒充成功。
3. 部分文件或源码快照已归档时，仍可展示结构元数据，但源码预览标记不可用。
4. 图查询超时或达到上限时返回已完成部分和明确截断状态。
5. 影响摘要生成失败时保留图、结构清单和测试候选。
6. 某类关系不受当前 CodeGraph 版本支持时，从筛选项中禁用并说明。

#### 5.7.17 可观测性与性能

每次分析记录：

1. 仓库、代码快照和 CodeGraph 版本。
2. 中心对象、方向、深度、过滤和聚合级别。
3. 查询节点数、边数、路径数、是否截断及原因。
4. CodeGraph 查询、聚合、测试关联和摘要生成耗时。
5. 缓存命中、错误类别和降级情况。

性能目标：

1. 深度不超过 3、节点不超过 500 时，纯结构图查询服务端 P95 小于 2 秒。
2. 首屏可以先返回中心和直接关系，再按层加载后续深度。
3. 布局渲染不计入服务端查询时间，但前端应在加载大图时保持基本交互响应。

#### 5.7.18 M2 不支持

1. 基于生产运行时链路的真实调用频率和时序。
2. 保证完整识别反射、动态代理、消息和配置驱动关系。
3. 跨仓库调用图。
4. 自动修改代码、生成补丁或自动执行测试。
5. 用 LLM 猜测并写回 CodeGraph 关系。
6. 无限深度或无限节点的全仓图加载。

### 5.8 知识沉淀

优先级：P2

首次交付：M2

#### 5.8.1 功能目标

知识沉淀用于保存代码之外的团队语境和人工确认结论，包括模块说明、FAQ、架构决策和排障记录，并将已发布、仍有效的知识纳入后续检索与问答。

本功能应：

1. 支持用户手工创建知识卡片。
2. 支持从问答、调用分析或检索结果生成待确认草稿。
3. 保存卡片版本、适用代码版本和证据引用。
4. 只有经过人工确认的已发布版本才能进入检索。
5. 代码变化后识别可能失效的卡片并要求复核。
6. 知识卡片与代码事实冲突时优先展示 CodeGraph 和源码证据。

#### 5.8.2 前置条件与权限

1. 用户至少具有仓库“只读”权限才能查看已发布知识卡片。
2. 具有仓库“维护”权限的用户可以创建卡片和编辑自己的草稿。
3. 具有仓库“管理”权限的用户可以查看和编辑全部草稿、发布、撤回、归档或删除卡片。
4. 超级管理员无需单独授权即可管理全部仓库卡片。
5. 发布卡片前必须存在可访问的仓库和明确的适用代码版本。
6. 将卡片纳入检索需要可用的知识卡片索引能力。

#### 5.8.3 卡片类型

M2 支持：

1. 模块说明：模块职责、边界、入口和关键依赖。
2. FAQ：常见问题及经确认的回答。
3. 架构决策：背景、选择、原因、限制和替代方案。
4. 排障记录：现象、原因、定位过程、解决方式和验证步骤。

卡片类型决定推荐字段和展示模板，但最终内容仍由用户确认。后续增加类型不得改变已有卡片语义。

#### 5.8.4 卡片内容与元数据

每个卡片至少包含：

1. 卡片 ID、仓库 ID、类型、标题和正文。
2. 标签和可选的模块或路径范围。
3. 创建者、当前维护者、创建时间和更新时间。
4. 当前状态、当前发布版本和修订号。
5. 基准代码快照、适用分支或上传版本。
6. 代码、文档、问答或调用图引用。
7. 来源类型：手工创建、问答转存、检索转存或影响分析转存。
8. 复核状态、最近复核人和最近复核时间。

标题去除首尾空格后不能为空，默认最大长度为 200 个字符。正文不能为空并设置可配置长度上限。

#### 5.8.5 创建方式

手工创建：

1. 用户选择仓库和卡片类型。
2. 填写标题、正文、标签和适用范围。
3. 可以通过代码检索选择文件、符号和行号作为引用。
4. 首次保存状态为“草稿”。

从现有结果创建：

1. 用户可以从代码问答、混合检索或影响分析选择“保存为知识卡片”。
2. 系统预填标题、正文、来源引用、仓库和代码版本。
3. 预填内容仅为草稿，用户必须检查和编辑后主动保存。
4. 不得因一次问答成功而自动发布或自动进入检索。
5. 原问答被删除后，卡片保留已复制的必要引用元数据；若证据版本不可用则标记不可预览。

#### 5.8.6 生命周期

卡片状态包括：

1. 草稿：仅作者和具有仓库“管理”权限的用户可见，不进入检索。
2. 已发布：对具有仓库只读权限的用户可见，发布版本校验成功后进入检索。
3. 需要复核：曾经发布，但因代码或证据变化可能失效；默认不作为问答事实证据。
4. 已归档：保留历史和版本，不进入默认列表与检索。

状态流转：

1. 新卡片从草稿开始。
2. 草稿由具有仓库“管理”权限的用户发布。
3. 编辑已发布卡片时创建新的草稿修订，旧发布版本继续可用，直到新版本成功发布。
4. 新版本发布成功后原子切换当前发布版本。
5. 已发布卡片可以撤回为草稿或归档；撤回和归档后从检索中移除。
6. 需要复核的卡片经人工确认后可以恢复已发布，或编辑形成新版本。
7. 删除需要仓库“管理”权限和二次确认；已被历史回答引用时保留最小版本与删除标记，不能让历史引用指向其他内容。

#### 5.8.7 版本与引用

1. 卡片每次保存形成递增修订，已发布修订不可原地修改。
2. 每个修订保存完整正文、元数据、引用和操作者。
3. 代码事实陈述应绑定至少一个代码或文档引用。
4. 团队约定、架构选择等无法直接由代码证明的内容标记为“团队知识”，并记录确认者。
5. 引用至少包含仓库、代码快照、文件、行号、符号和证据类型（适用时）。
6. 引用必须指向卡片发布时校验通过的证据版本，不得自动跳转到当前新代码。
7. 用户可以查看版本历史、比较修订并恢复某个历史版本为新草稿。
8. 恢复历史版本不覆盖现有历史，仍创建新的修订。

#### 5.8.8 发布校验

发布前检查：

1. 标题、正文、类型和适用版本完整。
2. 所有代码引用属于目标仓库且用户有权访问。
3. 文件存在、行号合法，符号引用能够解析。
4. 正文不包含禁止保存的密码、令牌、私钥或其他敏感值。
5. 仓库事实具有引用，团队知识具有明确标记和确认者。
6. 不存在另一个正在发布的卡片修订。

校验失败时保留草稿并逐项提示，不改变当前已发布版本。

#### 5.8.9 代码变化与复核

当仓库发布新代码快照后，系统检查已发布卡片：

1. 引用文件被删除或重命名。
2. 引用行范围内容摘要发生变化。
3. 引用符号被删除、移动或签名变化。
4. CodeGraph 关系与卡片描述的调用关系不再一致。
5. 卡片声明的适用分支或版本不包含新快照。

处理规则：

1. 命中变化条件的卡片标记“需要复核”，记录触发原因和新旧版本。
2. 需要复核的卡片仍可在卡片页面查看，但默认不进入问答证据和普通检索结果。
3. 用户可以查看变化前后的引用差异并选择确认仍适用、修改后发布或归档。
4. 人工确认仍适用时记录复核人、时间和新的适用代码快照。
5. 无法自动判断的团队知识不应无条件失效，但应在超过可配置复核周期后提醒维护者。

#### 5.8.10 知识卡片索引与检索

1. 只有状态为“已发布”且不处于“需要复核”的当前修订进入知识卡片索引。
2. 卡片按标题、正文、标签、类型、模块和引用生成可追溯知识 chunk。
3. 知识 chunk 绑定卡片 ID、修订号、仓库、适用代码版本和发布人。
4. 发布新修订时创建知识卡片索引更新任务；新修订索引成功前，旧发布修订继续参与检索，成功后原子切换。
5. 撤回、归档、删除或进入“需要复核”时先写入同步拒绝清单并立即停止新检索和问答召回，再异步清理索引；清理失败不得恢复可见性。
6. 新修订索引失败时，卡片页面显示“发布待索引”或“索引失败”，不得让半成品进入检索。
7. 检索结果明确标记“知识卡片”，不得伪装成源码或 CodeGraph 事实。
8. 卡片与源码或 CodeGraph 冲突时，结构事实和当前源码优先，并向用户展示冲突提示。
9. 默认只检索当前仓库内的卡片，不跨仓库复用。
10. 知识卡片索引与代码内容索引是独立版本；检索请求分别冻结二者版本，并记录卡片索引版本和召回策略版本。
11. M2 综合检索将知识卡片作为第五召回通道；卡片命中不得伪装成代码 chunk，也不得参与生成 CodeGraph 结构边。
12. 问答可将有效卡片用于团队约定和设计背景，但任何当前代码事实仍需源码或 CodeGraph 共同支持。

#### 5.8.11 列表、搜索与详情

卡片列表支持：

1. 按标题和正文关键词搜索。
2. 按类型、状态、标签、维护者、模块和复核状态过滤。
3. 按更新时间、发布时间和相关度排序。
4. 普通只读用户只看到已发布卡片；维护者看到自己的草稿；管理者看到仓库全部卡片。

卡片详情展示正文、状态、适用版本、引用、版本历史、维护者、发布与复核记录。点击引用打开对应代码快照和行号。

#### 5.8.12 冲突与重复

1. 标题相同不直接判定重复，但创建和发布时提示同仓库相似卡片。
2. 用户可以选择继续创建、合并到现有草稿或取消。
3. 同一主题存在多个已发布卡片且内容冲突时，在检索和问答中并列展示冲突，不静默选择。
4. 卡片不得覆盖 CodeGraph 已确认的相反调用关系。
5. 合并卡片时保留来源卡片和修订历史，不能只复制正文后删除证据。

#### 5.8.13 权限变化与删除

1. 仓库权限被回收后，用户不能查看该仓库卡片、草稿或引用。
2. 草稿作者失去维护权限后，草稿保留并由仓库管理者接管；重新授权后可按当前权限访问。
3. 停用账号不删除其卡片，维护者显示为已停用账号，仓库管理者可重新指定维护者。
4. 删除仓库时按仓库删除规则清理卡片和索引；历史审计保留最小主体标识。
5. 删除代码索引不自动删除卡片，但卡片引用和检索状态应显示不可用。

#### 5.8.14 安全与审计

1. 卡片正文、草稿、版本历史和引用均执行仓库权限校验。
2. 保存和发布前执行敏感信息检测。
3. 外部模型生成草稿时，只发送通过过滤的必要证据，生成结果仍需人工确认。
4. 服务日志不得记录完整卡片正文或引用代码。
5. 记录创建、编辑、发布、撤回、复核、归档、删除、维护者变更和索引结果。
6. 审计至少包含操作者、卡片、修订、动作、前后状态、时间和结果。

#### 5.8.15 异常与降级

1. 引用校验失败时保留草稿，不允许发布。
2. 知识卡片索引不可用时允许编辑草稿，但发布应显示“待索引”，且不得被检索。
3. 模型不可用时不影响手工创建和编辑。
4. 代码历史快照不可预览时保留引用元数据并明确提示。
5. 发布或索引过程中权限被回收时终止操作，不切换当前发布版本。
6. 并发编辑同一草稿时使用版本检查，后保存者不得静默覆盖他人修改。

#### 5.8.16 M2 不支持

1. 未经人工确认自动发布模型生成内容。
2. 多级审批、会签和复杂工作流。
3. 跨仓库共享或全局知识卡片。
4. 卡片评论、点赞和协同实时编辑。
5. 文件附件、图片和富媒体知识库。
6. 自动解决知识冲突。
7. 将知识卡片反向写入代码仓库。

### 5.9 前端界面

优先级：P0

首次交付：随 M0、M1、M2 分阶段交付

#### 5.9.1 功能目标

前端为账号、仓库、任务、检索、问答、图分析和知识沉淀提供统一工作台。界面必须真实反映后端状态、权限和版本，不得将未实现、不可用或已过期能力展示为正常可用。

#### 5.9.2 页面与里程碑

| 页面或入口 | 首次交付 | 主要能力 |
| --- | --- | --- |

未到交付里程碑的页面默认不出现在菜单中，不使用无效按钮或静态假数据占位。

#### 5.9.3 全局框架

1. 登录后显示主导航、当前账号和退出入口。
2. 代码检索、问答、调用图和知识卡片页面显示全局仓库选择器。
3. 仓库管理和账号管理不受全局仓库选择器过滤。
4. 当前仓库上下文持续显示来源类型、代码版本和 CodeGraph/索引新鲜度。
5. Git 展示 branch、commit 和工作区状态；ZIP 展示上传版本和摘要。
6. 页面刷新后保留用户有权访问的最近仓库；权限被回收时立即清除该选择。
7. 面包屑用于表达页面层级，不在多个区域重复显示同一上下文。

#### 5.9.4 导航与权限

1. 菜单按账号类型、仓库权限、里程碑开关和依赖可用性生成。
2. 超级管理员看到账号管理和全部系统设置；普通账号不显示无权入口。
3. 隐藏菜单不替代服务端授权，直接输入地址仍必须校验。
4. 无仓库授权的普通账号登录后展示明确空状态，不显示任何仓库名称或统计。
5. 权限在使用过程中变化时，页面停止后续请求、清除敏感数据并跳转到仍可访问位置。
6. 无权限、未登录、功能未交付、依赖不可用和数据为空使用不同页面状态与文案。

#### 5.9.5 版本与新鲜度

1. 所有代码、图、检索、问答和知识证据页面展示实际绑定的代码快照。
2. 产物对应旧快照时展示持续可见的“已过期”标记和目标版本。
3. 查看历史证据时不得自动跳到当前文件。
4. 仓库版本在页面使用期间更新时提示用户刷新或继续当前版本，不静默替换结果。
5. 同一页面混合展示多种产物时，必须先验证版本一致；不一致通道禁用并说明原因。

#### 5.9.6 长任务交互

1. 创建同步、分析或索引任务后立即返回任务入口，不要求用户停留在弹窗。
2. 列表和详情展示任务类型、仓库、目标版本、状态、阶段、进度、开始时间、最近更新、耗时和错误摘要。
3. 支持从详情执行当前权限允许的取消、重试和查看日志摘要。
4. 进度未知时展示阶段和活动状态，不伪造百分比。
5. 页面断开或刷新后能够重新获取真实任务状态。
6. 后台任务失败不应把上一版可用产物界面清空。

#### 5.9.7 表单与危险操作

1. 表单字段显示必填、格式、长度、帮助和内联错误。
2. 服务端错误应映射到具体字段或可操作的页面提示。
3. 凭据字段只允许写入或替换，不回显明文。
4. 页面离开有未保存内容时提示用户。
5. 删除仓库、删除索引、停用账号、重置密码、发布或撤回知识等重要操作需要确认。
6. 删除确认明确列出会删除和不会删除的数据；本地 Git 原目录必须列入“不会删除”。
7. 防止按钮重复提交；重复请求应复用已有任务或展示原操作结果。

#### 5.9.8 代码与证据查看

1. 源码查看器显示文件路径、版本、语言和行号。
2. 点击引用或检索结果后高亮准确起止行。
3. 支持复制代码片段和可追溯引用，不默认复制整文件。
4. 文件被归档或不可预览时仍展示引用元数据和明确状态。
5. 证据类型使用文字或图标区分，不能只用颜色。
6. 问答证据、检索命中和图关系均能返回对应来源页面。

#### 5.9.9 加载、空状态与错误

1. 首次加载、局部加载、无数据、无结果、无权限、依赖不可用和请求失败具有独立状态。
2. 局部区域失败不应清空其他成功区域。
3. 可重试错误提供重试入口；不可重试错误说明修复前置条件。
4. 列表翻页、过滤或刷新时保留已加载内容，避免无必要的整页闪烁。
5. 错误提示使用面向用户的摘要，不展示堆栈、SQL、绝对路径或敏感配置。
6. 所有破坏性操作完成后明确提示结果和是否可恢复。

#### 5.9.10 可访问性与适配

1. 桌面端为首要使用场景，支持宽度 1280px 及以上的完整工作台。
2. 1024px 至 1279px 支持收起导航和调整分栏；小于 1024px 至少保证登录、列表、任务状态和只读内容可用。
3. 主要操作可使用键盘完成，焦点状态清晰可见。
4. 表单控件具有可读标签，图标按钮提供文字说明。
5. 状态和风险不能仅通过颜色表达。
6. 正文、按钮和状态文字满足基本对比度要求。
7. 调用图提供列表或表格替代视图，便于无法使用图形交互的用户查看关系。

#### 5.9.11 前端安全

1. 不在浏览器持久化明文密码、仓库凭据、模型密钥或完整敏感代码上下文。
2. 页面渲染仓库文本、Markdown、日志和模型回答时防止脚本注入。
3. 外部链接默认明确提示并使用安全打开方式。
4. 退出、会话失效或权限回收后清除内存中的仓库详情、代码片段和问答数据。
5. 前端日志和错误上报不得包含完整代码、问题正文、模型响应或凭据。

### 5.10 系统设置与运行配置

优先级：P0

首次交付：M0 起分阶段交付

#### 5.10.1 功能目标

系统设置用于集中管理平台运行边界、安全策略和外部能力。配置必须可校验、可追踪，并明确影响新请求、新任务、已有产物还是需要重启。

#### 5.10.2 权限

1. 只有超级管理员可以查看和修改系统设置。
2. 普通账号不能通过页面或接口读取配置详情、连接信息和密钥掩码之外的数据。
3. 读取公开运行状态与读取敏感配置是不同权限；健康检查不得返回配置值。
4. 所有配置修改记录操作者、变更项、前后摘要、时间和结果。

#### 5.10.3 配置分组与里程碑

M0：

1. 登录安全：密码规则、会话时长、验证码和锁定阈值。
2. 路径与存储：允许根目录、受管目录、临时目录和容量告警阈值。
3. 仓库限制：ZIP、文件数、单文件、仓库总量和符号链接策略。
4. 任务资源：全局并发、单任务超时、CPU、内存、磁盘和日志上限。
5. CodeGraph：CLI 路径、受支持版本、schema 兼容矩阵和默认自动串行开关。
6. 内容索引：纳入类型、排除规则、敏感规则、chunk 大小和重叠。
7. 数据保留：临时文件、旧快照、旧产物、任务日志和安全记录保留期。
8. 备份恢复：计划频率、保留数量、备份范围、存储位置、手动备份、恢复预检和演练记录。

M1：

1. embedding provider、模型、维度、批量大小、限流和超时。
2. LLM provider、模型、上下文、输出上限、超时和外部发送开关。
3. 检索通道数量、超时、融合策略版本和查询日志策略。
4. 问答会话保留和模型调用预算。

M2：

1. 增量转全量阈值。
2. 多仓检索仓库数量上限。
3. 调用图深度、节点和边上限。
4. 知识卡片复核周期和知识卡片索引参数。

#### 5.10.4 敏感配置

1. Token、密码、私钥和模型密钥只允许新增或替换，不回显明文。
2. 页面显示是否已配置、类型、掩码、更新时间和最近验证结果。
3. 密钥清除需要二次确认，并说明受影响能力。
4. 敏感配置加密保存，密钥材料与业务数据分离。
5. 导出配置默认排除所有密文和可用于认证的值。
6. 测试连接和错误日志不得泄露凭据。

#### 5.10.5 校验与连接测试

1. 保存前执行类型、范围、路径、依赖和互斥规则校验。
2. 路径配置验证存在性、权限、磁盘空间和越界风险。
3. CodeGraph 配置验证可执行、版本和最小命令。
4. GitLab、embedding 和 LLM 配置支持独立“测试连接”。
5. 测试连接使用最小必要请求，不保存测试正文或覆盖当前有效配置。
6. 测试失败时返回稳定错误类别和脱敏摘要。
7. 关键配置可以选择“验证后保存”；验证失败不得替换当前有效配置。
8. Git、GitLab、embedding 和 LLM 自定义端点均复用远程目标网络边界策略；测试连接和实际调用分别在解析与连接阶段校验实际 IP、协议、端口、TLS 和重定向，不能通过代理或 DNS 变化绕过。

#### 5.10.6 生效范围

每个配置项标记：

1. 立即生效：影响保存后的新请求。
2. 下个任务生效：运行中任务继续使用创建时冻结的配置版本。
3. 需要重建：过滤、切分、模型或维度变化使相关索引标记已过期。
4. 需要重启：无法热更新的运行参数明确提示，保存后显示“待重启”。

规则：

1. 任务记录实际使用的配置版本。
2. 配置变化不得静默改变运行中任务。
3. 会导致重建或中断能力的修改在保存前展示影响预览。
4. 外部模型从关闭改为启用时，必须再次确认发送范围和敏感过滤。
5. 降低安全或资源保护阈值时展示风险提示。

#### 5.10.7 仓库级外发策略

1. 每个仓库设置外发策略：继承系统策略、仅本地处理、允许外部处理；新仓库默认“继承系统策略”，系统外部发送默认关闭。
2. 有仓库“管理”权限的普通账号只能把策略收紧为“仅本地处理”；只有超级管理员可以设为“允许外部处理”或把“仅本地处理”放宽。
3. 实际外发条件为：系统 provider 已启用、系统外发开关已开启、仓库策略允许、数据类别允许且敏感检测通过，缺一不可。
4. “允许外部处理”不代表所有数据可外发；embedding 仅允许规范化 chunk 或查询文本，LLM 仅允许当前请求所需的最小问题和证据上下文。
5. 检索、问答、影响分析和知识卡片生成页面在提交前展示本次使用本地或外部能力；外发时展示 provider、数据类别和仓库策略，不展示密钥。
6. 多仓请求只有所有选中仓库都允许同一外部处理时方可外发；否则整体使用本地能力或明确拒绝，不得拆分外发造成策略绕过。
7. 策略修改立即影响新请求；运行中调用按启动时冻结策略完成，但策略紧急收紧为“仅本地处理”时应取消尚未发出的后续外部调用。
8. 每次允许、阻止和降级均记录账号、仓库、provider、模型、数据类别、字符数、策略版本、结果和时间，不记录正文。

#### 5.10.8 版本、并发与回滚

1. 非敏感配置每次成功保存形成版本。
2. 多个超级管理员并发编辑时使用版本检查，后提交者不得覆盖他人修改。
3. 支持查看配置变更历史和将非敏感项恢复为历史值。
4. 回滚形成新版本，不删除历史。
5. 敏感值不支持从历史明文恢复；回滚时保持当前值或要求重新输入。
6. 配置文件或数据库写入失败时保留当前有效版本。

#### 5.10.9 异常与安全默认

1. 配置缺失或损坏时使用明确的安全默认值，不能自动启用外部发送。
2. 受管目录或临时目录不可写时禁止启动相关任务。
3. CLI 或 provider 配置失效时禁用依赖能力并提供修复入口。
4. 配置加载失败写入受保护日志并在系统状态中告警。
5. 不允许通过任意配置注入命令行参数、脚本或不受控文件路径。
6. 未知或过期配置项不得导致服务无法读取其余有效配置。

### 5.11 统一任务与错误模型

优先级：P0

首次交付：M0 起分阶段交付

#### 5.11.1 功能目标

仓库准备、代码更新、CodeGraph、内容与向量索引、知识卡片索引、清理及恢复等耗时操作统一为后台任务。所有功能复用同一状态、阶段、权限、取消、重试、日志和错误语义，功能章节只补充专属阶段和发布条件。

#### 5.11.2 任务类型与关系

任务类型至少包含：仓库创建、本地重新扫描、远程同步、ZIP 上传、CodeGraph 分析、全量内容索引、增量内容索引、向量索引、知识卡片索引、仓库删除、到期清理、备份和恢复。

每个任务记录：

1. 任务 ID、类型、仓库 ID、创建者、执行身份、优先级和创建来源。
2. 绑定的输入快照、上游产物、配置版本、凭据版本和外发策略版本。
3. 当前状态、阶段、阶段进度、总体进度、排队原因和预计可执行条件。
4. 创建、入队、开始、最后心跳、结束时间及尝试次数。
5. 上游、下游、父任务和子任务关系；自动串行任务必须可沿链路追踪。
6. 结果产物、发布结果、脱敏日志摘要、错误对象和取消信息。

#### 5.11.3 统一状态机

任务状态限定为：

| 状态 | 含义 | 是否终态 |
| --- | --- | --- |
| QUEUED | 已受理，等待资源、仓库锁或上游任务 | 否 |
| RUNNING | 已获得执行权，至少一个阶段正在运行 | 否 |
| CANCEL_REQUESTED | 已受理取消请求，正在安全停止 | 否 |
| SUCCEEDED | 所有必需阶段成功，结果按规则发布或确认无变更 | 是 |
| FAILED | 无法继续，未发布半成品并记录稳定错误 | 是 |
| CANCELED | 已安全停止，未发布未完成结果 | 是 |

规则：

1. 只允许 QUEUED 到 RUNNING/CANCELED，RUNNING 到 SUCCEEDED/FAILED/CANCEL_REQUESTED，CANCEL_REQUESTED 到 CANCELED/SUCCEEDED/FAILED 的合法迁移。
2. 取消与最终提交竞争时，以原子提交点为界；提交已完成则为 SUCCEEDED，否则清理临时结果后为 CANCELED。
3. 失败、取消或无变更均不得破坏上一版当前产物；“无变更”使用 SUCCEEDED 并记录结果类型 NO_CHANGE。
4. 任务状态和阶段不得使用自由文本代替稳定枚举；页面显示可本地化文案，但接口值保持稳定。
5. 终态不可回退。重试必须创建新任务并通过 retryOf 指向原任务，不改写原任务历史。

#### 5.11.4 阶段与进度

1. 通用阶段为准备、校验、执行、产物校验、原子发布、清理；任务类型可定义子阶段，但必须映射到通用阶段。
2. 进度为 0 至 100 的整数并注明计算口径；无法计算时返回不确定进度和已处理数量，不伪造百分比。
3. 阶段切换、进度显著变化、状态迁移和心跳持久化，页面刷新或服务重启后可恢复展示。
4. 到达 100 只表示执行完成，任务必须在发布或确认无变更后才能进入 SUCCEEDED。
5. 日志采用有序事件，包含时间、阶段、级别和脱敏消息；默认不包含源码正文、查询正文或凭据。

#### 5.11.5 并发、锁与幂等

1. 同仓库会改变代码快照或派生产物的任务使用仓库级互斥锁；只读查询不持有该锁。
2. 等待锁的任务保持 QUEUED 并返回阻塞任务 ID，不得表现为运行中。
3. 创建任务支持幂等键；同账号、同仓库、同类型、同输入版本和同幂等键返回原任务。
4. 相同操作已有非终态任务时默认返回该任务；需要强制新建的管理操作必须明确说明影响且不得绕过互斥。
5. 锁具有租约和心跳；执行者失联后由恢复器确认无活动执行实例，再释放或接管，禁止双执行。
6. 下游任务只在上游 SUCCEEDED 且结果满足发布条件时入队；上游 FAILED 或 CANCELED 时，下游记为未创建或以明确依赖错误失败，不得继续使用半成品。

#### 5.11.6 取消、重试与恢复

1. 创建者、具有仓库“维护”权限的账号和超级管理员可以取消普通仓库任务；仓库删除、恢复及系统级清理仅超级管理员可取消。
2. QUEUED 任务取消应立即进入 CANCELED；RUNNING 任务先进入 CANCEL_REQUESTED，并在安全检查点停止子进程、外部调用和后续阶段。
3. 取消超时必须标记告警并由执行器强制隔离，不能永久停留在 CANCEL_REQUESTED；默认超时由系统设置配置。
4. 只有 retryable=true 的失败提供直接重试；不可重试错误先展示修复动作，修复后由用户重新提交。
5. 重试默认冻结原输入快照和配置；用户选择“基于最新配置或代码重试”时创建新任务并明确新绑定版本。
6. 服务启动时扫描非终态任务：可安全接管则恢复，不可接管则以 TASK_WORKER_LOST 失败；不得静默重跑可能产生外部副作用的阶段。
7. 临时产物在失败或取消后由清理任务处理；清理失败不改变原任务终态，但必须告警并可追踪。

#### 5.11.7 权限与任务中心

1. 普通账号只能看到其有仓库“只读”权限的任务；只读账号可查看，维护账号可按规则触发和取消，管理账号可执行仓库配置及删除相关操作。
2. 超级管理员可查看全部任务及系统级任务，但会话正文、源码和密钥仍按各自隐私规则保护。
3. 权限回收后任务立即从该账号的列表、详情、日志和统计中消失。任务在创建时完成授权校验并转为平台受控执行身份，之后账号降权、停用或删除不自动取消任务；只有显式取消、仓库删除或依赖失效才按规则终止，避免与第 5.1.8 节“已触发任务继续执行”冲突。
4. 任务中心支持按仓库、类型、状态、创建者、时间和错误类别过滤，默认按创建时间倒序，并支持稳定分页。
5. 任务详情展示阶段时间线、版本绑定、依赖关系、重试链、取消状态、发布结果和建议动作。
6. 列表计数、排队位置、错误和耗时不得泄露未授权仓库或其他账号私有内容。

#### 5.11.8 统一错误对象与错误码

失败响应和任务错误至少包含：errorCode、category、summary、retryable、suggestedAction、requestId 或 taskId、occurredAt；可选 details 只能包含脱敏且对当前权限安全的信息。

错误类别与稳定码前缀：

| 类别 | 前缀 | 示例 | 默认可重试性 |
| --- | --- | --- | --- |
| 认证 | AUTH | AUTH_SESSION_EXPIRED | 否，重新登录 |
| 授权 | PERMISSION | PERMISSION_REPOSITORY_DENIED | 否 |
| 输入校验 | VALIDATION | VALIDATION_ZIP_LIMIT | 否 |
| 状态冲突 | CONFLICT | CONFLICT_REPOSITORY_LOCKED | 视阻塞状态 |
| 资源不存在 | NOT_FOUND | NOT_FOUND_SNAPSHOT | 否 |
| 凭据 | CREDENTIAL | CREDENTIAL_REMOTE_REJECTED | 修复后可重试 |
| 外部依赖 | DEPENDENCY | DEPENDENCY_CODEGRAPH_UNAVAILABLE | 视原因 |
| 资源限制 | RESOURCE | RESOURCE_DISK_INSUFFICIENT | 释放资源后可重试 |
| 超时 | TIMEOUT | TIMEOUT_PROVIDER | 是，受重试上限控制 |
| 兼容性 | INCOMPATIBLE | INCOMPATIBLE_CODEGRAPH_SCHEMA | 否 |
| 完整性 | INTEGRITY | INTEGRITY_ARTIFACT_MISMATCH | 否，需修复或重建 |
| 取消 | CANCELED | CANCELED_BY_USER | 否 |
| 内部错误 | INTERNAL | INTERNAL_UNEXPECTED | 视服务端判定 |

规则：

1. errorCode 是接口和自动化判断依据，发布后不得改变原语义或复用为其他含义；summary 可本地化。
2. 前端不得通过解析错误文案决定重试、跳转或权限行为。
3. 同类错误在同步接口、后台任务和审计记录中使用相同 errorCode。
4. 未知异常映射为 INTERNAL_UNEXPECTED，对用户隐藏堆栈、SQL、绝对路径和命令参数，并通过 requestId 关联受保护日志。
5. 批量或多仓操作返回总体状态和逐项错误对象，未授权项不得暴露其真实存在性。

#### 5.11.9 验收场景

| TASK-01 | 重复提交相同同步操作 | 返回同一非终态任务，不重复执行 |
| TASK-02 | 同仓库索引等待代码同步 | 保持 QUEUED，展示阻塞任务和原因 |
| TASK-03 | 取消排队任务 | 立即进入 CANCELED，未启动执行器 |
| TASK-04 | 取消运行中索引 | 先进入 CANCEL_REQUESTED，在安全点停止且不发布半成品 |

| TASK-11 | 接口与后台任务发生同类凭据错误 | 返回同一稳定错误码和一致重试建议 |
| TASK-12 | 未知内部异常 | 用户只见脱敏摘要和关联 ID，受保护日志保留诊断信息 |

## 6. 非功能需求

### 6.1 准确性与可追溯性

1. 仓库事实、代码位置和结构关系必须来自当前请求绑定的已发布产物。
2. 100% 的问答仓库事实具有有效引用；无效路径、越界行号和不存在符号为 0。
3. 调用、引用、继承等结构事实以 CodeGraph 为准，语义结果不得覆盖相反事实。
4. 检索、问答、图和知识卡片均返回仓库、代码快照和相关产物版本。
5. 新旧产物不得在一次请求中混用。
6. 证据不足、冲突、降级和结果截断必须显式说明。
7. 版本发布前执行完整性、数量、摘要和抽样引用校验。

质量基线使用第 9.2 节冻结的数据集，Java、TypeScript、Python 分语言统计，任何单一语言不得被总体平均值掩盖：

| 能力 | 指标 | 发布门槛 |
| --- | --- | --- |
| CodeGraph 定义定位 | precision、recall | 每种首批语言均不低于 95%；错误文件、越界行号为 0 |
| CodeGraph 直接引用与 caller/callee | precision | 每种首批语言均不低于 95% |
| CodeGraph 直接引用与 caller/callee | recall | 每种首批语言均不低于 90% |
| 精确符号或完整路径检索 | Top-5 命中率 | 每种首批语言均不低于 95% |
| 功能定位与自然语言检索 | Top-10 命中率 | 每种首批语言均不低于 90% |
| 问答仓库事实引用支持率 | 被证据直接支持的事实数/仓库事实总数 | 100% |
| 问答任务完成度 | 人工按固定评分规程判定可用的回答占比 | 不低于 85% |
| 证据不足拒答正确率 | 应拒答样例中正确拒答且未编造的占比 | 不低于 95% |
| 知识卡片状态隔离 | 未发布、已撤回、待复核卡片不进入默认检索或问答 | 100% |

1. 每种首批语言的 CodeGraph 与检索集合至少各 60 个独立问题，覆盖定义、引用、直接调用、同名符号、测试代码、配置和无结果样例。
2. 动态调用、反射、运行时生成代码等超出锁定 CodeGraph 能力的构造可以从结构召回率分母排除，但必须在兼容矩阵中逐项列出，并在实际结果中标记“无法静态确认”。
3. 问答评分由至少两名评审者独立执行；分歧样例仲裁后形成基线，评分规程和证据随发布归档。
4. 质量基线或样例变化必须评审并形成新版本；不得通过删除失败样例或放宽问题口径绕过回归。

### 6.2 性能

参考环境：8 核 CPU、16 GB 内存、本地 SSD、单实例服务、数据库位于同一内网；测试仓库不超过 10 万行、2 万文件、2 GB。正式验收必须记录实际硬件、数据规模、并发数和外部 provider 状态。

| 场景 | 目标 |
| --- | --- |
| 登录、会话校验 | 正常负载服务端 P95 小于 500 ms |
| 100 个仓库内的列表和详情 | 服务端 P95 小于 500 ms |
| 已发布内容索引的关键词/chunk 查询 | 前 20 条结果服务端 P95 小于 2 秒 |
| M1 四路综合检索 | 前 20 条结果服务端 P95 小于 3 秒 |
| 深度不超过 3、节点不超过 500 的结构图查询 | 服务端 P95 小于 2 秒 |
| 问答首个可见状态 | 提交后 2 秒内 |
| 正常模型服务下完整问答 | 目标小于 10 秒 |
| 任务状态查询和取消请求受理 | 服务端 P95 小于 500 ms |
| M0 全量内容索引（不含 CodeGraph） | 参考仓库目标小于 15 分钟 |
| CodeGraph 全量分析 | 参考仓库目标小于 30 分钟，最终以锁定 CLI 的基线测试为准 |

1. P95 至少基于 1000 次短请求或 30 次长任务样本计算；样本不足时必须标明。
2. 外部模型、embedding provider 和不可控网络异常不计入本地服务目标，但其等待时间必须单独记录。
3. 单个检索通道或模型超时不得无限阻塞整体请求。
4. 性能降级超过已发布基线 20% 时应在发布前说明和评估。

### 6.3 可靠性与恢复

1. 代码快照、CodeGraph、内容索引和向量索引均采用临时构建、校验和原子发布。
2. 新版本失败或取消不得破坏上一版可用产物。
3. 服务重启后运行中任务必须恢复、重新排队或明确失败，不得永久停留在运行中。
4. 使用心跳识别失联任务，并保留可从头重试的失败原因。
5. 重复提交使用幂等键或等价机制，避免重复任务和重复版本。
6. 数据库提交成功但文件发布失败，或文件发布成功但数据库提交失败时，系统能够检测并修复不一致。
7. 清理临时文件和旧版本不得阻塞当前查询。
8. 关键元数据支持定期备份和恢复演练；恢复后产物指针和文件摘要必须重新校验。
9. 默认业务元数据 RPO 不超过 24 小时，恢复账号、权限、仓库元数据、配置和可用产物指针的 RTO 不超过 4 小时。
10. 完整快照或大型索引未纳入备份时，基线规模内从源码重建到检索可用的服务恢复目标不超过 24 小时；恢复界面和运行手册必须区分“元数据已恢复”与“检索已恢复”。
11. 至少每季度执行一次恢复演练，并在平台重大升级、存储迁移或加密密钥轮换前后增加演练；记录实际 RPO、RTO、缺失项和整改结果。

### 6.4 安全性

身份与授权：

1. 除登录和必要健康检查外，所有业务接口要求有效会话。
2. 服务端对每次请求执行账号状态、账号类型和仓库权限校验。
3. 未授权仓库不得通过列表、搜索、自动补全、统计、错误或耗时信息泄露。
4. 权限回收和账号停用立即影响新请求和持续输出。

凭据与传输：

1. 密码使用专用密码哈希算法保存。
2. Git、GitLab、模型和其他访问凭据加密保存，页面和日志仅显示掩码。
3. 生产部署的登录、凭据和代码数据传输必须使用 TLS。
4. 会话凭据采用安全、不可预测和可撤销机制。

代码处理：

1. 仓库和压缩包按不可信输入处理。
2. 禁止路径穿越、越界符号链接、ZIP Bomb、设备文件和任意代码执行。
3. CodeGraph 与索引过程不执行构建脚本、Git hooks 或仓库程序。
4. 任务进程限制 CPU、内存、磁盘、超时、并发和网络。

模型与敏感信息：

1. 外部 embedding 和 LLM 默认关闭。
2. 启用前展示 provider、模型、可能发送的数据类别和过滤规则。
3. 查询、chunk、卡片和引用在外发前执行敏感检测。
4. 不向外部 provider 发送被排除文件、凭据或无关上下文。
5. 记录外发元数据但不记录明文代码正文。
6. 仓库代码、文档、卡片和检索结果中的指令均视为不可信数据，不得改变系统规则、扩大仓库范围、调用工具、读取密钥或触发网络请求。
7. 自定义 Git、GitLab、embedding 和 LLM 端点执行统一 SSRF、DNS 重绑定、TLS、重定向、代理和端口限制。

前端与接口：

1. 防止跨站脚本、请求伪造、注入、越权和不安全文件下载。
2. Markdown、日志、模型回答和仓库文本按不可信内容安全渲染。
3. 错误响应不得包含堆栈、SQL、绝对路径、密钥或内部命令。
4. 重要写操作记录操作者、目标、结果和时间。

### 6.5 可观测性

日志：

1. 使用请求 ID、任务 ID、仓库 ID 和版本 ID 关联链路。
2. 记录任务阶段、状态迁移、耗时、错误类别和重试来源。
3. 不记录密码、Token、会话、完整代码、完整问题、回答或模型上下文。
4. 用户页面只展示脱敏摘要，完整技术日志受保护。

指标：

1. HTTP 请求量、错误率和延迟。
2. 排队任务数、运行任务数、阶段耗时、成功率和取消率。
3. 文件、符号、chunk、向量、节点和边数量。
4. 检索通道耗时、命中数、降级率和无结果率。
5. 模型调用次数、token、耗时、失败率和限流次数。
6. 存储使用量、临时空间和旧版本待清理量。

告警：

1. 任务长期无心跳、连续失败或队列堆积。
2. 数据库、受管存储或临时磁盘容量不足。
3. 外部 provider 持续失败或认证失效。
4. 产物校验失败、指针不一致或引用越界。
5. 登录异常失败率或账号锁定量突增。

### 6.6 容量与扩展性

M0 单实例基线：

1. 最多 100 个仓库记录。
2. 单仓库不超过 10 万行、2 万文件、2 GB。
3. 同一仓库一次只运行一个变更或派生任务。
4. 全局任务并发数可配置，默认根据 CPU、内存和临时磁盘设置保守值。

扩展要求：

1. 仓库、任务、代码快照和产物使用稳定 ID，不依赖本地展示路径。
2. embedding provider、LLM provider、向量存储和 CodeGraph 适配层可替换。
3. 检索通道和排序策略能够独立增加并记录策略版本。
4. 任务执行与 API 服务可在后续拆分，不改变业务状态语义。
5. 超过基线规模时系统应拒绝、排队或提示调整，不得无保护地耗尽资源。

### 6.7 兼容性与部署

1. M0 默认部署为服务端和代码来源位于同一台机器的本地 Web 服务。
2. 容器部署必须显式挂载允许导入根目录、受管数据目录和 CodeGraph CLI，不能声称可访问未挂载宿主路径。
3. 支持的浏览器范围在发布前冻结，至少覆盖当前主流 Chromium 内核桌面浏览器。
4. CodeGraph CLI 和 schema 使用明确兼容矩阵，至少锁定一个受支持版本。
5. 平台升级前执行业务数据库、产物元数据和配置兼容检查。
6. 不兼容升级不得自动破坏旧产物，应提示迁移或重新分析。
7. Windows 和 Linux 的路径、进程、权限及文件锁行为均需在目标部署平台验证。

### 6.8 易用性与可访问性

1. 状态、错误和风险使用文字说明，不只依赖颜色。
2. 主要流程提供空状态、下一步建议和可操作错误。
3. 主要表单、列表、弹窗和代码引用支持键盘操作。
4. 页面使用统一术语：代码快照、CodeGraph、内容索引、向量索引、已过期、需要复核。
5. 同一状态在不同页面使用一致文案和颜色语义。
6. 时间显示用户时区，并可查看精确时间。
7. 中文为默认界面语言；代码标识符、路径和技术错误名保留原文。

### 6.9 数据保留与隐私

1. 超级管理员可配置任务日志、问答会话、旧快照、旧产物和安全记录保留期。
2. 删除和归档遵守各功能定义的引用保护规则。
3. 用户可以删除自己的问答会话；停用账号不自动删除其业务记录。
4. 备份、导出和恢复必须保持仓库权限和敏感数据保护。
5. 质量分析默认使用汇总指标；使用正文样本前需要明确权限和脱敏。
6. 数据删除完成后记录删除范围、结果和无法立即删除的受保护引用。

## 7. 数据范围

### 7.1 平台保存的数据

1. 账号、密码哈希、会话元数据、仓库授权和安全记录。
2. 仓库来源配置和加密凭据。
3. 平台受管代码快照及其版本元数据。
4. CodeGraph、内容索引、向量索引及版本元数据。
5. 任务、阶段、进度、脱敏日志摘要和错误类别。
6. 问答会话、消息、引用和检索轨迹。
7. 知识卡片、修订、引用、发布和复核记录。
8. 系统配置、排除规则、模型配置引用和运行指标。

### 7.2 纳入代码索引

1. CodeGraph 识别的源代码和测试代码。
2. README、Markdown 和仓库内 API 文档。
3. 通过敏感检测的必要配置结构。
4. 超级管理员显式允许的其他文本文件。

详细纳入、排除和切分规则以第 5.4.3 至 5.4.5 节为准。

### 7.3 永不默认索引

1. .git、.codegraph、依赖目录、构建产物和生成目录。
2. 二进制、媒体、压缩包和数据库文件。
3. .env、私钥、证书、凭据和疑似密钥内容。
4. 超过大小、数量、压缩比或编码限制的文件。
5. 越过仓库快照边界的符号链接。
6. 被全局强制排除规则命中的内容。

### 7.4 外部发送范围

1. 默认不向外部服务发送仓库代码。
2. 启用外部 embedding 后，只发送允许生成向量的规范化 chunk 或查询文本。
3. 启用外部 LLM 后，只发送当前问题和回答所需的最小证据上下文。
4. 不发送账号密码、仓库凭据、模型密钥、会话凭据和被排除内容。
5. 外发记录包含账号、仓库、provider、模型、数据类别、字符数、时间和结果，不保存明文正文。

### 7.5 删除与保留

1. 删除本地 Git 仓库记录不删除用户原目录。
2. 删除受管仓库按第 5.2.10 节执行，逻辑删除后立即停止授权访问和新查询，异步清理受管副本、快照、产物、任务、授权和缓存。
3. 历史问答和知识卡片不得成为源码无限期保留的理由；正文证据隐藏、最小审计保留、彻底清除和匿名化边界以第 5.2.10 节为准。
4. 临时上传、失败产物和取消任务数据应在可配置时间内清理，默认不超过 7 天。
5. 未删除仓库的旧快照和旧产物按保留期清理；当前指针、回滚窗口内版本和仍被有效业务记录引用的最小证据不得误删。
6. 到期清理、彻底清除和备份过期应形成可审计任务；删除中或已删除数据不得进入新索引、搜索、问答或知识卡片生成。

### 7.6 备份与恢复

1. 必备范围包括业务数据库、账号与仓库授权、加密配置、凭据密文、任务与审计元数据、受管产物元数据和备份清单。
2. 完整代码快照、CodeGraph 和大型索引是否直接备份由部署策略决定；未备份项必须标记重建来源、依赖版本、预计时长和不可重建风险。
3. 默认至少每日一次增量或完整备份，并保留最近 7 个日备份和 4 个周备份；组织策略可收紧频率和延长保留期。
4. 备份采用加密、完整性摘要和不可变清单；凭据密文保持加密，主密钥与数据备份分离保存，恢复时不得把密钥写入日志或导出包。
5. 恢复仅限超级管理员发起，执行前校验备份版本、摘要、schema 兼容性、可用空间和密钥可用性，并展示覆盖范围与停机影响。
6. 恢复在隔离目录完成校验后原子切换；失败时保留恢复前可用状态，不得形成数据库与文件指针混合版本。
7. 恢复后校验账号状态、仓库权限、当前指针、文件存在性、内容摘要、产物版本和凭据可解密性；缺失的可重建产物标记“待重建”并创建受追踪任务。
8. 逻辑删除或到期数据不得因恢复旧备份而重新对用户可见；恢复过程应用删除墓碑和保留期，过期备份按策略不可恢复地清理。
9. 恢复完成后会话凭据默认全部失效，用户重新登录；仓库权限和外发策略保持备份时状态，并在开放服务前重新执行安全校验。
10. RPO、RTO 和演练频率以第 6.3 节为最低门槛；每次演练保存备份时间、恢复点、实际耗时、校验结果和责任人。
11. 超级管理员可查看备份清单、范围、创建方式、状态、大小、摘要、恢复点和到期时间，可立即创建备份或按计划执行；失败备份不得标记为可恢复。
12. 恢复预检通过后系统进入维护模式：拒绝新业务写入和新后台任务，等待运行中写任务进入终态或由管理员取消，再冻结恢复前安全备份和当前指针。
13. 恢复完成并通过一致性、安全与权限校验后方可退出维护模式；失败时回到恢复前状态。维护模式仍提供本机健康检查、恢复任务状态和受限管理员入口。
14. 不允许为满足彻底删除而改写不可变历史备份；删除预览必须展示最晚备份到期时间。相关数据在备份到期前保持加密且不可用于业务查询，任何恢复都先应用删除墓碑。
15. 手动删除未到期备份需要二次确认，不得删除唯一满足当前 RPO 的可用恢复点；删除本身记录安全事件和清理任务。

备份恢复验收：

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| BAK-01 | 从最近备份恢复业务元数据 | 在 RPO/RTO 内恢复账号、授权、仓库和有效产物指针 |
| BAK-02 | 恢复包摘要损坏或版本不兼容 | 切换前拒绝，当前系统保持可用 |
| BAK-03 | 大型索引未纳入备份 | 明确标记待重建并创建任务，不假装检索已恢复 |
| BAK-04 | 旧备份包含后来已删除仓库 | 应用删除墓碑，仓库和源码不重新可见 |
| BAK-05 | 恢复包含加密凭据的备份 | 密钥分离使用，凭据可验证且全程无明文泄露 |
| BAK-06 | 恢复完成重新开放服务 | 旧会话失效，权限和外发策略校验通过 |
| BAK-07 | 按计划或手动创建备份 | 任务可追踪，清单记录范围、摘要、恢复点和到期时间 |
| BAK-08 | 有运行中写任务时发起恢复 | 进入预检并要求等待或取消，不能与业务写入并发切换 |
| BAK-09 | 恢复校验失败 | 保留恢复前状态和维护入口，不开放混合版本服务 |
| BAK-10 | 彻底删除的数据仍存在于未到期不可变备份 | 业务不可访问，预览显示最晚到期时间，恢复后墓碑继续阻止复活 |

## 8. 交付范围与里程碑

三个里程碑独立验收，后一个里程碑建立在前一个已通过的基础上。功能优先级表示产品重要性，首次交付里程碑决定实现顺序。

### 8.1 M0：账号、仓库与内容索引闭环

范围：

1. 本地账号登录、会话、密码和超级管理员初始化。
2. 普通账号管理及逐仓库只读、维护、管理授权。
3. 本地 Git、远程 Git、GitLab 和 ZIP 四类仓库来源。
4. 不可变代码快照、同步/覆盖、原子切换和安全删除。
5. 已有 CodeGraph 导入、CLI 首次分析/重新分析、结构查询和版本化产物。
6. 全量内容索引、chunk 浏览、关键词查询和源码定位。
7. 仓库准备、同步、CodeGraph、内容索引、删除和清理使用统一任务中心、状态机与错误码。
8. 登录、账号授权、仓库、任务、符号查询和 chunk 浏览页面。
9. M0 所需的安全、路径、资源、CodeGraph、内容索引和保留配置。
10. 临时密码、唯一管理员本机救援、安全记录检索和远程来源网络边界。
11. 备份策略、清单、手动备份、恢复预检、维护模式和恢复演练。

退出条件：

1. 第 5.1 至 5.4、5.9 至 5.11 中标记 M0 的验收用例全部通过。
2. 四类仓库各至少一个固定样例完成“导入、更新、分析、内容索引、查询、失败回滚、删除”闭环。
3. 普通账号无法访问未授权仓库，超级管理员可访问全部仓库。
4. CodeGraph 或内容索引重建失败后上一版仍可查询。
5. 关键安全、性能和恢复基线通过。
6. 仓库删除、历史证据处理、凭据替换和共享凭据解引用按规则完成。
7. 远程来源 SSRF、DNS 重绑定、TLS、SSH 指纹和凭据转发安全用例通过。
8. 备份恢复达到 RPO/RTO，恢复失败可回到原状态且删除数据不复活。

M0 不包含 embedding、向量检索、LLM 问答、多层调用图、影响摘要和知识卡片。

### 8.2 M1：混合检索与问答闭环

范围：

1. embedding provider、向量索引和模型配置。
2. 关键词、符号、向量、CodeGraph 四路检索。
3. 版本一致、可解释排序、去重和单路失败降级。
4. 单仓库代码问答、私人会话、流式状态和引用预览。
5. 证据充分性、引用校验、模型失败和敏感外发控制。
6. 代码检索和代码问答页面。
7. embedding、LLM、检索和问答相关系统设置。
8. 仓库级外发策略、外发前可见提示和阻止记录。

退出条件：

1. 第 5.5、5.6、5.9 至 5.11 中标记 M1 的验收用例全部通过。
2. 固定问题集覆盖功能定位、符号解释、调用方、错误排查和证据不足。
3. 100% 仓库事实带有效引用，无效路径和越界行号为 0。
4. 向量、CodeGraph 或模型单独不可用时按规则降级。
5. 未授权仓库和他人会话不可访问。
6. M1 性能、量化质量和外部模型安全基线通过。

M1 默认不包含跨仓检索、多层影响图、增量索引和知识卡片。

### 8.3 M2：图分析、增量更新与知识沉淀

范围：

1. 多层调用图、路径、聚合和影响分析。
2. 风险解释、测试关联和可选模型摘要。
3. 内容与向量索引增量更新。
4. 最多 5 个授权仓库的联合代码检索。
5. 知识卡片草稿、发布、版本、复核、独立知识卡片索引及第五检索通道。
6. 调用图、影响分析和知识卡片页面。
7. 增量、多仓、调用图和知识复核相关系统设置。

退出条件：

1. 第 5.4.15、5.5.14、5.7 至 5.11 中标记 M2 的验收用例全部通过。
2. 图循环、动态分派候选、节点截断和历史版本场景可正确展示。
3. 增量索引与对应全量索引的最终内容和查询结果一致。
4. 多仓结果严格执行权限隔离和仓库标识。
5. 未经人工确认或需要复核的知识卡片不进入默认问答证据，已发布卡片可追溯进入第五检索通道。
6. M2 性能、恢复和数据一致性基线通过。

### 8.4 当前不在范围

1. 企业 SSO、组织架构、用户组和自定义权限策略。
2. 跨仓库调用图、影响分析和多仓问答。
3. 生产运行时调用链、性能画像和真实调用频率。
4. 多模型自动路由、投票和复杂 Agent 工作流。
5. 知识卡片多级审批、实时协作和富媒体附件。
6. 自动修改代码、生成提交或执行测试。
7. 公网多租户 SaaS、计费和企业级合规审计平台。

## 9. 验收策略

### 9.1 验收用例来源

1. 各功能章节中的 AUTH、AM、AUD、RP、RM、CG、IDX、INCR、SRCH、MSRCH、QA、GRAPH、IMPACT、KC、UI、SET、TASK 和 BAK 编号用例是正式功能验收清单。
2. 非功能验收使用第 6 章指标。
3. 数据安全和删除验收使用第 7 章规则。
4. 每个用例记录前置数据、账号权限、操作步骤、预期结果、实际结果和证据。

### 9.2 固定测试数据

1. 四类来源各准备至少一个固定样例仓库。
2. 首批语言 Java、TypeScript、Python 各准备包含定义、引用、直接调用、循环、同名符号和测试代码的样例。
3. 准备包含 README、Markdown、配置、敏感文件、超长文件和排除目录的索引样例。
4. 准备正常 ZIP、路径穿越 ZIP、超限 ZIP、重复 ZIP 和多顶层目录 ZIP。
5. 准备模型正常、超时、限流、无效引用和空响应模拟。
6. 测试数据固定版本和预期结构事实，变更时更新基线并评审。

### 9.3 M0 端到端验收

1. 初始化超级管理员，创建普通账号并分配仓库权限。
2. 分别导入四类仓库，确认版本、凭据保护和权限隔离。
3. 对无 CodeGraph 仓库执行分析并查询符号、定义、引用和直接调用关系。
4. 构建内容索引，浏览 chunk、关键词查询并打开正确源码行号。
5. 更新代码后确认旧产物已过期，新任务失败时旧产物仍可用。
6. 服务在任务中重启后，任务恢复或明确失败并可重试。
7. 删除仓库时确认本地原目录不被修改。
8. 验证临时密码过期、唯一管理员本机救援及安全记录权限隔离。
9. 使用禁止网段、DNS 重绑定和未知 SSH 指纹样例验证远程来源在发送凭据前被拒绝。
10. 创建备份并执行成功与失败恢复，验证维护模式、权限、删除墓碑和恢复前回退点。

### 9.4 M1 端到端验收

1. 构建向量索引并执行四路综合检索。
2. 对功能定位问题返回语义和关键词证据。
3. 对调用关系问题返回 CodeGraph 结构事实。
4. 对同名符号进行消歧。
5. 问答事实全部带有效引用并可打开对应代码版本。
6. 无证据、证据冲突、向量不可用、CodeGraph 不可用和模型失败均正确降级。
7. 权限回收后停止持续输出并禁止访问历史证据。
8. 在源码、文档和卡片中放置提示注入样例，确认其仅作为数据且不能扩大上下文或触发外部动作。
8. 仓库内容中的提示注入不能改变系统约束、扩大数据范围或触发工具和网络调用。

### 9.5 M2 端到端验收

1. 展示深度 3 的调用图、环路、路径、聚合和截断状态。
2. 输出直接/间接影响、测试候选、风险因素和限制。
3. 对小范围代码变化执行增量索引，并与全量结果比对。
4. 对多个授权仓库执行联合检索，不泄露未授权仓库。
5. 从问答生成知识草稿，经人工发布后进入检索。
6. 引用代码变化后卡片进入“需要复核”并退出默认问答证据。
7. 撤回卡片并模拟索引清理失败，确认新检索和问答仍无法召回。
8. 联合检索多个仓库的卡片，确认结果不跨仓复用、合并或改变代码事实优先级。
7. 卡片撤回、归档、删除或待复核后立即退出召回，异步索引清理失败也不恢复可见性。
8. 多仓检索中的知识卡片保持仓库边界，不跨仓复用或静默合并。

### 9.6 质量基线验收

1. 使用冻结样例逐语言生成 CodeGraph 定义、引用和直接调用的期望集，自动计算 precision、recall 及无效定位数量。
2. 使用冻结查询集记录 Top-5、Top-10 命中率、实际通道、策略版本和失败样例，不允许只报告总体平均值。
3. 使用包含充分证据、部分证据、冲突证据和无证据的问题集执行问答，逐事实校验引用支持并评审任务完成度。
4. 使用已发布、草稿、撤回、待复核和互相冲突的卡片验证索引隔离、冲突展示与代码事实优先级。
5. 所有指标达到第 6.1 节门槛；未达门槛属于发布阻断，不以性能豁免或“模型随机性”为由跳过。

### 9.7 发布门槛

1. 当前里程碑 P0/P1 范围内的阻断和高优先级用例全部通过。
2. 不存在越权、明文凭据、任意代码执行、路径穿越和敏感外发漏洞。
3. 不存在发布失败破坏上一版、跨版本混用或无效引用问题。
4. 性能达到当前里程碑目标；未达标项必须有明确豁免、影响和后续计划。
5. 已知限制、配置默认值、备份恢复和升级步骤形成发布说明。

| 首批语言 | Java、TypeScript、Python，以固定样例验证实际支持质量 |
| 内容索引 | M0 启用全量内容索引和关键词查询，不生成 embedding |

| 增量索引 | M2 启用；不满足可靠变化检测时自动回退全量 |

| 备份恢复 | 业务元数据默认 RPO 24 小时、RTO 4 小时；基线规模完整检索恢复目标 24 小时 |

| 远程网络边界 | Git、GitLab、embedding 和 LLM 端点统一执行 SSRF、DNS、TLS、重定向、代理和端口限制 |

## 12. 术语表

| 术语 | 定义 |
| --- | --- |
| 仓库 | 平台中的稳定代码资产记录，具有唯一 ID、来源类型和权限 |
| 代码来源 | 本地 Git、远程 Git、GitLab 或 ZIP |
| 代码快照 | 某一时刻冻结、不可变、可计算摘要的代码内容 |
| 当前代码版本 | 仓库当前指针指向的代码快照 |
| 来源版本 | Git 的 branch/commit/工作区摘要，或 ZIP 的上传版本和内容摘要 |
| CodeGraph 产物 | 绑定一个代码快照、通过兼容与完整性校验的结构化事实版本 |
| 内容索引 | 绑定代码快照和 CodeGraph 的 chunk、元数据及关键词检索版本 |
| 向量索引 | 绑定内容索引、embedding provider、模型和维度的向量版本 |
| 当前产物 | 对某类产物通过原子发布后供新请求默认使用的版本 |
| 已过期 | 产物仍可使用，但依赖的代码或配置已不是当前版本 |
| 任务 | 一次同步、分析、索引、发布或清理执行，具有独立状态和阶段 |
| 任务终态 | SUCCEEDED、FAILED 或 CANCELED；进入后不可回退，重试形成新任务 |
| 错误码 | 跨接口、后台任务和审计保持稳定语义的机器可读错误标识 |
| 结构事实 | 由 CodeGraph 提供的定义、引用、调用、实现或继承关系 |
| chunk | 从源码或文档切分出的最小可检索、可追溯内容单元 |
| 证据 | 支持检索结果、回答或知识结论的源码、文档、结构关系或人工确认知识 |
| 引用 | 证据的可定位描述，包含仓库、版本、文件、符号和行号等信息 |
| 知识卡片 | 经人工维护的模块说明、FAQ、架构决策或排障记录 |
| 知识卡片索引 | 独立于代码内容索引、只包含可检索当前发布修订的版本化产物 |
| 需要复核 | 已发布知识因代码或证据变化而暂停作为默认问答证据的状态 |
| 仓库外发策略 | 仓库对外部 embedding 或 LLM 处理的继承、仅本地或允许外部约束 |
| 逻辑删除 | 立即停止业务可见性和新使用、等待异步清理和最终清除的删除阶段 |
| 审计墓碑 | 删除后保留的不可反推源码或身份正文的最小操作与计数记录 |
| 维护模式 | 恢复期间暂停普通业务访问和写任务、仅开放受限恢复与健康检查的运行状态 |
| RPO | 发生故障时允许丢失的数据时间窗口上限 |
| RTO | 发生故障后恢复到约定服务状态的时间上限 |
| 降级 | 某能力不可用时，明确跳过该能力并使用仍可用通道返回受限结果 |
