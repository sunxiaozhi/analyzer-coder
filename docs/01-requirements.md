# 代码智库系统需求规格

版本：v2.1
日期：2026-07-24
状态：核心功能与业务闭环基线

## 1. 产品目标与范围

### 1.1 产品目标

面向接手陌生代码库的开发者，把代码接入、版本化分析、检索、问答、图分析和知识沉淀串成可追溯闭环：

1. 仓库接入后 10 分钟内获得首个可引用结果。
2. 30 分钟内理解项目用途、启动方式、核心模块、关键调用链、测试入口中的至少三项。
3. 任何代码结论均可回到确定的仓库、快照、文件、符号和行号。

系统以代码快照为事实边界：PostgreSQL（关系型数据库）/pgvector（向量扩展）保存业务数据和检索索引；CodeGraph（代码结构图谱）提供结构事实；LLM（大语言模型）只解释已验证证据；人工知识补充代码无法完整表达的业务信息。

### 1.2 交付范围

| 阶段 | 交付结果 |
| --- | --- |
| M0（基础能力） | 账号与权限、仓库与快照、统一任务、CodeGraph、内容索引、系统设置、备份恢复 |
| QV1（快速价值版） | 快速开始、一键准备、项目画像、五个快捷动作、问答增强、Token（模型令牌）流式输出、跨页联动 |
| M1（增强能力） | 向量索引、混合检索、完整单仓问答、入门总览、学习路径、环境预检、基础场景链路 |
| M2（高级能力） | 增量索引、多仓检索、调用图、影响分析、知识卡片、业务域地图、变化摘要、团队沉淀 |

### 1.3 不在范围

1. 自动修改代码、创建分支、提交代码或创建 PR（合并请求）。
2. 替代 IDE（集成开发环境）、代码托管平台或 CI/CD（持续集成与持续交付）。
3. SaaS（软件即服务）多租户、计费、企业 SSO（单点登录）和组织架构。
4. 训练私有代码模型。
5. 自动执行仓库脚本、Git hooks（钩子）、README（项目说明）命令、构建或测试；仅允许管理员发布的受控检查。

### 1.4 中英文表达规范

1. 业务状态、角色、事件和策略采用“`英文编码`（中文含义）”格式。
2. 接口字段、配置键、协议名和验收编号保留英文，首次出现时补充中文说明。
3. 中文含义用于产品和验收理解，英文编码仍是接口、数据库和日志中的唯一值。

| 英文术语 | 中文含义 |
| --- | --- |
| CodeGraph | 代码结构图谱 |
| LLM（Large Language Model） | 大语言模型 |
| Token | 模型令牌/增量生成片段 |
| snapshot | 代码快照 |
| artifact | 派生产物 |
| staging | 暂存区 |
| chunk | 代码文本块 |
| embedding | 向量化表示 |
| Provider | 外部能力提供方 |
| schema | 数据结构定义 |
| capability | 服务端能力标识 |
| API（Application Programming Interface） | 应用程序接口 |
| SQL（Structured Query Language） | 结构化查询语言 |
## 2. 全局规则

1. **版本一致**：事实和产物绑定 `repositoryId + snapshotId + artifactVersion`，一次查询不得混用快照。
2. **原子发布**：快照和产物完整校验后才发布；失败、取消、并发冲突或重启不覆盖当前版本。
3. **事实分级**：代码正文、CodeGraph 结构事实、人工知识、模型内容分别标识。
4. **证据优先**：无有效证据时明确拒答；部分证据只回答可确认部分；结构关系只能来自 CodeGraph。
5. **最小权限**：列表、详情、任务、查询、历史、下载、引用跳转均按当前权限校验。
6. **即时撤权**：停用、撤权或删除后，入口、已加载正文、历史和流式输出立即停止。
7. **敏感保护**：密码、验证码答案、会话、凭据、密钥不得明文存储、回显、写日志或进入模型上下文。
8. **统一任务**：耗时写操作均具备状态、进度、取消、重试、重启恢复和审计。
9. **幂等补偿**：重复请求不产生重复非终态任务；失败临时数据和孤儿文件可补偿清理。
10. **受管边界**：平台只清理受管数据，不修改或删除本地 Git 原目录。

## 3. 角色、状态与数据边界

### 3.1 权限模型

| 主体 | 能力 |
| --- | --- |
| 超级管理员 | 账号、全局审计、系统设置、共享凭据、备份恢复、全部仓库治理 |
| 普通账号 | 登录、个人改密、创建仓库、访问本人拥有或被授权的仓库 |
| `READ`（只读） | 查看仓库、任务、已发布产物、检索、问答、图和已发布知识 |
| `MAINTAIN`（维护） | READ（只读）+ 同步、分析、索引、维护草稿 |
| `MANAGE`（管理） | MAINTAIN（维护）+ 编辑非敏感配置、发布知识和入门内容 |
| `OWNER`（所有者） | MANAGE（管理）+ 成员授权、专用凭据、所有权转移、删除仓库 |

每个未删除仓库有且仅有一个 OWNER，创建者自动成为 OWNER；OWNER 不写入普通授权表；MANAGE 不可转授权限；接口返回服务端计算的 `relationship`（仓库关系）和 `capabilities`（能力集合）；不得停用或降级最后一个启用的超级管理员。

### 3.2 对象状态

| 对象 | 状态 |
| --- | --- |
| 账号 | `PASSWORD_CHANGE_REQUIRED`（需修改密码）、`ENABLED`（已启用）、`LOCKED`（已锁定）、`DISABLED`（已停用） |
| 仓库 | `PREPARING`（准备中）、`READY`（就绪）、`AUTH_ERROR`（认证异常）、`DELETING`（删除中）、`DELETED`（已删除）、`FAILED`（失败） |
| 快照 | `PREPARING`（准备中）、`PUBLISHED`（已发布）、`RETIRED`（已退役）、`DELETED`（已删除） |
| 产物 | `ABSENT`（不存在）、`BUILDING`（构建中）、`PUBLISHED`（已发布）、`STALE`（已过期）、`FAILED`（失败）、`DELETING`（删除中） |
| 任务 | `QUEUED`（排队中）、`RUNNING`（运行中）、`CANCEL_REQUESTED`（已请求取消）、`SUCCEEDED`（成功）、`FAILED`（失败）、`CANCELED`（已取消） |
| 知识卡片 | `DRAFT`（草稿）、`PUBLISHED`（已发布）、`NEEDS_REVIEW`（待复核）、`ARCHIVED`（已归档） |
| 知识附件 | `UPLOADING`（上传中）、`QUARANTINED`（隔离扫描中）、`READY`（就绪）、`REJECTED`（已拒绝）、`DELETING`（删除中） |
| 备份 | `CREATING`（创建中）、`READY`（就绪）、`RESTORING`（恢复中）、`FAILED`（失败）、`EXPIRED`（已过期） |
| LLM 连接 | `UNCONFIGURED`（未配置）、`UNTESTED`（未检测）、`AVAILABLE`（可用）、`DEGRADED`（部分能力异常）、`UNAVAILABLE`（不可用） |

任何 `current*` 指针只能指向已发布对象。

### 3.3 快照、产物与存储

1. CodeSnapshot（代码快照）是确定来源版本的完整只读副本，发布后不可修改。
2. 更新先在 staging（暂存区）生成候选快照，成功后原子切换 `currentSnapshotId`。
3. CodeGraph、内容/向量/知识索引是快照的派生产物；新快照发布后旧产物标记 `STALE`。
4. 产物记录仓库、快照、输入摘要、工具/模型版本、配置版本、时间和状态。
5. PostgreSQL 保存业务数据；pgvector 同库启用；Flyway（数据库迁移工具）负责迁移；生产环境不得使用内存存储替代。
6. 知识附件二进制保存在受管文件系统，不保存为数据库大对象。

```text
APP_MANAGED_DATA_ROOT/
├── repositories/{repositoryId}/
│   ├── working-copy/
│   ├── snapshots/{snapshotId}/content/
│   ├── artifacts/codegraph/{snapshotId}/{artifactId}/project/.codegraph/
│   ├── artifacts/indexes/{snapshotId}/{indexId}/
│   └── knowledge/objects/{digestPrefix}/{sha256}
├── staging/{operationId}/
└── backups/{backupId}/
```

生产环境必须配置受管根目录；启动时校验绝对路径、权限、容量和目录嵌套；容器必须显式挂载受管目录和允许导入的本地目录。

## 4. 端到端闭环

### 4.1 主价值链路

```text
登录 → 接入来源并发布快照 → 构建 CodeGraph/内容索引
→ 快速画像/检索/问答 → 查看版本化证据 → 调用与影响分析
→ 人工发布知识 → 新快照触发产物过期和知识复核
```

每一步只消费已发布的上游结果；中间失败不回滚旧版本。

### 4.2 关键控制链路

- 更新：冻结输入 → staging 获取完整代码 → 校验 → 摘要比较 → 发布快照 → 标记旧产物过期 → 按需重建。
- 权限：授权 → 入口可见 → 操作鉴权 → 查询/历史二次鉴权 → 回收后立即停止 → 审计留痕。
- 删除：影响预览 → 锁与任务检查 → 二次确认 → 逻辑删除与撤权 → 异步清理 → 历史保留处理 → 墓碑。
- 恢复：预检 → 维护模式 → 恢复前备份 → 隔离恢复 → 完整性/权限/墓碑校验 → 原子切换 → 撤销会话 → 重建产物。

## 5. 核心功能

每项功能均按“权限与入口、处理、产物、异常”验收。

### F01 身份与会话（M0）

- 空库从环境变量创建唯一初始超级管理员，首次登录强制改密。
- 登录失败统一提示；连续失败触发持久化验证码和临时锁定。
- 密码 8–64 位、至少三类字符、不等于用户名且不命中弱密码表；PBKDF2-SHA256（基于 SHA-256 的密码派生算法）和独立盐。
- 使用服务端随机会话、HttpOnly Cookie（禁止脚本读取的会话凭据）、CSRF（跨站请求伪造）防护、空闲和绝对超时。
- 改密、重置、停用、安全恢复、角色降级后撤销相关会话。
- 唯一管理员救援仅允许本机用部署密钥生成一次性令牌并审计。

验收：`AUTH-01..09`。

### F02 账号、授权与审计（M0）

- 超级管理员新增、编辑、启停、解锁、重置账号；临时密码仅显示一次、24 小时有效、首次使用强制修改。
- 账号编辑仅允许显示名称和平台角色，携带版本号；无变化幂等，冲突不覆盖。
- 停用 OWNER 前预览仓库、空间和任务，并在同一事务完成全部所有权转移，否则保持启用。
- OWNER/超级管理员可授予 READ、MAINTAIN、MANAGE；请求携带 `ownershipVersion`，重复授权幂等。
- 所有权转移需目标启用、仓库无治理冲突并二次确认；同名冲突时重命名与转移原子完成；明确旧 OWNER 后续权限。
- 审计登录、账号、授权、所有权、凭据、配置、备份、恢复、删除；超级管理员看全局，OWNER 只看本人仓库治理，普通账号只看本人登录信息。
- 审计仅记录对象、字段、版本、结果和关联 ID，不记录敏感值或正文。

验收：`AM-01..10`、`AUD-01..02`、`RP-01..18`。

### F03 仓库创建与来源（M0）

- 启用账号均可创建并成为 OWNER；创建前校验来源、名称、配额、容量、并发和幂等键。
- 名称为 1–100 字符，同一 OWNER 下规范化唯一；同一来源和分支只登记一次，无权用户只收到通用冲突。
- 仓库、OWNER、首个快照同时可见；失败不留下可查询半成品。
- 默认个人上限：20 个仓库、2 个并行准备任务、20 GiB 受管数据；超级管理员仍受系统硬上限。

| 来源 | 输入 | 版本 | 更新 |
| --- | --- | --- | --- |
| 本地 Git | 白名单绝对路径 | branch、commit、工作区摘要 | 重新扫描 |
| 远程 Git | HTTPS（安全超文本传输）/SSH（安全外壳）URL（资源地址）、分支、凭据 | branch、commit | 同步 |
| GitLab | 服务地址、项目、分支、Token | branch、commit | 同步 |
| ZIP（压缩包） | 文件、可选源码根 | 上传序号、ZIP/内容摘要 | 重新上传 |

- 本地 Git 只读，不执行 pull、checkout、reset 或写操作。
- 远程来源校验协议、端口、DNS（域名系统）、实际 IP（网络地址）、TLS（传输层安全）、重定向和 known_hosts；禁用 hooks、ext 协议和交互提示。
- ZIP（压缩包）禁止绝对路径、穿越、链接、设备文件、嵌套压缩和压缩炸弹，并限制大小、数量、解压量、深度和超时。
- 来源类型、路径、URL、GitLab 项目和 ZIP 身份创建后不可编辑。

### F04 仓库编辑、凭据、更新与删除（M0）

- MANAGE 及以上可编辑名称、500 字符内描述和 Git 默认分支；名称/描述变化不创建快照。
- 分支变化通过任务在 staging 验证候选快照，成功后原子更新配置和快照；请求携带 `repositoryVersion`。
- 同步、扫描、上传生成完整候选版本；无变化直接返回；失败保留旧快照。
- 凭据独立加密且密钥分离；OWNER 管专用凭据，超级管理员管共享凭据，MANAGE 仅使用/测试。
- 凭据替换先验证后切换，任务使用冻结版本；认证失败进入 `AUTH_ERROR`（认证异常），当前快照仍可读。
- 仅 OWNER/超级管理员可删除；运行写任务或治理操作存在时拒绝。
- 逻辑删除立即撤权；异步清理受管数据，失败保持 `DELETING`（删除中） 重试；不删除本地原目录，ID 不复用。

验收：`RM-01..33`。

### F05 统一任务与错误（M0）

- 仓库准备/更新、CodeGraph、索引、附件处理、删除、备份恢复均使用统一任务。
- 任务冻结仓库、快照、上游产物、配置、凭据和外发策略；同仓库写任务使用租约、心跳和互斥锁。
- 持久化阶段、进度、心跳和脱敏事件；刷新后恢复真实状态。
- 排队任务直接取消，运行任务在安全点取消；发布与取消只允许一个合法终态。
- 重试创建新任务并记录 `retryOf`；重启后接管，无法接管则以 `TASK_WORKER_LOST`（任务执行器失联）失败。
- 撤权后平台可安全完成任务，但原用户立即失去可见性；删除与所有权转移使用治理锁互斥。
- 错误统一返回稳定错误码、类别、脱敏说明、关联 ID、可重试性和建议动作；前端不解析自由文本。

验收：`TASK-01..15`。

### F06 CodeGraph（M0）

- MAINTAIN 及以上可构建/更新/重试；READ 只看已发布结果。
- 已有 `.codegraph` 复制到独立副本后校验，不直接使用源码目录产物。
- 阶段：准备 → CLI（命令行工具）检测 → 分析 → schema（数据结构）校验 → 统计 → 发布 → 清理；禁止执行仓库代码、hooks 和构建脚本。
- 产物绑定快照、CLI 和 schema；相同仓库/快照/构建类型只允许一个非终态任务。
- 支持符号候选、定义、引用、直接 caller/callee 和证据位置；同名符号必须让用户选择。
- 缺失或失败时保留旧图并明确降级，不得用相似度伪造结构关系。

验收：`CG-01..16`。

### F07 内容、向量与增量索引（M0/M1/M2）

- 内容索引只读已发布快照，默认处理源码、配置、SQL、Markdown、纯文本；排除二进制、依赖、构建产物、`.git`、`.codegraph`、`.env` 和疑似密钥。
- 优先按符号切分，失败时按段落；chunk（代码文本块）保存仓库、快照、文件、语言、符号、行号、摘要、父子关系和切分器版本。
- 临时版本通过数量、摘要、引用校验后原子发布。
- 向量索引独立发布；embedding（向量化）部分失败不影响关键词检索且不替换旧向量版本。
- 外部 embedding（向量化服务）默认关闭，只发送通过策略和敏感扫描的最小文本。
- 增量索引比较冻结快照的增、改、删、重命名；规则/模型变化、差异不可靠或变化超阈值时转全量。
- 删除索引不删除快照或 CodeGraph。

验收：`IDX-01..15`、`INCR-01..06`。

### F08 混合与多仓检索（M1/M2）

- 单仓支持关键词、符号、向量、CodeGraph 四路召回；M2 增加已发布知识通道。
- 根据查询意图选择通道，但意图不生成事实；所有通道必须绑定同一快照。
- 按仓库、快照、文件、行号、摘要去重，并返回片段、分数、命中通道、排序解释和版本化跳转。
- 单路超时不阻塞其他通道；无结果返回已执行通道、降级项和收窄建议。
- M2 一次最多检索 5 个有权仓库；按仓归一化，同名符号不跨仓合并，不生成跨仓调用边。

验收：`SRCH-01..17`、`MSRCH-01..07`。

### F09 代码问答与流式输出（QV1/M1）

- 会话绑定账号、单仓和起始快照，支持新建、重命名、删除、历史恢复；普通账号只看本人会话。
- 每轮重新鉴权、检索和校验证据；有限历史仅解析指代，旧回答不作为新事实。
- 引用保存仓库、快照、文件、符号、行号、摘要和排序；非法引用不得发布。
- 提供六种模式、五个可编辑快捷问题、证据篮、建议追问、带引用复制和知识草稿保存。
- 回答结构为结论、实现位置、流程、限制/未知、下一步；事实句必须有引用，不显示虚假可信度百分比。
- 无证据不调用模型；外部 LLM 需同时满足全局、仓库、数据类别和敏感扫描策略。
- QV1 支持一个 OpenAI-compatible Provider（兼容 OpenAI 协议的模型提供方）；不可外发时降级为 `deterministic-local`（确定性本地模式）。
- SSE（服务端事件流）顺序：`accepted`（已受理） → `retrieving`（检索中） → `evidence_ready`（证据就绪） → `generating`（生成中，包含 `delta` 增量片段，可重复） → `validating`（校验中） → `completed`（已完成）；异常终态为 `insufficient_evidence`（证据不足）、`failed`（失败）、`stopped`（已停止）。
- `delta`（增量内容）仅为草稿，只有校验后的 `completed`（已完成）结果进入成功历史；停止、断线、重试、超时、限流均有确定状态。
- 撤权、停用、删除、会话失效或策略收紧时立即终止流；历史回答始终打开原快照。

验收：`QA-QV-01..12`、`QA-STREAM-01..10`、`QA-01..19`。

### F10 调用图与影响分析（M2）

- 用户先选精确符号，再选上游/下游/双向；默认深度 1，默认最大深度 3。
- 节点、边均保存版本和证据；保留循环边，动态分派展示候选。
- 支持符号、文件、模块聚合并展开；超限返回部分图和截断原因。
- 影响区分直接、间接和入口影响；测试区分结构关联与命名建议。
- 风险展示影响规模、入口、跨模块、核心路径、测试缺失、截断和未解析关系等构成。
- LLM 只总结已加载图；失败不影响确定性结果；历史图跳转原快照。

验收：`GRAPH-01..10`、`IMPACT-01..07`。

### F11 知识卡片与附件（M2）

- 类型包括模块说明、业务规则、技术决策、接口约定、FAQ（常见问题）、变更知识。
- MAINTAIN 维护草稿，MANAGE 及以上发布/撤回/归档，READ 只读已发布修订；生成内容不得自动发布。
- 发布前校验标题、Markdown、引用、适用版本和全部附件状态；新修订及知识索引成功后才替换旧修订。
- 引用因代码变化失效时进入 `NEEDS_REVIEW`（待复核）并退出新召回；恢复历史会创建新草稿；代码事实与知识冲突时以代码为准。
- Markdown 使用安全 CommonMark/GFM（通用 Markdown/扩展 Markdown）子集；服务端统一生成纯文本、消毒 HTML、渲染版本和摘要；正文最大 1 MiB。
- 内部文件使用 `knowledge-attachment://{attachmentId}` 并在访问时重新鉴权。
- 图片允许 PNG/JPEG/WebP/GIF；附件允许 PDF/TXT/MD/CSV/JSON/DOCX/XLSX/PPTX；拒绝危险或可执行类型。
- 校验扩展名、MIME（媒体类型）、魔数、安全解码、图片尺寸和恶意内容；生产扫描不可用时拒绝发布。
- 默认单图 10 MiB、附件 50 MiB、每修订 20 个且合计 200 MiB；按仓库 SHA-256 去重，无引用且过宽限期后才删除。
- 附件正文不进入检索或 LLM，仅索引文件名、说明、替代文本、MIME 和大小。

验收：`KC-01..31`。

### F12 系统设置与备份恢复（M0–M2）

- 仅超级管理员访问全局设置；配置按存储、网络、任务、安全、索引、模型、检索、CodeGraph、保留、备份分组。
- 配置版本化并乐观锁；运行任务使用冻结版本；敏感值加密、掩码且不从历史明文恢复。
- 路径和外部端点先校验/连接测试，成功后切换；仓库外发策略为 `INHERIT`（继承全局策略）、`LOCAL_ONLY`（仅本地）、`ALLOW_EXTERNAL`（允许外发），普通账号只能收紧。
- 语义配置变化使相关产物标记为 `STALE`（已过期）。

#### F12.1 LLM 配置

- 模型设置支持 `deterministic-local`（确定性本地模式）和一个启用的 `OPENAI_COMPATIBLE`（兼容 OpenAI 协议）Provider；外部 Provider 默认关闭，配置完成不等于允许外发。
- 外部 Provider 配置至少包含：配置名称、启用状态、Base URL（服务根地址）、模型标识、API Key（接口密钥）、连接超时、请求超时、最大输出 Token、Temperature（生成随机度）和是否启用流式输出。
- Base URL 只允许 `HTTPS`；仅开发环境可由部署配置显式放开回环地址和 `HTTP`，界面必须显示非安全提示。地址保存和每次调用均执行 scheme（协议）、host（主机）、port（端口）、DNS、实际 IP、重定向和 TLS 校验，不得绕过全局出站网络策略。
- API Key 仅写入、不回显；读取时只返回“已配置”和掩码摘要。空值表示保留原密钥，替换需要重新输入，删除需要二次确认；密钥加密存储，不进入配置历史明文、日志、审计详情、备份清单或前端持久化。
- 模型标识不得仅凭用户输入判定有效，必须在连接检测中由 Provider 接受；服务端不得静默替换模型。模型、Base URL、流式能力或安全策略变化形成新配置版本。
- 启用外部 Provider 前，候选配置必须在 10 分钟内通过连接检测，且检测使用的配置指纹与待保存内容一致。未启用的候选配置允许保存为 `UNTESTED`（未检测），但不得承接真实问答。
- 保存采用“候选配置 → 校验/检测 → 原子切换”；检测或保存失败时继续使用上一有效版本，不影响 `deterministic-local`。

#### F12.2 LLM 连通性检测

- 超级管理员可对尚未保存的候选配置或已保存配置执行“测试连接”；检测不得改变当前生效 Provider、外发开关或仓库策略，也不得写入问答历史。
- 检测按顺序执行：配置格式校验 → DNS/IP/端口与出站策略校验 → TCP/TLS 建连 → Provider 鉴权 → 指定模型最小生成 → 流式首 Token 检测（启用流式时）。前置阶段失败后不继续发送模型请求。
- 最小生成使用系统内置的非敏感固定探针，不携带仓库代码、知识、用户问题、会话历史或其他业务数据；返回内容只校验协议、模型响应和流式事件格式，不作为产品回答保存。
- 检测结果返回总体状态、各阶段状态、总耗时、建连耗时、首 Token 耗时、Provider/模型、检测时间、配置指纹、稳定错误码、脱敏说明、`requestId`（请求标识）和建议动作；不得返回密钥、完整响应体或底层异常堆栈。
- 结果映射为：全部必需阶段通过为 `AVAILABLE`；非必需能力（例如流式）失败但基础生成成功为 `DEGRADED`；鉴权、模型、网络、TLS、协议或超时失败为 `UNAVAILABLE`。关闭或修改配置后状态回到 `UNTESTED`。
- 错误至少区分 `LLM_CONFIG_INVALID`（配置无效）、`LLM_NETWORK_BLOCKED`（网络策略拒绝）、`LLM_DNS_FAILED`（域名解析失败）、`LLM_TLS_FAILED`（安全连接失败）、`LLM_AUTH_FAILED`（鉴权失败）、`LLM_MODEL_NOT_FOUND`（模型不可用）、`LLM_RATE_LIMITED`（触发限流）、`LLM_TIMEOUT`（检测超时）、`LLM_PROTOCOL_INVALID`（协议响应无效）和 `LLM_STREAM_UNSUPPORTED`（不支持流式）。
- 同一管理员对同一配置最多同时存在一个检测请求；检测默认总超时 15 秒，可取消。短时间重复点击复用进行中的请求，不并发轰击 Provider。
- 运行期记录最近成功时间、最近失败时间和连续失败次数；真实调用连续失败达到阈值后进入 `UNAVAILABLE` 并触发熔断，问答明确降级到 `deterministic-local`。后台健康检查仅使用固定探针，频率可配置且默认关闭，恢复必须重新检测成功。
- 审计配置创建、修改、启停、密钥替换和连接检测，只记录操作者、配置版本/指纹、Provider、模型、结果、错误码、耗时和关联 ID，不记录密钥、探针响应正文或业务上下文。

- 备份必须包含业务数据库、权限、加密配置/凭据、任务审计、元数据、知识 Markdown、`READY`（就绪）附件、清单和墓碑。
- 默认每日备份，保留 7 日 + 4 周；加密并校验后进入 `READY`（就绪）。可重建产物可不备份，但需记录重建信息。
- 恢复执行格式/版本/摘要/schema/空间/密钥预检，进入维护模式并创建恢复前备份，在隔离区校验后原子切换。
- 旧备份不得复活已删除数据；恢复后撤销会话并重建缺失产物。
- 开放前保证每仓一个有效 OWNER、同 OWNER 名称唯一、授权无 OWNER/重复；无效 OWNER 和名称冲突需显式映射。
- 目标 RPO（恢复点目标）为 24 小时、业务 RTO（恢复时间目标）为 4 小时、完整检索恢复 24 小时；每季度演练。

LLM 配置与连通性专项验收：

1. `SET-16`：新建未启用配置可保存为 `UNTESTED`，不会改变当前 Provider。
2. `SET-17`：正确地址、密钥和模型完成全部检测阶段，状态为 `AVAILABLE`，结果不含敏感值。
3. `SET-18`：错误密钥、错误模型、TLS 异常、超时和网络策略拒绝分别返回稳定错误码，旧有效配置继续生效。
4. `SET-19`：候选配置检测成功后被修改，因配置指纹不一致不得直接启用。
5. `SET-20`：流式检测失败而基础生成成功时状态为 `DEGRADED`；关闭流式后重新检测可进入 `AVAILABLE`。
6. `SET-21`：连接检测的请求和日志不含仓库代码、知识、用户问题、API Key 或完整模型响应。
7. `SET-22`：重复检测满足单飞、超时和取消要求；限流不会被自动高频重试放大。
8. `SET-23`：运行期 Provider 不可用时问答展示真实降级原因并使用 `deterministic-local`，恢复检测成功后才重新承接外部调用。

验收：`SET-01..23`、`BAK-01..12`。

### F13 快速开始（QV1）

- 登录默认进入快速开始；无仓库只显示接入动作，有仓库恢复最近有权仓库。
- 展示 OWNER、来源版本、快照、CodeGraph、内容索引、最近任务；状态来自权威对象并可携带上下文跳转。
- MAINTAIN 及以上可“一键准备”，只创建缺失的 CodeGraph/索引任务，按依赖执行，重复点击返回现有任务。
- 项目画像只使用当前快照 README、构建文件、目录和已发布产物，展示技术线索、目录、配置、入口候选、规模和测试分布；不确定项明确标候选。
- 五个快捷动作：系统做什么、如何启动、核心模块、跟踪调用链、测试入口；均可编辑并返回证据。
- 检索可进入影响分析/问答，问答可保存知识草稿，图节点可看源码/检索/提问；跨页携带仓库、快照、符号、引用。
- 撤权或切仓立即清除上下文。

QV1 不含自定义学习路径、私人笔记、业务域地图、完整 API/数据目录、服务端命令执行和变化摘要。

验收：`QV-01..12`；首次可引用结果不超过 10 分钟，用户 30 分钟内完成五个动作中的三个。

### F14 开发者入门工作台（M1/M2）

- 总览展示定位、技术栈、模块/业务域、入口、外部依赖、启动方式、快照和产物新鲜度，并区分代码事实、人工知识、模型解释。
- 环境、架构、业务域、数据、API、测试、运维七项分别显示已确认、待补充、已过期或不可用。
- 内置后端、前端、排障、接口开发、数据变更路径；步骤为 `READ`（阅读）、`RUN`（运行）、`TRACE`（追踪）、`QUERY`（查询）、`VERIFY`（验证），包含目标、耗时、前置、操作、证据、完成标准。
- 进度绑定账号、仓库、快照、路径版本；访问不自动完成，支持暂停、重置和显式迁移。
- 架构/业务域地图、场景链路、API 目录、数据模型和变化摘要均绑定版本和证据。
- 环境预检覆盖开发依赖、目录、端口、变量和健康状态；敏感值只显示配置状态。
- 服务端只执行受信任 allowlist（允许列表）检查；调试手册按 `requestId`（请求标识）/`taskId`（任务标识）串联错误、任务、配置、代码和测试。
- 用户可维护私有进度、收藏、笔记；团队可发布术语和路径；个人内容不因超级管理员角色而公开。
- 权限回收后总览、进度、收藏、笔记、历史和导出立即不可访问。

验收：`ONB-01..18`。

### 7.1 性能与容量

参考环境：8 核、16 GB、本地 SSD（固态硬盘）、单实例、同内网数据库；基准仓库 10 万行、2 万文件、2 GB。

| 能力 | 目标 |
| --- | --- |
| 关键词查询 | P95（第 95 百分位耗时） < 2 秒 |
| 混合检索 Top 20 | P95（第 95 百分位耗时） < 3 秒（不含 Provider 故障） |
| CodeGraph 直接关系 | P95（第 95 百分位耗时） < 2 秒 |
| 入门总览缓存命中 | P95（第 95 百分位耗时） < 2 秒 |

### 7.2 安全、可靠与兼容

1. 生产使用 TLS（传输层安全协议）；Cookie（浏览器会话凭据）启用 HttpOnly（禁止脚本读取）、SameSite（限制跨站发送）、Secure（仅安全连接发送）。
2. 外部模型默认关闭，启用时执行全局、仓库、数据类别三层策略。
3. 文件、ZIP、Git、CodeGraph、引用和清理防止路径穿越与链接逃逸；远程端点防 SSRF（服务端请求伪造）和 DNS（域名系统）重绑定。
4. Markdown/附件覆盖 XSS（跨站脚本攻击）、危险协议、MIME 欺骗、解析炸弹、恶意内容和越权下载测试。
5. 数据库、文件和当前指针使用事务或可恢复两阶段发布；重启后任务有确定终态。
6. 指标覆盖请求、任务、队列、阶段、失败分类、检索通道、Provider、容量；日志关联 requestId/taskId/repositoryId/snapshotId。
7. 支持 Windows/Linux 服务端和当前两个主要版本的 Chromium/Edge。
8. 删除、审计、问答、知识和备份保留期由管理员配置，法定策略优先。

8. 删除不触碰本地源目录，清理可幂等重试。
9. 备份恢复后 OWNER、授权、快照、知识和附件一致。
10. 配置 LLM 候选项，完成分阶段连接检测后启用；模拟鉴权失败、限流和超时，验证旧配置保留、状态可解释且问答正确降级。

### 8.3 发布红线

1. 当前里程碑编号用例或主链路未通过。
2. 存在越权、明文凭据、任意代码执行、路径穿越、SSRF 或未授权外发。
3. 失败、取消、重启、撤权、删除、恢复产生半成品指针、孤儿可见数据或版本混用。
4. 未实现功能以可用入口、成功状态或虚假数据展示。
5. 数据库、迁移、受管目录、CodeGraph、备份恢复缺少运行手册。

## 10. 完成定义

功能只有同时满足以下条件才算完成：

1. 有入口、服务端授权、业务处理和持久化。
2. 输入、前置条件、成功产物、异常结果和用户下一步清晰。
3. 结果绑定正确版本且可追溯证据。
4. 非法输入、依赖失败、取消、重启和并发冲突都有确定结果。
5. 重试幂等，失败不发布半成品、不覆盖旧结果。
6. 撤权和逻辑删除立即阻断访问。
7. 数据库、文件、任务、审计和保留策略生命周期一致。
8. 自动化测试覆盖主流程、权限、失败回滚和版本一致性。
9. 对应验收编号、使用文档和运维文档完成。
